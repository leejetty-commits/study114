## 2. 왜 이 색인가 (대비 계산)

WCAG 2.x 상대휘도 공식. 본문 14px/600은 「큰 글자」가 아니므로 **4.5 : 1 이상** 필요.

| 바탕 | 흰 글자 | #1C1917 | **#0B2545** | #1A4F96 | 판정 |
|---|---|---|---|---|---|
| #266BC4 (현재) | 5.27 | 3.32 | 2.92 | 1.53 | 흰 글자만 합격 |
| #6797D6 (흰 30%) | 3.01 ✗ | 5.81 | **5.11** | 2.68 | 어두운 글자 필요 |
| **#729FD9 (흰 35%) ← 확정** | 2.74 ✗ | 6.39 | **5.62 ✓** | 2.95 | **진남색 글자로 합격** |
| #7DA6DC (흰 40%) | 2.51 ✗ | 6.96 | 6.13 | 3.21 | 〃 |
| #3777C9 (흰 8%) | 4.52 (겨우) | — | — | — | 흰 글자 유지 한계 = 8%까지 |
| #4373B1 (A안: 채도만↓) | 4.85 | — | — | — | 밝아진 느낌 거의 없음 |
| #DCE8F7 (C안: 연한 바탕) | 1.24 | 14.10 | — | 6.50 | 흰 테두리 버튼과 구분 약함 |

- 종현 요청 「30–40% 밝게」 그대로면 흰 글자는 전부 불합격 → **글자를 진남색으로 바꾸는 B안**이 요청에 가장 가까우면서 AA 합격.
- 글자색 #0B2545는 #1C1917(잉크)보다 파란 기운이 있어 바탕과 어울림. 대비는 잉크(6.39)보다 낮지만 기준 대비 여유 1.1.
- 버튼 바탕 #729FD9 vs 흰 페이지 = 2.74 : 1. 버튼은 글자(라벨)로 식별되므로 WCAG 1.4.11(비텍스트 3:1)은 필수 아님. 테두리 추가 없이 감.

## 3. 모바일 누르는 영역 (기본안 ①)

- 보이는 높이: 데스크톱과 같음(30 / 26).
- 누르는 영역: `≤768px`에서 버튼에 `::after` 투명 레이어를 세로 가운데로 붙여 **높이 max(100%, 44px)**.

```css
@media (max-width: 768px) {
  :where(.btn) { position: relative; }          /* 특이도 0 — 맥락 규칙이 있으면 그쪽이 이김 */
  .btn::after {
    content: "";
    position: absolute;
    left: 0; right: 0; top: 50%;
    height: max(100%, var(--btn-tone-hit));
    transform: translateY(-50%);
  }
}
```

- 레이아웃 이동 0: 절대 위치라 버튼 크기·줄 높이·주변 여백 안 바뀜.
- 확인 결과: 현재 코드에 `.btn::before/::after` 사용처 0, `.btn`에 `position:absolute|fixed` 맥락 규칙 0 (rg 확인).
- 주의: 부모가 `overflow:hidden`이면 위아래가 잘릴 수 있음 → 검수에서 `elementFromPoint`로 확인(04 합격기준).
- 버튼끼리 세로 간격이 14px 미만이면 누르는 영역이 겹칠 수 있음 → 나중에 그려진 버튼이 이김. 검수에서 목록화.
