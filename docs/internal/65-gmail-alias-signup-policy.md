# 65 — 실서비스 가입: 지메일 별칭 제한

**기준일:** 2026-09-12  
**지위:** 운영 정책 결정. 코드 미적용. 가입·로그인 구현 시 이 문서를 따른다.  
**관련:** `src/Auth/EmailNormalizer.php` · `users.email` UNIQUE · CUR-006 이메일 인증

한 줄: *인증 메일이 같은 편지함으로 온다고 해서, 별칭 주소를 다른 회원으로 인정하지 않는다.*

## 1. 왜 적는가

테스터는 지메일 `+별칭`으로 아이디를 여러 개 만들 수 있다. 받은편지함은 하나다. 우동공과 가입은 지금 이 주소를 **각각 다른 회원**으로 저장한다.

테스트에는 쓰되, **실서비스 공개 가입은 같은 편지함을 다른 사람으로 인정하지 않는다.**

## 2. 현재 코드 (2026-09-12)

`EmailNormalizer`는 소문자·trim만 한다. `+`와 `.`을 접지 않는다.

그래서 아래는 전부 `users.email` UNIQUE를 통과한다. 지메일 쪽은 **같은 편지함**이다.

| 가입 이메일 | 지메일 편지함 | 지금 DB |
|---|---|---|
| `hong@gmail.com` | 본계정 | 회원 1 |
| `hong+tutor@gmail.com` | 본계정 | 회원 2 |
| `h.ong@gmail.com` | 본계정 | 회원 3 |
| `hong@googlemail.com` | 본계정 | 회원 4 |

로그인 아이디는 **가입 때 넣은 문자열 그대로**다. `hong+tutor@…`로 가입했으면 `hong@…`로 로그인되지 않는다.

핸드폰 번호도 전역 UNIQUE가 아니다. 별칭 학부모 계정은 쪽지설정 OTP 없이도 여러 개 만들 수 있다.

## 3. 실서비스 정책

| 구분 | 정책 |
|---|---|
| 메일 수신 | 별칭으로 인증 메일이 가도 된다. 폼에서 `+`를 막을 필요는 없다. |
| 회원 인정 | Gmail / Googlemail은 **한 편지함 = 한 회원**이다. |
| 계정·역할 | 한 계정은 한 모드만. 별칭으로 과외쌤·공부방·학부모를 나누지 않는다. |
| 테스트 | 별칭 가입은 정책 적용 **전** 내부 테스트, 또는 아래 §6 테스트 전용 주소로만. |

하지 않는 것:

- 별칭을 “다른 사람”으로 보고 쪽지·리뷰·유료 한도를 각각 준다.
- 공개 가입에서 지메일 별칭으로 역할 3개를 나눠 쓰게 한다.
- 임시메일(10분 메일)로 실회원 가입을 유지한다.

## 4. 같은 사람으로 볼 규칙 (Gmail)

가입·중복 검사에 쓸 **정규 이메일**은 아래만 접는다. 다른 도메인(네이버, 다음, 회사 메일)은 입력값 소문자 그대로다.

1. 전체를 소문자로 만든다.
2. 도메인이 `gmail.com` 또는 `googlemail.com`이면:
   - 로컬파트에서 `+`와 그 뒤를 제거한다.
   - 로컬파트의 `.`을 제거한다.
   - 도메인을 `gmail.com`으로 통일한다.
3. 그 값을 회원 중복 키로 쓴다. (`users.email` 원문은 가입 주소를 남겨도 된다. 중복은 정규 키로 막는다.)

예시: `Hong.Kim+tutor1@googlemail.com` → `hongkim@gmail.com`

Outlook `+별칭`도 수신은 같은 편지함인 경우가 많다. 1차 잠금은 Gmail/Googlemail만. Outlook은 남용 사례가 나오면 같은 방식으로 확장한다.

## 5. 적용 순서 (코드는 아직 하지 않음)

1. 내부 테스트 계정(`+별칭`)을 만들거면 **이 규칙 배포 전에** 만들거나, §6 주소만 쓴다.
2. 정규 키 컬럼(가칭 `email_canonical`) UNIQUE를 넣는다.
3. 가입·이메일 변경·아이디 찾기가 같은 키를 본다. 이미 있으면 “이미 가입된 이메일”로 거절한다.
4. 기존 회원이 별칭끼리 여러 줄이면, 배포 전에 중복 목록을 뽑고 남길 계정 하나를 정한다. 자동 병합하지 않는다.
5. 로그인 입력도 같은 정규화를 탄다. 본계정으로 넣든 별칭으로 넣든 **이미 있는 한 회원**으로 붙게 할지, 가입 원문만 받을지는 구현 때 한 줄로 잠근다. 기본안: 가입은 정규 키 중복 거절, 로그인은 원문 일치 + 정규 키 조회로 본계정도 찾는다.

이 문서만으로 스키마·API를 바꾸지 않는다. 쪽지설정·등록점검·유료 작업과 섞지 않는다.

## 6. 테스트 전용 주소 (선택)

장기 테스트는 지메일 별칭보다 `qa.study114.net` catch-all이 안전하다.

- 서브도메인만 쓴다. `study114.net` 루트 MX는 건드리지 않는다.
- Cloudflare Email Routing 등 전달은 추가 비용이 거의 없다.
- 예: `tutor1@qa.study114.net` → 운영자 지메일.

운영 중복 규칙을 켠 뒤에도 qa 주소는 Gmail 규칙 밖이라 테스트 아이디로 남을 수 있다. 실회원과 눈에 띄게 분리된다.

## 7. 테스터가 지금 해도 되는 것

정책 코드가 들어가기 전:

- 지메일 `이름+tutor1@gmail.com` 형태로 내부 6계정 가입·이메일 인증은 된다.
- 로그인 아이디는 별칭 문자열 그대로다.
- 실서비스에 “별칭 = 다른 손님”으로 안내하지 않는다.

정책 코드가 들어간 뒤:

- 같은 지메일 편지함으로는 공개 가입이 1개만 된다.
- 추가 테스트 아이디는 qa 도메인이나 서로 다른 실제 메일함을 쓴다.
