## Study114 보안 점검 지시문 (외부 AI용)

### 1. 승인 및 목적

- **서비스명:** Study114 (학원·과외 매칭 정보 사이트)
- **운영 도메인(정본):** `https://study114.net`
- **검증·호환용 호스트:** `https://www.study114.net`, `https://study114.dothome.co.kr` (동일 서비스, 호스트별 세션 분리 가능)
- **점검 주체:** 서비스 소유·운영자가 **본인 사이트**에 대해 요청하는 **합법적 보안 검토**이다.
- **목적:** 배포 전·홍보(유튜브 등) 전 **취약점 후보 식별**, 우선순위 정리, **수동 재현 절차** 제안. 공격 자동화·서비스 장애 유발·데이터 파괴는 목적이 아니다.
- **횟수:** 본 점검은 **1회성**이다. 반복·상시 모니터링·자동 재실행이 아니다.

**승인자:** Study114 운영자  
**점검 기간:** 2026-11-08 ~ 2026-11-15  
**연락:** 문제 발견·로그인 잠금·오류 폭주·서비스 지연이 보이면 **즉시 중단**하고 요약만 보고 (실계정·관리자 권한 남용 금지).

### 2. 반드시 지킬 규칙 (금지)

다음은 **하지 말 것**:

1. **DoS·과부하:** 초당 대량 요청, 동시 접속 폭주, 로그인 무한 시도, 크롤 전체 사이트 무차별 스캔.
2. **자동 침투 도구:** sqlmap, nuclei, dirb/gobuster 대량, 취약점 스캐너, exploit 프레임워크 실행.
3. **파괴적 행위:** 데이터 삭제·변조, 타 사용자 프로필·게시물 변경, 결제·관리 기능의 실제 악용.
4. **타인 계정:** 실사용자 계정 추측·브루트포스. **테스트 전용 계정이 제공되지 않으면 로그인 이후 심층 테스트는 하지 말 것.**
5. **비밀값:** Client Secret, DB 비밀번호, cron 키, FTP, `.env`, GitHub Secrets, `STUDY114_*` 키 등을 **요구하거나 출력에 적지 말 것.** (코드·설정에는 placeholder만 있다고 가정. 시크릿 **값 재발급·교체 여부 검증 요구 금지**.)
6. **제3자 신고 없음:** 취약점을 공개 이슈·SNS에 올리지 말 것. 결과는 **비공개 보고서**로만.
7. **환각 금지:** 확인하지 않은 취약점을 확정으로 쓰지 말 것. **「추정」과 「재현됨」**을 구분할 것.

허용되는 것은 **저강도·수동에 가까운** 탐색: 공개 URL·공개 API의 **읽기(GET)**, HTTP 보안 헤더·쿠키 속성 검토, **오픈 리다이렉트·CSRF·XSS 후보**의 논리적 분석, 공개 SPA/정적 자산 구조 추론 등.

**Rate limit 확인 시:** 동일 실패 시도를 **한도 직전까지만** 하고, 차단·안내 문구가 보이면 **즉시 중단**. 잠금이 풀릴 때까지 재시도하지 말 것.

### 3. 점검 범위 (우선순위)

#### A. 인증·세션·OAuth

- 소셜 로그인(카카오·네이버·구글 등) **리다이렉트 URI·`state`·`return_to`** 오픈 리다이렉트·피싱 가능성.
- 로그인 실패 **rate limit** 동작 여부(과도 시도 시 차단 메시지·잠금). 공개 문서상 대략: 비밀번호 이메일 실패 약 5회/15분, IP 약 15회/15분, 소셜 시작 IP 약 10회/2분 — **확인은 한도 직전만**.
- 세션 쿠키: `Secure`, `HttpOnly`, `SameSite` 적절성 (호스트별 분리 인지).
- 비밀번호 변경·이메일 인증 등 **인증 API**의 인가 누락 가능성(문서·공개 엔드포인트 이름 기준 추론만; 무단 POST 남발 금지).

#### B. API·백엔드 (PHP `/api/...` 가정)

- **IDOR:** 다른 사용자 `user_id`·샵 ID로 조회·수정 가능한지 (로그인 없이는 이론만, 로그인 시는 테스트 계정 2개 있을 때만).
- **권한 상승:** 일반 사용자가 **관리자·오너 전용** 경로 접근 가능한지.
- **입력 검증:** SQLi·경로 조작·JSON 필드 오염 **후보만** (실제 exploit payload 대량 전송 금지).
- **민감 엔드포인트:** cron·메일 프로브·스토리지 서명 URL — 키 없이 호출 시 거부되는지 (**추측 키 brute force 금지**).

#### C. 파일·업로드·스토리지

- 업로드가 있다면: 확장자·MIME·경로 traversal·공개 URL 노출 가능성 (실제 악성 파일 업로드는 **승인자 지시 없이 하지 말 것**).

#### D. 프론트 (Vite SPA)

- DOM XSS 후보: `dangerouslySetInnerHTML`·URL 파라미터·`postMessage` 반사.
- **민감 정보:** JS 번들·소스맵·주석에 키·내부 URL 노출.
- CORS·`Access-Control-Allow-Origin` 과다 개방 여부 (브라우저 기준 관찰).

#### E. 관리자·내부

- `/admin` 또는 관리 UI: 미인증 접근, 기본 경로 노출, **게스트 검색 필드** 등 과도 정보 노출 (최근 강화 항목으로 가정).

#### F. 인프라·설정 (관찰만)

- `.env`, `.git`, 백업 파일, `phpinfo`, 디렉터리 리스팅 노출 여부 (**소수의 well-known 경로만** 확인, 사전 대량 스캔 금지).
- **HTTPS** 강제, HSTS, CSP 존재 여부 (없으면 권고만).

#### G. 최근 보완 가정 (코드 확인 시 우선 검증)

- Cron·배치 호출 **기본 키 제거·시크릿 필수화**
- 스토리지·서명 URL **시크릿 필수**
- OAuth **return_to 화이트리스트**
- 로그인·소셜 **rate limit**

(공개 저장소 또는 제공된 **비밀 제거** 코드가 있으면 위 항목이 실제 반영됐는지 **화이트박스**로 확인. 없으면 공개 동작·헤더 관찰 + **체크리스트**만.)

### 4. 작업 방식

1. **1단계:** 공개 페이지만 브라우징·헤더·쿠키·공개 API OPTIONS/GET (필요 시 HEAD).
2. **2단계:** 제공된 **프론트/백엔드 코드** 또는 공개 GitHub 구조가 있으면 정적 분석 (비밀·PII 붙여넣기 금지).
3. **3단계:** 테스트 계정 제공: **없음** — 인증 후 영역은 **체크리스트·위험 시나리오**만 작성. (계정 2개가 나중에 제공되면 IDOR·권한 상승만 추가.)
4. 모든 항목에 **재현 단계·기대 결과·실제 관찰·심각도**를 붙일 것.
5. 불확실하면 **「추가 확인 필요」**로 표기.

**요청 빈도 상한:** 동일 엔드포인트 **분당 10회 미만**, 전체 점검 **1시간 이내** 소요 목표.  
한 플랫폼에 **한 번**만 수행하고, 여러 AI에 **동시·반복**으로 돌리지 말 것.

### 6. 참고 (공개 정보만)

- 서비스: 한국어 학원·과외 정보, 지도(네이버 맵 SDK), 소셜 로그인.
- 배포: 정적 프론트(Vite SPA) + PHP API (닷홈 호스팅 가정).
- 도메인 정책: apex `study114.net`이 1차; www·dothome는 호환.
- 배경: 유튜브 등 홍보 유입을 대비해 cron 키·스토리지 서명·OAuth `return_to`·로그인 rate limit·OAuth Client Secret 운영을 최근 강화한 상태. **외부 점검자는 시크릿 값 확인 없이**, 공개 동작·헤더·(있다면) 비밀 제거 코드만으로 잔여 위험을 본다.

**첨부 가능:** 공개 페이지 URL 목록, 아키텍처 설명, **비밀이 제거된** API 목록, 공개 git 브랜치 링크.  
**첨부 금지:** `.env`, OAuth secret, DB dump, 실사용자 데이터.
