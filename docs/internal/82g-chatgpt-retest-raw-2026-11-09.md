# Study114 보안 재점검 보고서 (82f)

외부 검증 제한

비파괴 점검 원칙 준수

- 점검 기준일: 2026년 11월 9일
- 대상: `https://study114.net`
- 점검 유형: 1차 조치 후 공개 영역 재검증
- 테스트 계정: 없음
- 코드: 미제공
- 점검 방식: 공개 URL 접근 및 저강도 확인

먼저 중요한 결과부터 말씀드리겠습니다.

이번 환경에서는 대상 사이트에 대한 직접 HTTP 요청이 브라우징 단계에서 차단됐습니다(`DisabledError`). 따라서 HTTP 응답 헤더나 실제 상태 코드를 읽을 수 없었습니다.

이는 Study114 서버가 접속을 거부했다는 뜻이 아닙니다. 점검 도구의 접근 제한입니다.

따라서 운영자가 적용했다고 알려준 보안 조치를 실제 확인된 것으로 처리하지 않겠습니다. 특히 HSTS, CSP Enforce, 관리자 API 401, OAuth state, 쿠키 속성은 아직 검증되지 않았습니다.

또한 이번에는 로그인 시도, 상태 변경 요청, Cron 실행, 파일 업로드를 하지 않았습니다.

## 2. 1차 대비 개선 사항

운영자께서 제공한 조치 내역을 기준으로 개선된 설계 항목을 정리했습니다.

| 영역    | 운영자 보고 조치                      | 재점검 평가   |
| ----- | ------------------------------ | -------- |
| HTTPS | Cloudflare Always Use HTTPS    | 개선 조치 보고 |
| 보안 헤더 | HSTS, nosniff, X-Frame-Options | 개선 조치 보고 |
| 관리자   | 게스트 게이트 및 API 인가               | 개선 조치 보고 |
| OAuth | state 검증 및 return_to 살균        | 개선 조치 보고 |
| IDOR  | 설정 URL, 쪽지 소유권                 | 선별 보완 보고 |
| XSS   | DOM 및 속성 이스케이프                 | 선별 보완 보고 |
| 업로드   | finfo 및 확장자 일치 검증              | 개선 조치 보고 |
| CSP   | Report-Only에서 Enforce          | 개선 조치 보고 |
| Cron  | 시크릿 필수화                        | 개선 조치 보고 |
| Git   | 과거 키 재발급, 히스토리 유지              | 운영 정책 확인 |

여기서 '개선 조치 보고'는 운영자 제공 사실을 정리한 것이며 외부에서 작동을 검증했다는 의미는 아닙니다.

## 3. 조치 후 좋아진 점

운영자 설명이 정확히 반영됐다는 전제에서 다음 개선은 의미가 큽니다.

1. HTTP에서 HTTPS로 강제 전환하는 정책이 추가됐습니다.
2. 관리자 API의 서버 측 인가와 OAuth state 검증이 보강됐습니다.
3. 업로드 MIME 검증과 CSP Enforce 적용으로 방어 계층이 강화됐습니다.

## 4. 아직 남거나 새로 확인할 점

현재 확인 가능한 미해결 검증 과제는 다음과 같습니다.

1. HSTS와 CSP가 실제 응답 헤더에 적용되는지 확인해야 합니다.
2. CSP가 네이버 지도 및 지오코딩 기능을 실제로 차단하지 않는지 확인해야 합니다.
3. 관리자 API, Cron, OAuth의 실제 응답 및 인증 흐름을 확인해야 합니다.

추가로 다음 두 항목은 정책상 의도적인 후순위입니다.

- Git 히스토리 purge: 현재 운영 정책대로 별도 진행하지 않음.
- 로그인 계정 2개를 이용한 IDOR 교차 테스트: 테스트 계정 제공 이후 진행.

### 7. 다음 단계: 실제 헤더를 확보하는 방법

이번 작업에서 가장 큰 장애는 취약점 자체가 아니라 외부 점검 도구가 HTTP 응답을 읽지 못했다는 점입니다.

이를 해결하려면 Windows에서 다음 명령을 실행해 주시면 됩니다. 사이트에 대한 소수의 HEAD 요청만 수행하므로 저강도 점검 원칙에도 부합합니다.

① HTTP→HTTPS 확인

```
curl.exe -sSI http://study114.net/
```

② HTTPS 보안 헤더 확인

```
curl.exe -sSI https://study114.net/
```

③ 호스트 정규화 확인

```
curl.exe -sSI https://www.study114.net/
curl.exe -sSI https://study114.dothome.co.kr/
```

④ 관리자 API 확인

실제 공개된 GET 전용 관리자 API 경로 하나를 지정해 주시면 됩니다.

주의: 출력 결과에 쿠키 값이나 인증 관련 정보가 포함되면 해당 값은 삭제하고 공유하세요.

브라우저를 통한 공개 웹사이트 접근 및 자료 추출을 보완할 수 있는 TinyFish도 연결할 수 있습니다. 연결 여부는 본인이 선택하면 됩니다.

제 제안: 지금은 추가 공격 테스트보다 ①\~③의 응답 헤더를 먼저 확보하는 것이 효율적입니다. 헤더 결과만 있으면 R1\~R6의 상당 부분을 실제 관찰 기준으로 다시 판정할 수 있습니다.
