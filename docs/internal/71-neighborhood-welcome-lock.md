## 1. 한 줄 정의

새로 등록한 공부방·과외쌤을 **기존 동네 인사 목록 안에** 「새 이웃」 한 줄로 7일 동안 소개한다. 별도 판·별도 화면·별도 라우트를 만들지 않는다.

## 2. 레드라인 (어기면 반려)

1. **노출 정책은 기존 동네 인사와 동일.** 환영 줄만의 예외(노출 범위 확대, 이름 가림 해제, 랭킹 가산)를 두지 않는다.
2. **이름 클릭 팝업이 열리지 않는 환영 줄은 내보내지 않는다.** 환영 줄 자격 = 카드 팝업 API(`neighborhood-greeting-card.php` → `basicCard()`)가 카드를 돌려주는 등록. 판정 코드를 복제하지 말고 같은 판정을 쓴다.
3. **환영 줄의 이름·동네·문구는 서버가 DB에서 만든다.** 브라우저가 보낸 값을 쓰지 않는다.
4. **학생(수요자) 정보는 환영 줄에 절대 나오지 않는다.** 환영 대상은 공부방·과외쌤 등록뿐.
5. **새 라우트·새 API 파일을 만들지 않는다.** 기존 `GET/POST /api/neighborhood-greetings.php`, `GET /api/neighborhood-greeting-card.php`, 기존 팝업(`openGreetingTarget`)만 쓴다.
6. **SQL 변경 없음.** 환영 줄은 읽을 때 계산한다(GET에서 파일 쓰기 금지).

## 4. 환영 줄 규칙

### 4-1. 자격 (모두 만족)

1. 등록 종류: 공부방(`study_rooms`) 또는 과외쌤(`tutors`).
2. 등록 생성 후 **7일 이내**(`created_at` 기준, 서버 시각).
3. 카드 팝업이 열리는 상태(레드라인 2). 즉 현행 동네 인사 노출 조건(대표 지역·탈퇴 아님·숨김/삭제 아님)을 그대로 통과.
4. 그 등록에 **동네 인사 기록이 하나도 없음**(올림·내림 모두 포함). 본인이 직접 인사를 올렸거나 내렸거나 환영 줄을 끈 경우 환영 줄을 만들지 않는다.
5. 같은 회원의 **같은 종류 첫 등록**일 것(삭제된 공부방 포함 더 오래된 등록이 있으면 제외). 등록을 지웠다 다시 만들어 환영 줄을 반복 노출하는 것을 막는다.
6. 동네 이름(대표 지역의 동)이 비어 있지 않을 것.

### 4-2. 내용

| 항목 | 값 |
|---|---|
| 종류 표시(머리표) | 「새 이웃」 |
| 이름 | 카드에 나오는 이름(과외쌤 `tutor_display_name`, 공부방 `study_room_name`). 비면 「과외쌤」/「공부방」. 로그인 전에는 기존 `maskName()` 그대로 |
| 동네 | 대표 지역 `regions.dong_name` |
| 문구(과외쌤) | 「{동}에 새로 오신 과외쌤이에요. 반갑게 맞아 주세요!」 |
| 문구(공부방) | 「{동}에 새 공부방이 문을 열었어요. 반갑게 맞아 주세요!」 |
| 시각(정렬용) | 등록 `created_at` |
| 구분값 | API 항목에 `origin: 'welcome'` (직접 쓴 인사는 `origin` 없음 또는 `'member'`) |

문구는 80자·금지어 검사(`validate()`)를 통과해야 한다. 연락처·가격·홍보 문구를 넣지 않는다.

### 4-3. 표시

- 홈 동네 인사 칸 3줄 중 **환영 줄은 최대 1줄**. 나머지는 직접 쓴 인사가 우선이고, 직접 쓴 인사가 부족하면 그 자리를 비워 둔다(환영 줄로 채우지 않는다).
- 「더보기」 팝업 목록에는 자격이 있는 환영 줄을 모두 최신순으로 섞어 보인다.
- 이름을 누르면 기존 카드 팝업(로그인 전 로그인 안내 포함)이 그대로 열린다.
- 0건 문구·받는 중·실패 문구는 현행 그대로.

### 4-4. 공급자·수요자 관계

| 보는 사람 | 의미 | 규칙 |
|---|---|---|
| 학부모·학생·게스트(수요자) | 주 대상. 우리 동네에 새로 생긴 선택지를 알게 됨 | 기존 동네 일치 규칙으로만 노출. 카드 팝업 → 상세·쪽지 흐름은 현행 |
| 같은 동네 다른 공급자 | 이웃 인사. 경쟁 정보가 아니라 동네 소식 | 현행 동네 인사와 같게 보임. 문구는 홍보가 아닌 환영 톤 유지 |
| 새로 온 공급자 본인 | 첫 주 노출 혜택 | 마이페이지 동네 인사 편집 칸에 상태만 안내(아래 4-5). 작성 재촉 금지 |

환영 줄은 검색 순위·카드 노출 순서·유료 상품 노출에 영향을 주지 않는다.

### 4-5. 본인 제어 (마이페이지 동네 인사 편집 칸)

- 환영 줄이 보이는 동안 안내: 「우리 동네 새 이웃으로 소개되고 있어요 (D-n). 직접 인사를 올리면 그 인사로 바뀌어요.」 + 「소개 내리기」 버튼.
- 「소개 내리기」 = 그 등록에 내림 상태 기록을 남긴다(본문 없음, `origin: 'welcome_off'`). 이후 4-1 조건 4에 걸려 환영 줄이 다시 나오지 않는다. 직접 인사 올리기는 그대로 가능.
- 「다시 켜기」는 두지 않는다(1회성 혜택, 단순 유지).

## 6. 라우팅

- 새 해시 라우트 없음. 홈 각 역할(게스트·학부모·과외쌤·공부방)과 마이페이지 동네 인사 편집 칸에서만 보인다.

## 7. 알려진 제약 (이번 범위 밖)

- 동네 인사 파일 저장은 읽기-수정-쓰기 사이 잠금이 없다(기존). 환영 줄은 읽기 계산이라 쓰기 경합을 늘리지 않는다. `welcome_off`만 쓰기를 추가.
- 직접 쓴 인사의 `display_name`은 현행대로 브라우저가 보낸 값을 저장한다(기존 동작, 이번에 바꾸지 않음). 환영 줄은 레드라인 3에 따라 서버 값.
- 게시 환영 메일은 ③ 우동공과 편지(발송 기록 SQL 필요)에서 다룬다.
- 관리자 숨김 기능 없음(시스템 문구라 위험 낮음). 필요 시 후속.
