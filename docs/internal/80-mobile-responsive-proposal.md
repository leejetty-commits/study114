## 2. 문제별 해결 방안

### 2-1. 지도 모바일 여백 문제

**현상:** 모바일 세로 배치(≤719px)에서 지도 canvas 높이(9~13rem)가 화면 대비 과도하고, 지도 콘텐츠(대치동 핀 1개)에 비해 빈 공간이 많다.

**원인:**
- `hero-map__surface` min-height가 고정값(9rem / 13rem / 17rem)
- 지도 canvas와 banner가 세로로 쌓여 합산 높이가 17~21rem
- 지도 SDK가 빈 영역을 배경색으로 채움

**해결 방안:**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 아코디언 접기 (권장)** | 모바일에서 지도를 접힌 상태로 제공. 「지도 보기 ▾」 탭으로 펼침 | 첫 화면에서 카드 목록이 바로 보임 | 지도가 기본 숨김 |
| B. 비율 고정 | `aspect-ratio: 16/9` 또는 `3/2`로 교체 | 기기별 일정한 비율 | 소형 기기에서 여전히 클 수 있음 |
| C. 높이 축소 | 모바일 min-height를 `7rem`(112px)으로 낮춤 | 단순 | 지도 조작이 불편 |

**권장안 A 상세:**

```
≤719px 모바일 히어로 맵 구조:

┌─────────────────────────────┐
│ 대치동 · 공부방·과외쌤 찾기  │  ← banner(지역명+CTA+통계) 항상 표시
├─────────────────────────────┤
│ [▾ 지도 보기]               │  ← 탭 버튼 (접힌 상태 기본)
│ ┌─────────────────────────┐ │
│ │    (지도 canvas)         │ │  ← 펼치면 aspect-ratio: 4/3
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

- 모바일에서 **banner(지역+통계+CTA)를 위에**, 지도를 아래에 접어 둔다
- banner가 위에 있으므로 핵심 정보(지역명·검색 CTA)는 즉시 보임
- 펼쳤을 때 `aspect-ratio: 4/3` → 지도 비율 안정
- 데스크톱(≥720px)은 기존 가로 배치 그대로 유지

### 2-2. 햄버거 GNB (모바일 ≤899px)

**현상:** 9개 항목이 수평 스크롤로 나열. 5~6개만 보이고 나머지 잘림. 유틸바 480px 이하 숨김으로 이용안내·로그인도 사라짐.

**해결 방안:**

```
≤899px 헤더 구조:

┌──────────────────────────────────┐
│ [☰]  [로고 — 우동공과]   [CTA]  │  ← 한 줄 헤더
└──────────────────────────────────┘
                 ↓ ☰ 터치 시
┌──────────────────────────────────┐
│ 홈                               │
│ 공부방찾기                        │
│ 과외쌤찾기                        │
│ 학생찾기                          │
│ ───────────────────              │
│ 유료상품                          │
│ 커뮤니티                          │
│ 고객센터                          │
│ ───────────────────              │
│ 이용안내                          │
│ 로그인 / 회원가입                 │
│ (또는) 마이페이지 / 쪽지함 / 로그아웃 │
└──────────────────────────────────┘
```

**핵심:**
- **모바일 GNB 수평 스크롤(`.home-gnb-mobile`) 제거** → 햄버거 드로어로 교체
- **유틸바 링크를 햄버거 안에 포함** → 480px 이하에서도 로그인·이용안내 접근 가능
- 역할별 숨김 규칙(`GNB_VISIBILITY`)은 기존 그대로 적용
- 등록 메뉴(공부방상세등록·과외쌤상세등록)는 역할에 따라 하나만 노출
- **데스크톱(≥900px)은 현재 펼침 메뉴 그대로 유지**

**CTA 버튼(헤더 우측):**
- 비로그인: 「회원가입」(brand-blue)
- 로그인: 「마이페이지」또는 미읽음 쪽지 뱃지

### 2-3. 우측 레일 모바일 처리

**현상:**
- 481~1023px: 본문 아래에 레일 전체가 쌓여 스크롤이 길어짐
- ≤480px: 완전 숨김 → 고민방·안내 카드 접근 불가

**해결 방안:**

| 구간 | 현재 | 개선 |
|---|---|---|
| ≥1024px | 우측 사이드바 | **변경 없음** |
| 481~1023px | 본문 아래 전부 쌓임 | **아코디언 접기** — 「현장 고민·안내 ▾」 탭 1개 |
| ≤480px | 완전 숨김 | **아코디언 접기** — 같은 UI |

- 모바일에서 레일은 **본문 아래에 접힌 단일 아코디언**으로 표시
- 기존 `mobileBehavior: 'collapse'` 속성이 일부 슬롯에 이미 있음 → 전체 적용
- 「이달의 베스트」는 아코디언 밖에 1줄 티저로 노출 가능

### 2-4. 카드 목록·검색 결과 모바일 최적화

**현상:** 카드(hcard)가 데스크톱 가로 레이아웃 그대로 축소되어 텍스트 잘림·이미지 비율 깨짐.

**해결 방안:**
- ≤600px: 카드를 **세로형(media 위 + 정보 아래)**으로 전환 (search-visily.css에 이미 부분 적용)
- 필터 패널: C-11에서 기본 접힘 적용 완료 → 유지
- 정렬 바: 터치 드롭다운으로 전환 (현재 라디오 버튼 → `<select>`)

## 4. 작업 범위 — 파트별

### Part A: 햄버거 GNB + 유틸 통합

| 항목 | 상세 |

## 5. 브레이크포인트 정리 (제안)

현재 6개 이상의 분산된 브레이크포인트를 **3단계**로 정리한다.

| 이름 | 범위 | 헤더 | 본문 | 레일 | 지도 |
|---|---|---|---|---|---|
| **Desktop** | ≥900px | 유틸+GNB 펼침 | 2단(≥1024) / 1단 | 사이드바(≥1024) | 가로 배치 |
| **Tablet** | 600–899px | ☰ 햄버거 | 1단 | 아코디언 | 가로(≥720) / 세로 |
| **Mobile** | ≤599px | ☰ 햄버거 | 1단 | 아코디언 | banner위 + 지도접힘 |

> 기존 480px·639px·720px·900px·1023px·1024px·1100px을 유지하되,
> **새로 추가하는 규칙은 위 3단계에만 맞춘다.**
