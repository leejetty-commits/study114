# 제출함 · 신뢰표시 — 공통 개발 + 차등 운영

작성: 2026-08-19  
대상: 이번 버전 운영 정책 (구현 기준)  
관련: [15장 §2-1](../ssot/15-mypage-structure.md#2-1-p15-10-제출자료-상태) · [20장](../ssot/20-study-room-registration-management.md) · [21장](../ssot/21-tutor-registration-management.md) · [22장](../ssot/22-platform-lifecycle-principles.md) · [47](./47-study-room-home-card-map.md) · [48](./48-tutor-home-card-map.md)

**한 줄:** 기능 뼈대는 공통으로 두고, 이번 버전의 화면·운영은 역할별로 나눈다. **공부방 = 체크리스트 중심. 과외쌤 = 제출함 사용.**

이번 버전은 공부방과 과외쌤을 동일 강도로 처리하지 않는다.

---

## 0. 잠금

| 역할 | 이번 버전 | 하지 않는 것 |
| --- | --- | --- |
| **공부방** | 공개/노출 체크리스트 · 단계별 입력 · 교육청 등록 체크 등 **최소 신뢰 표시** | 제출함 보드를 다시 크게 살리지 않음. 원본/공개용 증빙 이미지 MVP는 후순위 |
| **과외쌤** | 제출함을 **실제 사용 가능**하게 유지. 고액과외 신뢰 자료용 | 제출함 기능을 버리거나 공부방과 같이 숨기지 않음 |

공통 원칙([22장](../ssot/22-platform-lifecycle-principles.md))은 그대로다. 제출자료는 운영자 심사가 아니다. 공개 스위치(`profile_status`)와 제출함은 별개다.

---

## 1. 공통으로 묶는 것 (개발 기반)

역할 UI를 갈라 놓아도 **두 벌로 쪼개지 말 것.**

| 층 | 공통으로 유지 | 이유 |
| --- | --- | --- |
| 원칙 | 심사·승인·반려 없음. 당사자 제출·표시만 | 22장. 역할이 달라도 플랫폼 입장은 같음 |
| 프로필 공개 | `profile_status` + 필수 체크리스트 + 자기확인 | 공개 게이트는 양쪽 다 체크리스트 |
| 증빙 테이블 | `*_verification_documents` 패턴 | 공부방·과외 모두 DDL 있음. 공부방은 이번 버전 **안 씀** |
| 비공개 파일 저장 | `storage/attachments` · `AttachmentStorage` | 원본을 `public/uploads`에 두지 않는 공통 규칙 |
| 보드 엔진 | `board_key=submission` · P23-04 본체 | 과외쌤이 씀. 공부방 메뉴만 숨김 |
| 상태 화면 개념 | P15-10 = 제출 여부·공개 범위 **표시만** | 주 사용자는 과외쌤. 공부방 권한은 △ 유지 |
| 용어 | 제출함 · 제출자료 상태. 검증/인증/심사 금지 | 22장 §7 |

구현 시: 업로드·권한·경로 가드는 **역할 플래그**로 막는다. 공부방용 별도 보드/별도 스토리지를 만들지 않는다.

## 2. 공부방 — 숨기거나 후순위

이번 버전 집중: **공개/노출 체크리스트와 3단계 입력.**

### 화면에서 숨김 (이번 버전)

| 위치 | 처리 |
| --- | --- |
| 마이페이지 내 등록 | 제출함 링크 없음 |
| 공부방 운영홈 탭 | 제출함 탭 없음. 옛 URL은 「쓰지 않음」 안내만 |
| P15-10 / P23-04 | 공부방 역할이면 진입해도 사용 UI 없음 |
| 홈 카드 | 「제출자료 n개」 없음. 픽·프라임 신뢰는 **교육청 등록 체크** |
| 등록 3단계 | 파일 제출함 칸 없음 |

### 후순위 (스키마는 유지)

| 항목 | 메모 |
| --- | --- |
| `study_room_verification_documents` | 원본 `file_path` · 공개용 `masked_file_path` 이미 있음. UI/API 없음 |
| `study_room_badges` | 이번 버전 동기하지 않음 |
| 원본 비공개 + 유저 마스킹 공개용 + ON/OFF | 검토만 함. 이번 버전 범위 아님 |
| 교육청 배지를 파일 확인으로 바꾸기 | 하지 않음. 체크+번호가 최소 신뢰 |

### 이번 버전 공부방이 쓰는 신뢰

- 상세2 **교육청 등록 체크 + 번호**
- 카드 배지 = 그 체크 (`education_office_registered`)
- 홍보사진은 제출함이 아님

## 3. 과외쌤 — 이번 버전 실제 노출·사용

제출함은 버리지 않는다. 과외쌤 기준으로 **쓸 수 있게** 둔다.

| 위치 | 이번 버전 |
| --- | --- |
| 마이페이지 내 등록 | 제출자료 상태(P15-10) · 제출함(P23-04) **노출** |
| 등록 상세2 | 「증빙서류 제출 가능」 체크 + **제출함 열기** |
| 픽·프라임 카드 | 「제출자료 n개」 (`tutor_verification_documents` 집계) |
| 베이직 카드 | 제출자료 행 없음 (카드 매핑 [48](./48-tutor-home-card-map.md)) |
| 공개 게이트 | 제출함 미완으로 공개를 막지 않음. 공개는 체크리스트 |

### 과외쌤 제출함에서 다루는 것 (1차 항목)

본인 확인 · 학력 · 경력 · 자격증. 플랫폼 보증 없음. 공개 범위는 본인 확인용 / 학부모 공개용 라벨.

안정화 때 손볼 것(기능은 유지, 완성도만 올림):

- 등록 3단계 안의 파일 칸 (지금은 마이페이지로 안내)
- 체크(`proof_document_available`)와 실제 파일 수 동기
- 업로드·공개범위 UX

## 4. 구현 관점 — 어디를 고치고 어디를 건드리지 말지

| 구분 | 이번 버전 |
| --- | --- |
| 공부방 제출함 메뉴를 다시 켜기 | ✕ |
| 제출함 보드·첨부 스토리지를 과외쌤용으로 유지 | ○ |
| `study_room_verification_documents` DROP | ✕ (후순위 기반) |
| 공부방 공개 게이트에 제출함 필수 | ✕ |
| 과외쌤 공개 게이트에 제출함 필수 | ✕ (선택 신뢰. 고액과외용 자료) |
| 교육청 체크를 파일 증빙으로 교체 | ✕ |
| 역할 가드 (`study_room` 숨김 · `tutor` 사용) | ○ 공통 코드 위 |

**공통 개발** = 테이블·저장소·보드·P15-10 개념·22장 문구.  
**차등 운영** = 메뉴 노출, 카드 필드, 등록 단계 CTA, 이번 버전 할 일 순서.

---

## 5. 이번 버전 할 일 순서 (정책)

1. 공부방: 공개 체크리스트 · 단계 입력 · 카드 매핑 정리 ([47](./47-study-room-home-card-map.md))
2. 과외쌤: 제출함 진입·업로드·상태 표시가 실제로 돌게 ([48](./48-tutor-home-card-map.md))
3. 후순위: 공부방 원본/공개용 증빙 이미지. 그때도 보드를 크게 살리지 않고, 공통 저장 + 공부방 전용 2칸을 검토
