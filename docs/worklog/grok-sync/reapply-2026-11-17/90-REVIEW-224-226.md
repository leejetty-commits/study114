## R1 상세 — 로그인 사용자의 빈 카드 클릭 차단

현재 코드(`main.js:581-606`, capture 단계, document):

```js
const guestOnly =
  href.includes('#/login') || href.includes('#/signup') ||
  action === 'login-gate' || action === 'compare-guest-blocked' || action === 'search' ||
  Boolean(target.closest('[data-prime-empty], [data-basic-empty], [data-pick-empty]'));
if (!guestOnly) return;
if (sessionChecked && !isLoggedIn()) return;   // 손님은 통과
event.preventDefault(); event.stopPropagation(); // 로그인 사용자·세션 전은 막힘
```

- 빈 프라임·픽 카드(`exposure-render.js:697-717 renderEmptyPromoCard`)는 공부방·과외쌤 로그인 화면에도 나오고, 안에 「유료상품 보기」(`data-nav="/plans/positions"`)가 있다(`exposure-rules.js:160` — 학부모만 버튼 없음).
- document capture에서 `stopPropagation`하면 그 아래 `data-nav` 처리와 `href` 이동이 모두 멈춘다.
- 빈 카드 손님 게이트는 원래 `shared/guest-gate-ui.js:283-300 bindGuestEmptyCardLoginGate`가 「로그인 사용자는 통과」로 따로 처리하고 있다. main.js 쪽 줄은 중복이고, 로그인 사용자에겐 반대로 동작한다.
- 11-17 상세등록 멈춤과 같은 종류(#224가 손님 전용 차단 목록에 로그인 화면 요소를 넣음).

최소 수정(별도 PR, `main.js` 이 블록만):

```js
// 로그인 뒤에는 손님 전용 목록도 막지 않는다. 세션 확정 전에만 막는다.
if (sessionChecked) return;
event.preventDefault();
event.stopPropagation();
```

즉 `if (sessionChecked && !isLoggedIn()) return;` 한 줄을 `if (sessionChecked) return;`로 바꾼다.
- 이유: 로그인 사용자 화면엔 `login-gate`·`compare-guest-blocked`·로그인/가입 링크가 애초에 안 그려진다. 막을 대상은 「세션 확인 전에 손님 셸에서 눌린 것」뿐이다(3a77299b의 원래 목적).
- 상세등록 두 메뉴(#239) 분기는 그대로 둔다.
- 수락: 공부방·과외쌤 로그인 → 홈·찾기의 빈 프라임 카드 「유료상품 보기」 클릭 → `#/plans/positions`. 손님은 빈 카드 클릭 시 로그인 안내 그대로. 00-INDEX 공통 점검 전부.
- 먼저 운영에서 실클릭으로 증상부터 확인한다. 확인되면 이 수정을 01 다음 순서로 넣는다(오픈 전).
