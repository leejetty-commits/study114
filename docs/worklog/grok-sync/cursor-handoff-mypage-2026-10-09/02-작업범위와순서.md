## 0. 모든 티켓 공통 규칙 (어기면 불합격)

### 0-1. 절차 (종현 잠금)
**점검 → 작업 → 검수 → 보완 → … → 검수완료 → 종현 보고 → 종현 승인 후 배포.**
- Cursor는 「작업」과 「보완」까지만 한다. 검수는 우동공과2(그록봇)/메인 에이전트가, 승인은 종현이 한다.
- **main push · main merge · 배포 · `build:dothome` 산출물 커밋 · PR 머지 = 종현 승인 없이는 절대 금지.**
- 「완료」 = **검사로 확인된 것**. 화면을 한 번 띄워 본 것만으로는 완료가 아니다. 합격 기준 숫자를 실제로 재서 보고한다.

### 0-2. 브랜치·커밋
- 티켓 하나 = 브랜치 하나: 최신 `origin/main`에서 `cursor/mypage-<티켓>-<짧은이름>-YYYYMMDD` (예: `cursor/mypage-t1-devterms-20261010`).
- **한 번에 티켓 하나.** 앞 티켓이 「검수완료」가 되기 전에 다음 티켓을 같은 파일에서 시작하지 않는다(파일이 겹치는 티켓이 많다).
- stage는 **허용 파일만 경로를 하나씩** 지정. `git add -A` / `git add .` 금지. 이미 push한 커밋 amend·rebase·force-push 금지.
- 커밋 메시지는 한국어, 한 줄 요약 + 티켓 번호.

### 0-3. 허용 파일 원칙
- 각 티켓의 「허용 파일」 밖 파일을 한 줄이라도 바꾸면 **불합격**. 꼭 필요하면 멈추고 보고해서 허락을 받는다.
- 모든 티켓에 공통으로 허용: 작업 기록 1개 `docs/worklog/2026/10/<날짜>-mypage-<티켓>.md`(저장소 관례: 지시서 원문·바꾼 파일·검사 결과·스크린샷 경로). 스크린샷은 저장소에 커밋하지 않는다(`tmp/` 등 로컬).
- 아래는 **어느 티켓에서도 금지**(티켓에 명시된 줄 제외):
  - 사이트 공용 CSS: `styles/tokens.css`, `styles/design-system.css`, `styles/udx-std-apply.css`, `styles/home.css`, `styles/home-member-flows.css`, `styles/home-admin.css`, `styles/home-provider-reviews.css`
  - `src/main.js`, `src/state.js`, `preview/shared/**`(특히 `study-room-basic-form.js`), PHP(`src/**`, `public/api/**`), `sql/**`, `.github/**`, `.cursor/rules/**`, 기존 검사 스크립트(`scripts/verify-*.mjs` 수정 금지 — 새 검사 파일 추가는 티켓에 적힌 경우만)
  - 공개 마이샵 `src/myshop/**`, `styles/myshop-public.css`
- 옛 CSS를 고치는 대신 `styles/mypage-ops.css`에서 **마이페이지 범위 선택자**로 덮어쓴다(01 §5-1).
