## 0. 현재 진단 (한눈에)

| 문제 | 현상 |
|------|------|
| 제목 일관성 없음 | H1「이용안내 / ○○」+ H2 동일 반복 · 문서 title은 계속「메인 화면 프리뷰」 |

## 1. 역할 재정의 (신박한 한 줄)

**이용안내 = “어떻게 쓰면 되는지” 플레이북**  
**고객센터 = “문제·정책·문의” 헬프데스크**

- 이용안내에 약관·신고·자료실을 **두지 않음** (연결만).
- 고객센터에 “처음 이용 6단계”를 **두지 않음** (가이드로 보냄).

## 2. 제안 메뉴 구성 (좌메뉴 · 슬림)

### KEEP (4 + 홈)
| 라벨 | 라우트 | 한 줄 역할 |
|------|--------|------------|
| 이용안내 홈 | `#/guide` | 허브 · 상황별 입구 3개만 |
| 찾기·첫 이용 | `#/guide/start` | 찾는 사람 여정 (구 getting-started) |
| 등록·공개 | `#/guide/register` | 등록하는 사람 여정 (구 registration) |
| 찜·비교·쪽지 | `#/guide/connect` | 저장·비교·첫 쪽지 (구 saved-contact) |
| 안전하게 쓰기 | `#/guide/safe` | **행동 수칙**만 (정책 본문은 CS) |

### CUT / MOVE
| 현재 | 처리 |
|------|------|
| 허브의「고객센터 연결」큰 섹션(공지/FAQ/약관/자료/문의 타일 나열) | **한 줄 링크**로 축소 → `#/support` |
| 우레일 가이드 카드 4장 (좌메뉴와 동일) | **삭제** 또는 현재 페이지만 관련 1개 |
| 「빠른 흐름 요약」이 좌메뉴·카드와 동어반복 | 허브에서는 **상황 3카드만** 남기고 요약 블록 삭제 |
| `#/guide/safety`의 긴 정책성 본문 | 가이드는 체크리스트 5~7개 +「정책 전문 → CS」 |
| 레거시 `#/policy/*` | 전부 `#/support/policies/*`로 **리다이렉트** |

### 라벨 톤 (일관)
- 좌메뉴·H1·카드 제목 = **같은 짧은 명사구** (「이용안내 / 등록방법」이중 표기 금지)
- H1 = 페이지 이름만 (`등록·공개`)  
- Eyebrow = `이용안내` (전 서브 공통)

## 4. 페이지별 레이아웃·카피 골격

### 공통 Shell
- Type B: 좌메뉴(화이트) + 본문 + **슬림 우레일**(관련 다음 행동 1~2만) 또는 서브는 우레일 **접기/최소화**
- 타이포: H1 22/28 · 섹션 18 · 본문 14/16 · Pretendard 토큰
- 장식: edge accent / chip / icon tile (코너 브래킷 금지 · 유료 warm 캔버스는 가이드에 강제 적용하지 않음 — 정보형 white)

### A. `#/guide` 허브 (대폭 축소)
**남길 것**
1. H1 `이용안내` + 리드 1문장  
2. **상황 카드 3장만**  
   - 찾는 중이에요 → `#/guide/start`  
   - 등록하려고요 → `#/guide/register`  
   - 찜·쪽지 쓰려고요 → `#/guide/connect`  
3. 보조 링크 1행: `안전하게 쓰기` · `고객센터`
4. (선택) 다음 행동: 공부방찾기 / 과외쌤찾기 — 기존「다음 단계」축소

**뺄 것:** 자주 찾는 안내 4카드 + 빠른 흐름 요약 3열 + CS 타일 벽 + 우레일 중복 가이드 카드

**카피 예**  
리드: `찾기·등록·쪽지까지, 필요한 흐름만 짧게 안내합니다.`

### B. `#/guide/start` (찾기·첫 이용)
**구조:** compact intro → **한 가지** 진행 UI만  
- 추천: **가로 스텝 5** (차트 OR 상세 단계 중 **하나만**; 나머지는 접기)  
  1 대상 고르기 → 2 검색 → 3 찜·비교 → 4 상세 확인 → 5 첫 쪽지  
- CTA: `공부방 찾기` · `과외쌤 찾기` · (로그인 시) 이어보기  
- 하단 링크만: `찜·비교·쪽지 자세히`

**뺄 것:** 플로우 차트와 6단계 카드 동시 전개

### C. `#/guide/register` (등록·공개)
**구조:** intro → 공통 5스텝 1열 → **공부방 / 과외쌤 탭**으로 체크리스트만 분기 → FAQ는 **3개만** 또는 CS FAQ로 링크  
스텝: 가입 → 기본등록 → 상세등록 → 공개 → (선택) 유료 노출  
CTA: `공부방 등록` · `과외쌤 등록` · `유료상품 안내`

**뺄 것:** 히어로 칩 + 차트 + 6단계 + 역할별 장문 중복

### D. `#/guide/connect` (찜·비교·쪽지)
**구조:** intro → **기능 3칩**(찜/비교/쪽지) 한 줄 → 스텝 4~5 **하나만** → CTA `찜 목록` · `쪽지함`  
비교 FAQ는 **접기 3문** 또는 삭제 후 본문에 1표만

**카피 주의:** 「쪽지는 유일한 채널」단정 문구는 제품 포지션과 충돌 소지 →  
`첫 연락은 쪽지로 시작하세요` 정도로 완화 제안 (정책 확정 전 가정, 확정 카피와 맞출 것)

### E. `#/guide/safe` (안전하게 쓰기)
**구조:** intro → **하지 말 것 / 할 것** 체크 2열 → 문제 시 `신고·분쟁`·`고객센터` 링크만  
정책 전문·긴 원칙문은 `#/support/policies/safety`로

## 5. 고객센터와의 경계 (라우팅 정리)

| 주제 | 이용안내 | 고객센터 |
|------|----------|----------|
| 어떻게 찾나/등록하나 | ✅ 본문 | 링크만 |
| 찜·비교·쪽지 사용법 | ✅ 본문 | FAQ에 짧은 항목만 |
| 선입금·외부결제·개인정보 | 체크리스트 | **정책 전문** |
| 신고·제재·분쟁 | 링크 | **정본** `#/support/policies/reporting` |
| 공지·문의·자료실 | 링크 1행 | ✅ 본진 |

`#/support` vs `#/support/notice`: 루트를 공지 하이라이트 허브로 두고 notice는 alias, 또는 notice만 남기고 루트는「도움 허브」카드형으로 **차별** — 현 상태(동일어)는 제거 대상.

## 6. 레이아웃 “신박” 포인트 (구현 힌트)

1. **허브 = 상황 3문** (역할 기반 IA). 문서 목차형 4카드 폐기.  
2. **서브 = 단일 내러티브** (차트 XOR 스텝). Progressive disclosure.  
3. **우레일 다이어트**: 서브에서는「다음 가이드 1 + CS 1」만. 파란 빈 기둥 제거.  
4. **제목 체계 고정**: Eyebrow `이용안내` / H1 페이지명 / H2 섹션(플로우·다음 행동) — H1에 `이용안내 /` 접두 금지.  
5. **모바일**: GNB 축약 + 좌메뉴 아코디언/셀렉트. 390 가로 스크롤 FAIL 처리.

---

## 7. 삭제 우선순위 (과감)

1. 허브 우레일·본문·좌메뉴 **삼중 반복** 링크  
2. 각 서브 **플로우+단계 이중 전개** 중 하나  
3. 레거시 `#/policy/*`  
4. 가이드 안 CS 타일 월  
5. `#/support`≈notice 중복  
6. guide safety ↔ policies safety 본문 복붙
