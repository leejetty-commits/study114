- 작성일: 2026-09-24 (KST)
- 목적: 사용자가 예전에 구상한 **실시간 매칭** 방향을 내부 SSOT로 보관. 구현·Cursor 티켓 아님.
- 상태: **기획 진행** — 주체·지역 버킷 잠금. 구상 원본 파일 업로드 후 항목·플로우 병합 예정
- 출처: 2026-09-24 채팅 구상 · 주체 판단(급함·유료 의지) · 우동공과2 의견

---

## 0. 한 줄 개념

학생이 가입(또는 매칭 항목 저장)하면, **그 지역·조건에 맞는 제공자에게 알림**이 가고, 학생 본인에게는 **같은 규칙으로 목록·검색이 바로** 열린다.  
제공자가 **미리 걸어 둔 조건**에 맞는 학생이 들어오면 **제공자에게 즉시 알림**.

전역 스캔이 아니라 **지역 버킷 안에서만** 후보를 고른다.

---

## 0-A. 주체 잠금 (2026-09-24 「정리」)

판단 초점: **누가 더 급한가 · 누가 돈을 들여서라도 대상을 찾으려 하는가.**

| | 역할 | 잠금 |
|--|------|------|
| **유료·푸시·구독 조건의 주체** | **공부방(1순위) → 과외쌤(2순위)** | 자리가 비면 매출이 바로  Aff고, 이미 프라임·픽·홍보지역에 지갑을 여는 쪽 |
| **이벤트(공급)** | 학생 가입·매칭 항목 저장 | 제공자 조건을 채우는 트리거 |
| **학생 쪽 가치** | 가입 직후 **무료**로 맞는 제공자·방이 **검색·목록에 바로** 보임 | “알림을 사서 찾는” 주체가 아님 |

양방향처럼 보여도, **급함·지갑의 주체는 제공자**다.  
제품·과금·알림 UX를 설계할 때 기본 화살표는 **학생 가입 → 제공자 알림**이고, 학생 화면의 즉시 검색은 **전환·신뢰용 무료 가치**로 둔다.

공부방을 1순위로 둔 이유: 동(우리동네) 단위로 수요가 매출과 직결되고, 소상공인 모델·기존 유료 노출과 맞다.  
과외쌤은 시·군으로 학생을 구하지만 유료 의지는 들쭉날쭉할 수 있어 **2순위**.

---

## 1. 사용자 구상 (채팅 원문 요약)

1. **학생 → 제공자**  
   - 가입 시 특정 항목 입력 → 맞는 과외쌤·공부방에 **자동 알림**.  
   - 가입 직후 **본인에게도 검색(목록)이 바로** 된다.
2. **제공자 → 학생**  
   - 과외쌤(등)이 특정 항목을 **미리** 입력해 두면, 맞는 학생이 가입할 때 **즉시 알림**.  
   - (주체 잠금 후) 이 “미리 입력”은 **제공자 구독·조건**이 제품의 중심축.
3. **부하에 대한 판단**  
   - 크게 서버에 부담을 주지 않는다고 봄.  
   - 이유: **지역 기반** — 공부방은 **우리동네(동)**, 과외쌤은 **시·군** 단위로만 검색.

(원본 기획 파일이 오면 이 절을 파일 기준으로 교체·보강한다.)

---

## 2. 지역 버킷 (제품과 맞출 SSOT)

| 역할 | 매칭·알림 1차 버킷 | 제품 쪽 기존 잠금과의 정렬 |
|------|-------------------|---------------------------|
| 공부방 | **우리동네 · 홍보지역1(동)** | 홈/찾기 홍보1 (044·050·051) |
| 과외쌤 | **시·군** | 가입 시·군 매핑 (030) |
| 학생 (피매칭·검색 기본) | 학생이 넣은 희망지역 / 동네 기준이 제품 정의와 일치해야 함 | 추후 원본·가입 필드와 맞춤 |

**넣지 말 것 (함정):** 개설주소·hub·데모 대치·게스트 시드만으로 매칭 버킷을 대체하는 폴백.

---

## 3. 알림 vs 검색 (같은 규칙)

| | 알림 (제공자 주체) | 검색·목록에 바로 보이기 (학생 무료 가치) |
|--|-------------------|------------------------------------------|
| 시점 | 학생 가입·매칭항목 저장(쓰기 이벤트) | 같은 이벤트 직후 **동일 필터로 1회 조회** |
| 범위 | 해당 지역 버킷 + 조건을 건 **제공자** | 가입 학생 본인 화면의 기본/결과 목록 |
| 과금 | 조건 구독·알림 우선·상한 등은 **제공자** 쪽 후보 | 학생에게 알림 유료화하지 않음(잠금) |
| 규칙 | **알림과 목록이 다른 조건이면 안 됨** (“알림은 왔는데 찾기에 없다” 방지) |

매칭은 상시 폴링이 아니라 **가끔 있는 쓰기 + 버킷 조회**에 붙는 일회성 작업으로 둔다.

## 4. 부하·스팸 가드 (초안 권고)

- 1차 컷: 지역 버킷만 → 후보 집합을 작게.
- 2차 컷: 학년·과목·희망유형 등 **가입/구독에 이미 있는 항목**만 (필드 목록은 원본 파일 병합 시 확정).
- 시·군은 동보다 넓을 수 있음 → 알림 **상위 N**, **하루 상한**, **중복 억제** 권장.
- 전 회원 푸시·전역 풀스캔 금지.
- 제공자 알림 스팸 억제는 유료 주체 경험의 핵심(무료 난사 금지).

## 5. 잠금 / 미잠금

### 잠금 (2026-09-24)

- 주체: **유료·알림 구독 = 공부방(1) · 과외쌤(2)** / 학생 = 무료 즉시 검색.
- 지역: 공부방=동(홍보1) · 과외쌤=시·군.
- 알림과 검색 **동일 매칭 규칙**.
- 구현·배포·노션·홈찾기 커밋과 **혼합하지 않음** (기획만).

### 아직 잠그지 않은 것 (원본 파일·후속 대기)

- 매칭에 쓰는 **정확한 항목 목록** (학생 / 과외쌤 / 공부방 각각).
- 알림 채널 (앱 내 쪽지·푸시·뱃지 등)과 카피.
- 조건 변경 시 재매칭 여부·빈도.
- 유료(프라임/픽)와 매칭 알림 **우선순위·묶음 과금**의 구체 관계.
- 구현 순서·티켓 분할.
