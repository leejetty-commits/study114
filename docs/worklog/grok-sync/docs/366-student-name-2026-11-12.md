## 종현 확정 (2026-11-12)

1. 학생 기본정보에서 「표시명」 항목을 없애고, 그 자리에는 학생 이름(`student_name`)을 쓴다.
2. 다른 사람에게 보이는 학생 이름은 가운뎃자를 가린다.
   - 2자: `홍*`
   - 3자: `홍*동`
   - 4자 이상: 첫 글자와 끝 글자만 남기고, 가운데는 글자 수만큼 `*`(예: `홍길동일` → `홍**일`)
   - 1자는 `*`. 이 경우는 보고에 적는다.
   - 가림 기호는 `*`(동그라미 `○` 쓰지 않음).
3. 본인 화면(기본정보·마이페이지)에서는 이름 전체를 보여 준다.
4. 관리자 화면은 지금 방식을 그대로 둔다.
5. 학생 상세정보 용어는 「희망지역 추가값」이 아니라 「희망지역 추가」다.

## 범위

1. **용어:** 학생 상세정보의 「희망지역 추가값」을 화면, 안내문, SSOT·문서에서 모두 「희망지역 추가」로 바꾼다.
2. **표시명 칸 제거:** 학생 기본정보(가입·수정·읽기)에서 「표시명」 입력·표시 항목을 없앤다. 그 자리에는 학생 이름을 보여 주고, 본인이 수정할 수 있게 한다(기존 이름 입력 규칙 유지).
3. **가림:** 다른 사람에게 보이는 학생 이름은 위 규칙으로 가린다. 가림 함수는 **서버 쪽 한 곳**에 두고, **화면이 아니라 API 응답 단계**에서 가린 값만 내보낸다. 프론트는 타인에게 학생 이름 원문을 다시 그리지 않는다.
4. **본인·관리자:** 본인(기본정보·마이페이지)에게는 이름 전체. 관리자 화면은 변경하지 않는다.
5. **기존 데이터:** `public_display_name` 값은 지우지 않는다. 화면·공개 API에서 쓰지 않게만 한다. 지울지는 보고에만 적는다. 이름이 비어 있는 기존 학생이 있으면 어떻게 보이는지 보고한다.
6. **DB:** 이 작업에 스키마 변경(컬럼 삭제·추가)이 필요하면 구현하지 말고 먼저 보고한다. 가입 저장 시 `public_display_name`이 비면 안 되는 제약이 있으면, 화면에서는 안 쓰더라도 `student_name`과 같은 값을 넣어 스키마를 건드리지 않는다.
