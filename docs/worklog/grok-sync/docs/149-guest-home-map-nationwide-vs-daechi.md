## 2. 실측 (2026-09-25 운영)

### 2.1 숫자 API (정상 축)

`POST /api/search/region-stats.php` `{}` → 공부방 1 · 과외 0 · 학생 0 · axes 대치동/서울시/서울시.

### 2.2 홈 목록 API (지도 핀 원천 · 문제)

게스트 홈은 라이브 목록을 `filters:{}`(빈 필터)로 가져온다.

`POST /api/search/search.php`  
`{"tab":"room","filters":{},"page":1,"limit":50,"sort":"latest"}`

| id | 이름 | 지역 | 위도·경도 |
|----|------|------|-----------|
| 1 | 대치 Prime … | 대치동 | 37.49 / 127.06 |
| 2 | 우동 Pick … | 해운대 우동 | 35.16 / 129.16 |
| 3 | 센텀 Basic … | 센텀동 | 35.16 / 129.13 |
| 6–9 | 가능동 등 | 의정부 등 | 좌표 없음 → 핀 제외 |

좌표 있는 핀만으로도 **대치↔부산 약 250km** 떨어짐.

`region_label=대치동` 필터 시 total **1** (숫자 축과 맞음).


### 2.4 브라우저 스모크 (2026-09-25)

게스트 `#/guest` · 비로그인.

- 라벨: 현재위치 **서울 강남구 대치동** · 숫자 공부방 1 / 과외 0 / 학생 0
- 타일 안정 후: **한반도 광역**(약 50km 스케일 · 서울·인천·강원·충북·울릉·독도 보임) — 대치 동네 줌 아님
- 샷: `/workspace/guest-map-audit/guest-home-map-before.png`, `guest-home-map-after.png`

**버그 재현 확인.**

### 2.3 프론트 동작 (번들)

1. `VN()` = 라이브 공부방 중 위·경도 있는 것 최대 12개  
2. `xb(..., VN(), { regionLabel: Gf.full })` → 네이버 지도  
3. 핀 **2개 이상**이면 `fitBounds`로 모든 핀이 보이게 줌 축소  
4. 그 결과 **라벨은 대치동**인데 **화면은 전국(광역)**  

첫 페인트: 목록 로드 전(`Te.live` false)에는 핀 0 → 대치 기본 좌표(zoom 13)일 수 있음.  
로드 후 리렌더에서 부산+대치 핀 → **전국으로 벌어짐**. 「초기에 대치가 정확히 안 나오고 전국으로 보인다」와 맞음.

## 4. 수정 방향 (권장 · 로컬 티켓용)

**목표:** 손님 홈 지도는 항상 **대치동 동네**처럼 보이게.

권장(최소·정책 일치):

1. 손님 홈 지도에 넣는 핀 = **대치동(데모 축)에 해당하는 공부방만**  
   - 목록 fetch에 `region_label`(또는 동등 필터) **대치동**을 넣거나  
   - 클라이언트에서 `Gf`/데모 동 기준으로 핀 필터  
2. 손님 홈(`variant` guest/home)에서는 핀이 0~1개여도 **중심=대치동 · zoom≈14** 고정.  
   - 핀 2개+여도 **fitBounds로 타시도까지 넓히지 않음** (대치 바운드 클램프 또는 fitBounds 비활성).  
3. 카드 목록(프라임/픽/베이직) 정책을 전국 샘플로 두는 것과 지도를 섞지 말 것.  
   - 목록 노출 규칙이 전국이어도 **지도 카메라·핀은 대치 축** (122 지도 박스와 동일).

비권장: GPS로 고치기(122에서 게스트 홈 GPS 없음 잠금).
