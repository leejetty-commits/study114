# 326 · 이상적인 반응형 웹(모바일) 구현 방안

> 작성 2026-11-07 KST · 상태: 초안 — 사용자 검토 대기
> 정본: `docs/internal/80-mobile-responsive-proposal.md`

## 목적

study114(우동공과)의 웹사이트 우선(Desktop-first) 원칙 아래, 모바일 구조적 문제를 해결하는 4파트 계획.

## 대원칙

1. 웹사이트가 우선이다 — 데스크톱 레이아웃은 건드리지 않는다
2. 모바일은 같은 콘텐츠·다른 배치 — 기능 삭제 없이 시각 배치만 변경
3. 기존 CSS 토큰(`tokens.css`) 재사용
4. 배포 파이프라인 변경 없음

## 현황 문제 4건

1. **GNB 9항목 잘림**: 모바일 수평 스크롤에서 5~6개만 보임, 커뮤니티·고객센터 잘림
2. **지도 여백**: 히어로맵 세로 배치 시 canvas(9~13rem) + banner(8rem) = 17~21rem, 빈 공간 과도
3. **레일 481~1023px**: 본문 아래 전부 쌓여 스크롤 길어짐
4. **유틸바 480px 숨김**: 이용안내·로그인 접근 경로 사라짐

## 4파트 작업 범위

| 파트 | 핵심 | 수정 파일 | 위험도 | 우선순위 |
|---|---|---|---|---|
| **A. 햄버거 GNB** | ≤899px 수평스크롤 → ☰ 드로어 + 유틸 통합 | site-chrome.js, layout.js, home.css | 중간 | 1순위 |
| **B. 히어로 맵 아코디언** | ≤719px 지도 접힘 + banner 위로 | guest-sections.js, home.css, search-visily.css | 낮음 | 2순위 |
| **C. 레일 아코디언** | ≤1023px 레일 접힌 아코디언 통일 | right-rail.js, home-right-rail.css | 낮음 | 2순위(B 병렬) |
| **D. 카드 세로형 보완** | ≤600px 카드 세로형 통일 | search-visily.css, home-listings.css | 낮음 | 3순위 |

## 지도 여백 해결 — 권장안

모바일에서 banner(지역명+통계+CTA)를 위에, 지도 canvas를 「지도 보기 ▾」 아코디언으로 접어 둠. 첫 화면에서 카드 목록 즉시 보임.

## PC 안전성

- 모든 변경은 CSS 미디어쿼리(≤899px 등) 안에서만 동작
- 기존 데스크톱 규칙 삭제·수정 없음 (추가만)
- 파트별 별도 커밋 → 문제 시 파트 단위 revert 가능
