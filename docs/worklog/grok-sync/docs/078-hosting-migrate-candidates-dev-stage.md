## 0. 솔직한 한계

공유→공유 이사만으로 522/525가 **반드시** 사라지진 않는다.  
다만 CS·백업·트래픽 정책·체감 안정성은 업체마다 다르고, 닷홈 현 구간이 **개발도 막는 수준**이면 이전 검토 이유는 충분하다.

## 1. GitHub만으로 되나?

| 되는 것 | 손볼 것 |
|---------|---------|
| 앱 코드·히스토리 | GitHub Actions의 **FTP/배포 시크릿·경로**를 새 호스트에 맞게 |
| 빌드 산출물 재생성 | `.env` / DB 접속 / 세션·쿠키 도메인 |
| Cloudflare 네임서버 유지 | A 레코드를 **새 원본 IP**로 변경 (프록시 ON 유지 가능) |
| | MySQL **덤프·복원**, SES 메일은 CF DNS 그대로면 유지 |

“자료가 깃에 있다 = 원클릭 이사”는 아님. **반나절~수일** 이전 공수는 잡는 게 맞다.

## 3. 권고 (우동공과 · 개발중)

1. **단독은 나중에** (정식·트래픽 증가 시).
2. ~~이전한다면 1순위 가비아…~~ → **§4 예산 보정 후:** 1순위 카페24 VPS 일반형 · 2순위 가비아 PHP 베이직.  
   “카페24 500원”은 **하지 말 것**.
3. Cloudflare는 **유지**. 원본만 갈아끼우기.
4. 이전 전: 닷홈 항의 기록 유지 + 새 호스트에서 **스터디 서브도메인/스테이징**으로 먼저 올려 522 패턴 비교.
