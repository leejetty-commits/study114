## 1. 「가입 · 기본등록 완료」의 빈 칸 — 답

**제대로 된 표기가 아니다.**

| 화면 항목 | 스크린샷 | 의미 |
|-----------|----------|------|
| 회원 ID (DB) | `—` | `signupState.lastSignup.userId` 없음 |
| 역할 (DB role_type) | `—` | `signupState.lastSignup.roleType` 없음 |
| 로그인 계정 | 확인됨 | 이메일 확인은 됨 |
| 기본등록 프로필 | `study_room #8` | **기본등록 저장은 성공** |
| 기본등록 seed | 가능동·일본어·홍보지역1… | seed도 있음 |

코드 (`signup-complete.js`): 공부방/과외쌤 완료 화면에 **디버그용** `회원 ID (DB)` / `역할 (DB role_type)`를 `lastSignup`에서 읽는다.  
`lastSignup`은 역할 선택 직후(`signup-role.js`)에만 채운다. 이메일 확인·새 창·SPA 상태 유실 후에는 비고, 이후 기본등록 결과(`basicRegisterResult`)만 남는 패턴이 가능하다.

학생 완료 화면은 이 DB 칸을 **아예 안 보여** 더 정상적이다.

**판정**

1. 빈 칸 ≠ 가입 실패. 프로필 `#8`이 있으면 기본등록은 된 것이다.  
2. 일반 회원에게 DB id / `role_type` raw를 보여주는 것 자체가 정책상 불필요(운영 화면이 아니라 검수/디버그 냄새).  
3. 고쳐야 할 것: (A) 완료 화면에서 디버그 dl 제거·회원용 요약만, 또는 (B) `fetchMeApi()`로 id·role을 채워 `—` 금지.

## 2. 이슈별 · 최근 노션 vs 현상

### 2-1. 학생 · 과외 희망지역 (시·군)

- **정본:** 과외 희망/활동 = **시 기준**(14장·UDX). 광역(도/광역시) 다음 = **시·군(시군구)** 목록.  
- **현상:** 「경기도 의정부시」선택 후 「선택한 시에 매핑된 지역이 없습니다.」→ 다음 불가.  
- **판정:** **버그.** 시 선택까지 됐는데 하위/매핑 데이터가 비어 있음(목록 불완전과 동일 축).

### 2-2. 이메일 확인 후 새 창

- **정본:** 확인 완료 후 **같은 흐름**으로 역할별 기본등록(2장 §2-5-1).  
- **코드:** 공부방 「상세등록 이어하기」가 `window.open(STUDY_ROOM_UI_BASE, '_blank')`.  
- **판정:** **버그/정책 위반.** 같은 탭 `location.assign`이 맞음(과외쌤은 이미 assign). 새 창이 게스트 상세 플래시(2-1) 원인도 됨.

### 2-3. 공부방 · 기본→상세 때 게스트 「공부방상세정보」 깜빡임

- **판정:** **버그.** 상세 이어하기가 새 창·게스트 엔트리로 열려 로그인 라우트 정착 전 공개 상세가 보임.

### 2-4. 상세정보1·2 · 빈 저장 · 안내 카피

- **최근 정본(2026-09-19):** 공개≠입력완성. 빈 값은 빈 값. 필수는 **Prime/Pick 자격·안내**용.  
- **14장(상대적으로 이전 층):** 상세1 필수 7 + 상세2 필수 1 = **Prime 자격 8개** (공개 게이트 아님).  
- **화면:**  
  - 상세1: 「필수정보는 입력해 꼭 해주세요」+ 다수 `*` · **「비어도 저장」안내 없음** · 하단 저장 있음.  
  - 상세2: 「비어 있어도 저장할 수 있습니다」있음 · 「저장 꼭 누르라」는 없음.  
  - 다른 플로우(선택 상세1): 「상세정보 1 (선택)」+ 「다음 단계로」만.  
- **저장 실패 예:** `curriculum cannot be null` — UI/정책상 비어도 진행인데 **DB NOT NULL**이 막음.  
- **카피 판정:**  
  1. 상세1·2 **동일**하게 「지금 다 안 채워도 됩니다. 다만 아래 **저장**(또는 다음)은 눌러 주세요」필요.  
  2. `*` / 「꼭 해주세요」는 **Prime 자격 항목**에만 쓰고, 공개·단계 진행을 막지 않게.  
  3. 빈 저장이 되게 서버·스키마(또는 insert 시 빈 문자열/스킵) 맞출 것. NOT NULL로 alert 나면 「선택」카피는 거짓말.
