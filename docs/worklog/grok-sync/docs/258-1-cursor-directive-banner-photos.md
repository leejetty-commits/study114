## 3. 작업 내용

## 5. 작업 순서와 커밋

1. 브랜치 `cursor/258-catalog-banner-photo-20261019` 최신 상태에서 시작한다. **이미 push된 브랜치이므로 rebase 하지 마라** (force-push가 필요해지므로 금지).
2. 작업 1: 원본 대조 → 복사 → 복사본 전수 대조 (크기·SHA-256).
3. 작업 2: CSS 무변경·참조 경로 일치만 확인한다.
4. 커밋은 **사진만 담은 별도 커밋 하나**로 추가한다. 기존 커밋 `20bda9f0`를 고치거나 합치지 마라.
   - 커밋 메시지: `258 assets(home): 카탈로그 배너 사진 3장을 banners 자산에 더한다`
   - `git add`는 사진 3개를 하나씩 이름으로 지정해서 담아라. **`git add -A` 금지.**
   - 커밋 직전 `git status`와 `git diff --cached --stat`으로 담긴 파일이 사진 3개뿐인지 확인한다. 다르면 커밋하지 말고 멈춰서 보고해라.
5. 브랜치를 push하고 **멈춘다.** main에 합치지 않는다.
6. 이후 순서는 고정이다: **브랜치 push 후 멈춤 → 검수 → 종현 승인 → main 병합.** 승인 전에 main에 병합하거나 배포하지 마라.

## 8. 확인 방법

모두 확인하고 보고해라. 하나라도 빠지면 완료가 아니다.

1. **사진 대조:** 복사한 3장의 파일명·크기·SHA-256이 2장 표 및 원본과 각각 같은지, 합계 55,420 bytes인지.
2. **파일 범위:** `git diff --stat`과 커밋 기준으로 이번 커밋에 사진 3개만 들어갔는지. CSS를 포함한 그 밖 파일 변경이 0인지.
3. **화면 확인:** 홈 상단 3칸에 각 칸 사진이 보이는지 (공부방 칸=공부방 사진, 과외쌤 칸=과외쌤 사진, 학생 칸=학생 사진), 왼쪽 흰 막 위로 글자가 읽히는지, 왼쪽 색 띠가 보이는지, hover에서 사진이 사라지지 않는지.
4. **모바일:** 폭 390px(720px 이하)에서 1열로 쌓이고 사진·글자가 깨지지 않는지.
5. **로드 실패 차이 기록:** 사진을 못 불러오면 흰 막 때문에 거의 흰색으로 보인다는 알려진 차이는 이번에 고치는 대상이 아니다. 화면 확인에서 이 모습을 봤으면 그 사실만 보고에 적어라 (임의로 CSS를 고치지 마라).
