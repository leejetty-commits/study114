## 0. 한 줄 (쉬운 말)

메일 확인 링크는 **새 탭**에서 열린다(막을 수 없음).  
**예전에 열어 둔 대기 탭**은 확인이 끝날 때까지 **더 진행하지 못하게 잠긴 화면**으로 두고, 확인이 끝나면 **그 대기 탭이 기본정보(역할별 Basic)로 이어가게** 한다.

브라우저 탭 자체를 OS처럼 잠그거나, 메일 앱이 연 탭을 강제로 없애는 것은 **범위 밖·불가에 가깝다.**

---

## 1. 동작 잠금

### 1.1 대기 탭 (`verify-email?send=1` 등 대기 화면)

메일 발송 성공 후(이미 대기 화면인 동안):

1. **잠금 UI:** 다시 보내기 외 가입 진행 조작은 막거나, “이 화면에서는 이어가지 마세요”가 분명할 것.  
   - 권장: 안내 카피를 **잠금 톤**으로 보강 — 「메일 링크는 새 탭에서 열립니다. 확인이 끝나면 **이 탭**에서 기본정보로 이어집니다. 그전까지 이 화면에서는 진행하지 마세요.」  
   - 「이 탭은 닫아도 됩니다」만 강조하던 073 톤은 **이 티켓 목표와 충돌** → 대기 탭을 **이어갈 주 탭**으로 재정의. 닫아도 됨은 **부차**(새 탭에서도 이어갈 수 있음은 유지하되, 기본 안내는 대기 탭 이어가기).
2. **수신:** 다른 탭에서 이메일 확인이 완료되면 신호 수신 → `basicRegisterPathForMe` / 역할별 Basic으로 `navigate`.  
3. 신호 수단: `BroadcastChannel` 및/또는 `localStorage` storage 이벤트(폴백). 채널명·키는 한곳에 상수.
4. 확인 완료를 **폴링만**으로 때우지 말 것(가능하면 확인 탭이 publish). 보조로 짧은 `fetchMe` 폴백은 허용·보고.

### 1.2 확인이 끝난 탭 (메일 링크로 연 탭)

1. 기존처럼 확인 처리·세션 확립.
2. **대기 탭에 “확인 완료” 신호 publish** (역할·다음 경로 hint 포함 가능).
3. 이 탭 UX (택1, 보고에 명시):  
   - **A(권장):** 확인 완료 짧은 안내 + 「원래 탭에서 이어가세요. 이 탭은 닫아도 됩니다.」· 자동으로 Basic까지 또 열지 **말 것**(대기 탭이 이어가므로 **이중 Basic 진입 최소화**).  
   - 대기 탭이 없/신호를 못 받으면 기존처럼 이 탭에서 Basic 이어가기(폴백).
4. `window.close()` 시도는 **해도 되고 실패해도 OK**(스크립트가 연 탭이 아니면 대부분 실패) — 실패를 에러로 쓰지 말 것.

### 1.3 하지 말 것

- 메일 앱이 새 탭 여는 동작 차단·변경  
- 대기 탭 `window.close()` 강제(실패·이상 UX)  
- 다른 사이트 탭 조작  
- BroadcastChannel을 핑 핑거프린팅/추적에 오용  
- 학생 기본정보 086 WIP·홈 dirty와 **한 커밋으로 섞지 말 것**  
- push / `build:dothome`

## 4. 스모크

1. 탭1 가입 → 메일 발송 대기: **잠금 안내** 보임.  
2. 탭2에서 확인 링크(또는 로컬 동등 트리거): 탭1이 **Basic으로 이동**.  
3. 탭2는 이중 Basic 자동 진입 없이 안내(또는 폴백만).  
4. 탭1만 있는 경우(신호 없음): 기존 폴백으로 가입 가능·보고.  
5. 공부방/과외쌤/학생 역할별 Basic 경로.
