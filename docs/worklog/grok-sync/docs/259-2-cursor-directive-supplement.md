## 1. 배경 — 왜 조건부 합격인가 (Cursor 잘못 아님)

1. 259 커밋 `8b217632`는 검수에서 **조건부 합격**을 받았다. 남은 조건은 아래 **조건 A·B 2건뿐**이며, 두 건 모두 지시서가 가리킨 위치·단언이 실제와 어긋난 **지시서 쪽 문제**다. Cursor가 지시서대로 구현한 것 자체는 잘못이 아니므로, 이미 반영된 259·259-1 확정분을 되돌리거나 다시 만들지 마라.
2. **조건 A (소개 힌트의 실제 렌더 위치 불일치):** 259-1에서 새 소개 힌트 문구 「상세 소개를 입력하면 카드와 확대카드에 보입니다」로 문장 자체는 바뀌었으나, 그 문장이 실제로 렌더되는 위치가 아니었다. 실제로 프라임 미입력 목록에 뜨는 것은 `registration-check-copy.js:140`(브랜치 `8b217632` 기준)의 `intro_long` 힌트 「프라임 상세에서 과외를 설명합니다」이며, 이 줄은 이번 검수 시점까지 **무변경**이다. 그래서 화면에서는 옛 힌트가 그대로 보인다.
3. **조건 B (검사 스크립트의 옛 제목 단언):** 검사 스크립트 `scripts/verify-tutor-registration-check-frame.mjs:114-115`가 옛 제목 `'[픽] 추가 입력'`·`'[프라임] 추가 입력'`을 단언하고 있어 **2건 실패**한다. 259에서 제목이 `픽 노출까지 추가 입력`·`프라임 노출까지 추가 입력`으로 확정·변경됐으므로, 스크립트 쪽 단언이 옛 문구에 머문 것이 원인이다.
4. 이 문서는 위 2건을 종현 확정안으로 봉합한다. 이 문서를 받은 뒤에는 조건 A·B를 이유로 다시 멈추지 말고, 2장 확정안 그대로 좁게 반영하라. 단, 2장 밖의 새 문안·새 범위가 필요해지면 그때는 6장대로 중단 보고하라.

## 5. 작업 순서 — 259 브랜치에서 이어서

2. 작업 시작 전 `git status`가 깨끗한지 확인한다. 더럽혀져 있으면 그 내용을 보고에 적고 멈춰라. 기준 코드가 2장의 전(before) 문구와 크게 다르면 억지로 맞추지 말고 멈추고 보고하라 (6장).
3. 허용 파일(4-1) **2개만** 수정한다: `registration-check-copy.js`의 `intro_long` 힌트 1줄(2-1), `verify-tutor-registration-check-frame.mjs` 114-115행 2줄(2-2). 범위 밖 파일이 필요하다고 판단되면 멈추고 보고한다 (6장).
