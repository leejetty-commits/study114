## 종현 확정 (2026-11-10 t4806)

학생 가입에서 기본정보를 입력한 뒤 「상세정보 이어서하기」(화면 문구: 「상세정보 이어서 입력하기」)를 누르면 상세정보 화면이 나와야 한다. 지금처럼 마이페이지·내등록(목록 또는 마이프로필)으로 바로 가면 오류다.

## 원인 (main `0db907fe` 기준, 확인됨)

`preview/auth-ui/src/screens/signup-complete.js`의 `go-detail-register`가 공부방·과외쌤은 각 상세등록으로 보내는데, 학생만 `${HOME_UI_BASE}/#/mypage/registrations/students`(목록)로 보낸다. 상세 화면은 마이페이지에 이미 있다. 목적지 경로도 이미 있다.

- 목록: `#/mypage/registrations/students`
- 상세 폼: `#/mypage/registrations/students/{id}/detail` (`studentSectionPath(id, 'detail')`, `renderDetailForm`)

## 대상

학생 가입 완료 화면의 「상세정보 이어서 입력하기」 버튼 이동.

## 범위

1. `preview/auth-ui/src/screens/signup-complete.js`의 학생 분기만 고친다. `data-action="go-detail-register"` 클릭 시 상세 폼으로 이동한다.
2. 목적지: `${HOME_UI_BASE}/#/mypage/registrations/students/{id}/detail`. `{id}`는 `signupState.basicRegisterResult.id`이고, `kind`가 student일 때만 쓴다. 경로 문자열은 기존 `studentSectionPath(id, 'detail')`과 같게 맞춘다. auth-ui에서 그 함수를 바로 쓸 수 있으면 재사용하고, 아니면 같은 해시만 쓴다. 새 경로를 만들지 않는다.
3. id가 없을 때(완료 화면 새로고침 등으로 상태가 비는 경우): 기존 본인 학생 조회 API로 id를 받아 같은 상세 경로로 이동한다. 그래도 id를 못 얻으면 지금처럼 목록으로 보낸다. 폴백 방식을 보고에 적는다.
4. 이동 뒤에는 허브(마이프로필)나 목록이 아니라 상세 폼(`renderDetailForm`)이 보여야 한다.
