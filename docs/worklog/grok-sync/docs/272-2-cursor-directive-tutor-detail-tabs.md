  - 「주 회수 기준」(`monthly_by_weekly_schedule`): **주 회수 select.** 기본등록 `tutor-ui/src/screens/step-basic.js:140-141`과 같은 코드 `shared/lesson-weekly-options.js`의 `lessonWeeklyOptions()`·`lessonWeeklySelectValue()`를 그대로 쓴다(1회~7회, 기타=8). 라벨 「주 회수」. 저장 칸은 **`tutors.lessons_per_week`(기본정보 주 회수와 같은 값)** 이다. 새 칸을 만들지 않는다.
    - 주의: 기본정보 필수 항목과 같은 값이므로, 여기서 바꾸면 기본정보·카드 「주 ○회」도 바뀐다. 빈 값(「선택」)으로 저장해 기본정보를 지우는 일이 없게, **이 상자에서는 빈 값을 보내지 않는다**(값이 있을 때만 `lessons_per_week`를 싣는다). lesson 저장이 `lessons_per_week`를 받지 않으면 고치지 말고 멈추고 보고.
  - 「월 총 횟수 기준」(`monthly_by_total_sessions`): **월 총 횟수 select.** 옵션: 「선택」(빈 값), 「월2회」(2) … 「월15회」(15), 「월16회 이상」(16). 라벨 「월 총 횟수」. 저장 칸 `tutors.monthly_session_count`.
  - 산정방식을 안 고르면 상자는 「주 회수 기준」 모양으로 둔다(지금 기본값 동작 확인 후 같게).
- 옵션 상수는 공용 파일 하나(예: `shared/lesson-monthly-options.js`, `lessonMonthlyOptions()`·`lessonMonthlySelectValue()`)에 두고 화면·등록점검·마이프로필이 같이 쓴다.
- 산정방식을 바꿔도 **다른 쪽 값은 지우지 않는다**(주 회수 기준으로 바꿔도 `monthly_session_count`를 비우지 않음, 반대도 같음). 보내는 값은 보이는 상자 하나뿐.

**저장 형식**
- DB 형식은 **바꾸지 않는다.** `monthly_session_count SMALLINT UNSIGNED NULL` 그대로, 값은 2~15 정수, 「월16회 이상」은 **16**. 빈 값 = NULL.
- 서버는 이미 정수로 받는다(`optionalInt`). **PHP 수정 없음.** 범위 검사(2~16)를 서버에 넣어야 할 것 같으면 고치지 말고 보고.

**기존 값 대응 (화면에서만, DB는 손대지 않음)**
- DB 값이 2~15 → 그 옵션 선택. 16 이상 → 「월16회 이상」 선택(저장하면 16이 됨 — 사용자가 저장할 때만). 0·1·NULL → 「선택」(빈 칸)으로 보이고, **사용자가 저장하지 않으면 DB 값은 그대로.**
  - 1처럼 옵션에 없는 값이 있는 계정이 저장하면 NULL이 되는 것을 막기 위해: 옵션에 없는 기존 값이고 사용자가 상자를 건드리지 않았으면 `monthly_session_count`를 **보내지 않는다.**
- DB가 이미 정수 칸이라 「글자로 적힌 값」은 DB에 있을 수 없다. 숫자로 못 읽는 값은 화면 쪽 상태값에만 있을 수 있고, 그때는 빈 칸.

**종현에게 넘길 SQL (Cursor는 실행하지 않는다. 운영 DB 쓰기 없음, 읽기만)**

```sql
-- 1) 읽기 전용 확인: 월 총 횟수 분포 (먼저 이것만 돌린다)
SELECT fee_basis_type,
       CASE
         WHEN monthly_session_count IS NULL THEN 'NULL'
         WHEN monthly_session_count BETWEEN 2 AND 15 THEN '2-15'
         WHEN monthly_session_count >= 16 THEN '16+'
         ELSE CONCAT('out:', monthly_session_count)
       END AS bucket,
       COUNT(*) AS n
FROM tutors
GROUP BY fee_basis_type, bucket
ORDER BY fee_basis_type, bucket;

-- 2) 읽기 전용 확인: 옵션에 없는 값(0·1) 계정 목록
SELECT id, fee_basis_type, monthly_session_count, lessons_per_week
FROM tutors
WHERE monthly_session_count IS NOT NULL AND monthly_session_count < 2;
```

- **이전(migration) SQL은 없다.** 16 이상을 16으로 바꾸는 UPDATE도 하지 않는다(카드에 나오지 않고, 화면이 「월16회 이상」으로 읽으므로 필요 없음). 1)·2) 결과에 이상한 값이 많으면 종현이 따로 정한다.

**카드·검색 표시 확인 (읽기만, 보고)**
- 우동공과2 확인: `monthly_session_count`는 카드(`home-ui/src/exposure-render.js`)·검색 응답 표시에 **쓰이지 않는다.** 쓰는 곳은 마이프로필 `home-ui/src/tutor-reg/profile-read.js:39,53`과 등록점검 `registration-check-model.js` `monthlyLabel`.
- 이 두 곳은 공용 옵션 함수로 「월N회」「월16회 이상」 글자를 만든다. 값이 없거나 옵션에 없으면 **「-」** 를 보인다(지금 등록점검은 「—」 표시: 현황표 빈 값 표시 규칙과 같으면 그대로, 다르면 보고).
- Cursor가 카드·검색에서 이 값을 쓰는 곳을 찾으면 줄 번호를 보고하고, 표시가 바뀌어야 하면 고치지 말고 멈추고 보고.

### 5-2. 전체 과정 2회 (우동공과2, **새 시험 계정만**, 2회 모두 다른 새 계정)

가입 → 이메일 인증 → 기본등록 → 상세등록 1·2 → 등록점검 → 마이페이지 상세정보1·2 수정 → 저장 → 다시 열기(새로고침) 순서로, 각 단계에서:

1. **라우팅:** 탭 주소(`detail`, `detail2`), 옛 주소 `detail?focus=feature_2` 등이 맞는 탭으로 감, 뒤로가기, 등록점검 `return` 배너 복귀.
2. **API 기록:** `/api/tutor/register.php` 요청마다 `action`·`step`·보낸 키·응답(`ok`, 상태 코드). 상세정보1 저장은 `save/lesson`만, 상세정보2 저장은 `save/career`+`save/contact`만. 저장 뒤 `load`(또는 DB)에서 값이 실제로 남았는지.
3. **보존:** 홍보 채널, 연락 가능 시간, 상세 소개, 기존 `feature_3`(DB에 미리 넣은 값), 기존 `monthly_session_count`=1인 계정(옵션 밖 값) — 손대지 않고 저장해도 그대로. `lessons_per_week`가 상세정보1 저장으로 비워지지 않음.
4. **월 총 횟수:** 「월 총 횟수 기준」 + 「월16회 이상」 저장 → DB 16 → 다시 열면 「월16회 이상」. 주 회수 기준으로 바꿔 저장해도 `monthly_session_count` 그대로.
5. **특징 3:** 입력·저장·다시 열기·비우기.
6. **등록점검:** 빈 계정으로 줄마다 「수정」 링크 → 해당 탭·칸 강조·포커스(모든 줄, 결과 표). 픽·프라임 목록 「입력하러 가기」 전부 칸 찾음(feature_3 포함).
7. 「저장되었습니다.」 안내, 「취소」가 저장 안 함.
