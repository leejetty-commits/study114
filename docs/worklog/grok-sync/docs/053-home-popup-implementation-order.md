## 1. 권장 순서 (티켓 쪼개기)

### Phase 0 — 확정만 (코드 거의 없음)
1. ~~set-a vs set-b 한 세트~~ → **2026-09-25: 6종 전부 구현 · 골라 쓰기** (111)
2. 유형: 공지 / 이벤트 / 광고 (우선순위 공지>이벤트>광고, 동시 1개) — 유지
3. 대상·미리보기: 111 잠금 (관리자만 미리보기 · 공개 시 대상 복수)
4. (선택) 공지 게시판 연동 Phase5 이번/나중

### Phase 1 — 프론트 모달 껍데기 (**6종**, 레이아웃 고정)
**목표:** pack6 시안 6장을 홈에 심고, **더미 props** + **관리자만** 연다. **작업 분할 권장.**

**1a (먼저)**
1. Modal 셸: 오버레이 · 카드 · X · ESC · focus trap · 「오늘 하루 보지 않기」
2. **set-a** 템플릿 3종(공지·이벤트·광고) — HANDOFF/111 잠금
3. 에셋 lockup PNG · 모바일 규칙
4. 관리자 세션에서만 더미 표시 · 유형 전환 스위치(더미)

**1b (이어서, 별 티켓/커밋 가능)**
1. **set-b** 3종(워터마크 imprint)
2. 패밀리(set-a/set-b) 선택 UI(더미·이후 관리자 필드)

**아직 하지 않음:** 관리자 저장 API/DB, 공개 배포.  
**스모크:** 관리자로 홈에서 6종을 하나씩 열어 보기·닫기·(미리보기에서) 하루 안 보기 무시.

### Phase 2 — 표시 엔진 (어떤 팝업을 고를지)
1. 활성 팝업 목록 in-memory/API 응답 소비
2. 우선순위·기간(start/end)·surface·enabled 필터
3. 「오늘 하루 보지 않기」키 = popup id별
4. 로그인/게스트 분기(Phase 0 결정 따름)

**스모크:** 더미 2건 중 우선순위·기간만 맞는 1건.

### Phase 3 — 백엔드 정본 (sessionStorage 졸업)
1. 테이블(예: `site_popups` 또는 기존 content 패턴 맞춤): id, type, title, body, cta_label, cta_url, image_url, surface, priority, starts_at, ends_at, enabled, sort…
2. API: 관리자 CRUD + 공개 GET(홈용, enabled·기간만)
3. 업로드(이미지)는 기존 미디어/업로드 파이프 재사용 우선

**스모크:** DB에 넣은 팝업이 홈 GET으로 내려옴. sessionStorage 의존 제거(또는 마이그레이션 후 deprecate).

### Phase 4 — 관리자 연동
1. 기존 `#/admin/settings/popups`를 **API 저장**으로 교체(프리뷰 sessionStorage 제거/폴백)
2. 필드 = 내용만(레이아웃 HTML 편집 UI **금지**)
3. 유형 선택 → 미리보기(가능하면 Phase1 템플릿 재사용)
4. 권한: 관리자만

**스모크:** 관리자 저장 → 새로고침·다른 브라우저에서도 홈에 동일 노출.

### Phase 5 — (선택) 공지 연동
1. `#/admin/notices/posts` 글 → 「팝업으로도 띄우기」링크/체크 (자동 복제 또는 popup이 notice_id 참조)
2. 없어도 Phase 1–4로 운영 가능 — **후순위**

### Phase 6 — 배포
1. allowlist 커밋만 (홈찾기 044~051 배치와 섞지 말 것)
2. 사용자 「배포해」후에만 push/`build:dothome`

## 2. 하지 말 순서 (함정)

| 잘못된 순서 | 이유 |
|-------------|------|
| 관리자 UI부터 고치기 | 템플릿·API 없으면 다시 sessionStorage 미봉 |
| 시안 HTML을 관리자 파일로 업로드 | 레이아웃 파손·XSS·버전 난립 |
| DB 없이 운영 배포 | PC/세션마다 내용 다름 |
| 공지 게시판 연동부터 | 범위 팽창. 팝업 CMS가 먼저 |
| 홈/찾기 위치 티켓과 한 커밋 | 롤백·리뷰 지옥 |
