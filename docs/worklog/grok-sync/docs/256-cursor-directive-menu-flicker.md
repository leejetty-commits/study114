## 1. 왜 이런 일이 생기는지 (분석 완료, 코드 근거)

추측이 아니라 아래 파일에서 확인한 원인이다. (기준: `origin/main` `2a061f58`)

1. **로그인 확인이 끝나기 전에 화면을 먼저 그린다.**
   - `preview/home-ui/src/main.js`의 `shouldPaintBeforeSession`: 세션 확인이 끝나기 전에도 먼저 그리도록 허용하는 경로가 있다.
   - `preview/search-ui`는 셸(틀)을 그릴 때 세션을 기다리지 않고 그린다.
   - 확인 전에는 사용자 정보가 `user=null`이다. 그래서 비회원 헤더·본문이 잠깐 그려졌다가, 확인이 끝나면 로그인 화면으로 다시 그려진다. 이 "먼저 그려졌다가 다시 그려짐"이 깜빡임이다.

2. **역할 홈 자체는 이미 보호되어 있다. 건드리지 마라.**
   - `preview/home-ui/src/main.js:147-148, 260` 근처: 역할 홈은 세션 전 선행 페인트에서 보호되고 있다. 이 보호를 풀거나 우회하지 마라.

3. **학생찾이는 매번 재발하는 구조다.**
   - 학생찾이는 `preview/search-ui` 전체를 이동(새로 그림)하므로, 메뉴를 누를 때마다 세션 미확정 상태의 첫 그림이 다시 발생한다.

4. **커뮤니티·고객센터도 같은 위험군이다.**
   - 커뮤니티·고객센터는 선행 페인트 대상이고, `preview/home-ui/src/main.js:434-437` 근처에서 게시판(board)을 `navRole guest`(비회원 역할)로 먼저 불러온다. 세션 확정 후 역할이 바뀌면 다시 그려질 수 있다.

5. **고칠 지점 후보 (이 범위 안에서 최소안을 골라라):**
   - ① `main.js` 선행 페인트에서 커뮤니티·고객센터를 제외한다. 또는 세션 확인 전에 로딩 셸만 보여 준다.
   - ② `search-ui` 헤더를 "세션 미확정 상태"와 "게스트(비회원 확정) 상태"로 분리한다. 미확정일 때는 게스트 헤더를 그리지 않는다.
   - ③ `auth-session`(`preview/home-ui/src/auth-session.js`): `me.php` 확정이 끝나는 즉시 다시 그리게 하고, 부가 로딩(부가 정보 불러오기)은 재렌더 뒤로 미룬다.
   - 위 ①~③ 중 점검(2장)에서 확인된 메뉴만 고치는 데 필요한 최소 조합을 선택하고, **택한 방식과 이유를 보고에 명시**해라.

## 2. 첫 단계 (필수) — 메인메뉴 전체 점검, 점검 없이 일부만 고치지 마라

**코드를 고치기 전에 반드시 이 점검부터 하고, 표로 기록해라. 점검 없이 커뮤니티·학생찾기 등 일부 메뉴만 골라 고치는 것은 금지한다.**

### 점검 방법
1. 로그인 상태 4가지로 각각 로그인한다: **학생 · 공부방 · 과외쌤 · 비회원(비로그인)**.
2. 각 상태에서 **상단 메인메뉴 전 항목을 하나씩 눌러 전환**한다. 메인메뉴 항목은 상단 헤더에 실제로 보이는 전 항목을 빠짐없이 대상으로 한다 (홈, 공부방찾기, 과외쌤찾기, 학생찾기, 커뮤니티, 고객센터 등 그 상태에서 보이는 전 항목. 항목이 더 있으면 표에 행을 추가해라).
3. 전환할 때마다 **게스트(비회원) 헤더·본문이 잠깐이라도 보이는지**를 눈으로 확인한다. 가능하면 화면 녹화나 느린 네트워크(개발자도구 네트워크 제한) 조건도 함께 써서, 빠르게 지나가 못 보는 경우를 줄여라.
4. 아래 표를 채워 보고에 그대로 포함해라. 한 칸도 비우지 마라. 확인을 못 한 칸은 "확인 못 함 + 이유"로 적어라.

### 점검 표 (양식 — 그대로 복사해 채울 것)

| 로그인 상태 | 전환한 메인메뉴 항목 | 게스트 화면 잠깐 보임 (예/아니오) | 무엇이 보였나 (헤더만/본문만/둘 다, 구체적으로) | 비고 |
|---|---|---|---|---|
| 학생 | (항목별로 한 행씩) | | | |
| 공부방 | (항목별로 한 행씩) | | | |
| 과외쌤 | (항목별로 한 행씩) | | | |
| 비회원 | (항목별로 한 행씩) | | | |

- 비회원 상태에서는 게스트 화면이 보이는 것이 정상이다. "보임=정상, 깜빡임 아님"으로 구분해 적어라.
- 역할 홈이 이미 보호되고 있는지(1장 2번)도 표에서 확인해라. 보호가 깨져 있으면 그 자체를 보고에 적어라.

### 수정 대상 확정
- **게스트 화면이 잠깐 보인 메뉴만 수정 대상으로 확정한다.** 보이지 않은 메뉴는 고치지 마라.
- 수정 대상이 분석(1장)에서 예상한 메뉴(학생찾기·커뮤니티·고객센터) 밖으로 넓어지면, 6장(허용 파일)의 규칙대로 **멈추고 보고**해라.
- 점검 표 없이, 또는 점검 표가 비어 있는 채로 낸 수정 보고는 인정하지 않는다.

## 3. 수정 원칙 (반드시 지킬 것)

1. **세션 확인 전에는 게스트 화면을 그리지 않는다.**
   - 세션이 확정되지 않은 동안에는 비회원 헤더·본문을 그리지 마라. "일단 게스트로 그리고 나중에 바꾸기"는 이 작업의 금지 사항 그 자체다.

2. **로딩 중 표시는 최소안 하나로 통일한다.**
   - 선택지: (a) 기존 화면 유지(전환 전 화면을 그대로 두었다가 확정 후 새 화면을 그림), (b) 빈 셸(헤더·본문 내용 없이 틀만, 또는 아무것도 그리지 않음).
   - 코드 구조에 맞는 **최소안 하나**를 고르고, 왜 그 방식인지, 어느 메뉴에 적용했는지를 **보고에 명시**해라. 메뉴마다 다른 방식을 쓰면 그 이유도 적어라.
   - 새로운 로딩 화면·스피너·문구를 디자인해서 추가하지 마라. 이 작업은 "게스트를 안 보여주는 것"이지 "로딩 화면을 만드는 것"이 아니다.

3. **세션 확정 즉시 다시 그린다.**
   - `me.php`로 로그인 상태가 확정되는 즉시 실제 역할 화면으로 다시 그려라. 부가 로딩이 재렌더를 늦추고 있으면, 부가 로딩을 재렌더 뒤로 미루는 쪽으로 정리해라 (1장 후보 ③).

4. **241 결정과 충돌하지 않게 한다.**
   - 241 결정: **분기를 모르는 상태(세션 확인 전)에서는 찾기 메뉴를 숨긴다.** 이 동작은 유지한다.
   - 즉, 세션 미확정 상태에서 찾기 메뉴를 미리 보여주거나, 분기를 추정(기본값으로 채우기)해서 메뉴·화면을 그리는 방식으로 깜빡임을 해결하지 마라.

5. **249 건(`#/messages`, 완료)과 섞지 않는다.**
   - 쪽지함 주소 건은 완료된 별도 작업이다. 이 작업에서 `#/messages` 관련 코드·동작을 건드리거나 함께 고치지 마라. 점검 중 쪽지함에서 같은 깜빡임이 보여도, 이 지시서에서는 **기록만** 하고 수정 대상에 넣지 마라 (필요하면 별도 지시서로 분리 보고).

6. **진짜 비회원 화면은 바꾸지 않는다.**
   - 로그아웃 상태·비회원이 실제로 보는 게스트 헤더·본문의 내용과 동작은 현행 그대로다. 바꾸는 것은 "로그인 확인 전에 게스트로 그려지는 것"뿐이다.

## 4. 별도 항목 — 과외쌤찾기 반대 분기 현재위치 안내 문구 (255 결정)

이 항목은 1~3장(깜빡임)과 **별도 항목**이다. 같은 지시서로 함께 진행하되, 아래 규칙을 지켜라.

- 결정 근거: `ds/docs/255-find-place-prompt-decision-2026-10-18.md` (종현 결정, 2026-10-18). 코드를 고치기 전에 이 메모를 읽어라.

### 바꿀 내용
- 과외쌤찾기의 **반대 분기**에서 나오는 현재위치 안내 문구 「마이페이지에서 희망지역을 등록해 주세요」를 「아래 검색창에서 지역을 선택하여 검색하세요」로 바꾼다.
- 반대 분기란: 학생이 자기 분기와 반대쪽 찾기를 여는 경우다. 공부방 분기 학생이 과외쌤찾기를 여는 경우와, 그 반대(과외 분기 학생이 공부방찾기를 여는 경우)도 **동일한 취지**로 적용한다. 반대쪽 찾기에서는 마이페이지 희망지역 등록을 유도하지 않는다 (희망지역은 자기 분기 기준 저장이므로, 반대 화면에서 바꾸라고 안내하면 안 된다).
- 반대쪽 찾기의 기본 지역을 비워 두는 기존 결정(241)은 유지한다. 문구만 바꾸는 작업이다.

### 지금 코드에서 문구가 나오는 곳 (`origin/main` `2a061f58` 기준, 참고)
- `preview/shared/location-display.js:581` — `STUDENT_PLACE_PROMPT = '마이페이지에서 희망지역을 등록해 주세요'`
- 사용처: `preview/search-ui/src/screens/search-page.js:94`, `preview/search-ui/src/search-find-surface.js:2487, 2739`

### 경로 분리 주의 (가장 중요)
- 위 상수는 반대 분기만이 아니라 **학생 현재위치 표시 전반**에 쓰일 수 있다.
- 상수 값을 통째로 바꾸면, **자기 분기 탭에서 진짜로 희망지역을 등록하지 않은 학생에게 보여야 할 안내까지 같이 바뀌어 버릴 수 있다. 그것은 금지한다.**
- 따라서 먼저 각 사용처가 "반대 분기 표시 경로"인지 "자기 분기(진짜 미등록) 표시 경로"인지 나눠 확인하고, **반대 분기 경로만** 새 문구가 나오게 분리해라.
  - 예: 반대 분기 전용 상수/값을 따로 두거나, 표시 지점에서 분기를 나눠 문구를 고른다. 방식은 코드 구조에 맞는 최소안으로 하고, 택한 방식을 보고에 적어라.
- 자기 분기 탭의 진짜 미등록 안내 「마이페이지에서 희망지역을 등록해 주세요」는 **그대로 유지**되는 것을 확인 항목(7장)에서 반드시 검증해라.

### 커밋 분리
- 이 문구 항목과 깜빡임 항목(1~3장)이 **파일이 겹치면 함께** 고쳐도 된다.
- **파일이 겹치지 않으면, 같은 브랜치에서 별도 커밋**으로 나눠라. 한 커밋에 섞지 마라.
- 문구 항목 커밋 메시지: `256 fix(search): 반대 분기 현재위치 안내 문구를 검색창 지역 선택으로 변경` (7장 보고에 실제 해시를 적어라.)

## 5. 작업 순서

1. 최신 `origin/main`에서 브랜치 `cursor/256-menu-flicker-20261018`을 만든다.
2. **2장 점검을 먼저 끝내고 표를 채운다.** 점검 결과가 이 지시서의 예상과 크게 다르거나, 수정 대상이 허용 파일(6장) 밖으로 넓어지면 고치지 말고 **멈추고 보고**한다 (t1844 중단 보고 방식: 무엇을 확인했고, 어디서 막혔고, 어떤 파일이 더 필요한지를 적어 중단 보고).
3. 점검으로 확정된 메뉴만 3장 원칙대로 고친다.
4. 4장 문구 항목을 진행한다. 파일이 겹치지 않으면 별도 커밋으로 나눈다.
5. 고친 파일만 하나씩 지정해서 add한다 (`git add -A` 금지). 커밋 메시지:
   - 깜빡임: `256 fix(nav): 메뉴 전환 시 세션 확인 전 게스트 화면 깜빡임 수정`
   - 문구 (별도 커밋 시): `256 fix(search): 반대 분기 현재위치 안내 문구를 검색창 지역 선택으로 변경`
6. 브랜치를 push하고 **멈춘다**. main에 합치지 않는다. force push는 하지 않는다.

  - 비회원(게스트) 화면 자체의 내용·디자인
  - 저장 지역 DB 구조, 가입 저장 방식, 서버의 세션/분기 판단 규칙
- **허용 파일이 늘어야 하면 멈추고 보고한다.** 2장 점검 결과로 필요한 파일이 위 목록 밖에서 나오면, 임의로 범위를 넓히지 말고 t1844 중단 보고를 해라: 점검 표, 추가로 필요한 파일과 이유, 예상 영향 범위를 적어라. 종현 확인 없이 범위 밖 파일을 고치지 마라.

## 7. 확인 방법

### 깜빡임 (1~3장)
1. 2장 점검 표를 수정 후에도 같은 방식으로 다시 돌린다: **학생·공부방·과외쌤·비회원 × 상단 메인메뉴 전 항목** 전환 시 게스트 헤더·본문이 잠깐도 보이지 않는지 확인한다. 수정 전/후 표를 나란히 보고에 넣는다.
2. 로딩 중 표시로 택한 방식(기존 화면 유지 또는 빈 셸)이 실제로 그렇게 보이는지, 메뉴별로 확인해 보고에 적는다.
3. 실제 로그인 후 각 역할의 최종 화면(헤더 메뉴 구성·본문)이 수정 전과 같은지 확인한다 (회귀 확인).
4. 세션 확인 전 찾기 메뉴가 숨겨진 채로 남는지 확인한다 (241 유지 확인).
5. 비회원 상태의 화면이 수정 전과 같은지 확인한다.
6. `#/messages` 동작이 수정 전과 같은지 확인한다 (249를 섞지 않았는지 확인).

### 문구 (4장)
7. 반대 분기: 공부방 분기 학생이 과외쌤찾기를 열었을 때 (그리고 과외 분기 학생이 공부방찾기를 열었을 때) 현재위치 안내가 「아래 검색창에서 지역을 선택하여 검색하세요」로 보이는지 확인한다.
8. 자기 분기: 희망지역을 등록하지 않은 학생이 자기 분기 탭을 열었을 때 안내가 「마이페이지에서 희망지역을 등록해 주세요」 **그대로**인지 확인한다. (경로 분리 검증)
9. 반대쪽 찾기에서 지역 고르기(시·군·구 → 행정동/아파트단지, 시 전체)로 검색이 되는지, 처음 현재위치가 비어 있는지도 확인한다 (241 유지 확인).

### 공통
10. `git diff origin/main --stat`에 허용 파일(6장)만 있는지 확인한다. 커밋이 나뉘어 있으면 커밋별로 파일 목록을 확인한다.
