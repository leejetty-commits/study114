# 253 지시서 — 학생 기본정보에서만 '다음' 버튼·칸별 안내 고치기 (S-M5)

- 작업 번호: 253
- 식별: S-M5
- 날짜: 2026-10-18
- 확정: 종현이 2026-10-18에 확정했다. 확정 문구: "학생 기본정보에서만 고쳐줘."
- 브랜치 이름: `cursor/253-student-signup-basic-20261018`
- 기준 코드: `origin/main` `666393b6` (확인 기준). 작업 시작 시점의 최신 `origin/main`에서 브랜치를 만들어라. 줄 번호가 밀렸으면 아래 함수·표시 이름으로 같은 코드를 찾아 확인하고, 함수 내용 자체가 이 지시서와 크게 다르면 멈추고 보고해라(9번).
- 이 글의 목적: 무엇을, 어느 파일만 건드려서, 어떻게 확인할지를 정하는 지시서다. 이 지시서에 없는 변경은 하지 마라.

> 쉬운 말 안내: 학생이 가입할 때 기본정보를 적는 화면에서만 고친다. 필수 칸이 비어 있으면 아래 '다음' 버튼을 누를 수 없게 하고, 칸을 채울 때마다 버튼 상태가 바로 바뀐다. 그래도 제출이 되면(예: 버튼 상태를 우회한 경우) 예전처럼 경고창 하나로 한꺼번에 띄우지 말고, 빠진 칸 바로 아래에 빨간 안내를 띄우고 첫 번째 빠진 칸으로 커서를 옮긴다. 다른 가입 단계, 공부방·과외쌤 화면은 건드리지 않는다.

---

## 1. 목적

- 학생 기본정보 화면에서만 아래 두 가지를 바꾼다.
  1. **'다음' 버튼 실시간 비활성**: 필수 칸이 하나라도 비면 '다음' 버튼이 비활성(`disabled`)이고, 입력이 바뀔 때마다(`input`·`change` 등 그 칸의 값이 바뀌는 순간) 다시 검사해서 버튼 상태가 바로 갱신된다. 전부 채워지면 버튼이 다시 활성화된다.
  2. **제출 시 칸별 인라인 안내 + 첫 칸 focus**: 제출 시점에 빠진 칸이 있으면, `alert`로 한꺼번에 띄우지 말고 각 빠진 칸 아래에 인라인 안내를 표시하고, **첫 번째 빠진 칸**으로 `focus`(커서 이동)를 옮긴다. 칸을 하나씩 채우면 그 칸의 안내는 그때그때 사라진다.
- 정상적으로 다 채워서 제출하면, 저장·다음 화면 이동은 지금과 완전히 같아야 한다.

## 2. 범위 (종현 확정 — 넓히지 마라)

### 하는 것 (학생 기본정보만)

- 대상 화면: 학생 가입 기본정보 (`renderStudentBasic`이 그리는 폼, `data-form="basic-student"`).
- 대상 동작: 위 1번의 버튼 비활성·실시간 갱신, 제출 시 인라인 안내·첫 칸 focus, 채우면 안내 사라짐.

### 하지 않는 것 (범위 제외 — 건드리면 실패)

- **다른 단계**: 약관·계정(이메일/비밀번호 등)·이메일 확인·완료 등 학생 기본정보가 아닌 모든 가입 단계.
- **공부방·과외쌤 가입 화면/분기**: 같은 파일 안에 있는 공부방(`renderStudyRoomBasic`·`role === 'study_room'` 분기)·과외쌤(`renderTutorBasic`·`role === 'tutor'` 분기) 렌더와 제출 처리는 한 글자도 바꾸지 마라. 과외쌤 분기는 아래 3번처럼 "패턴 참고용"으로만 읽는다.
- **저장 API·검증 항목 자체**: 무엇이 필수인지는 바꾸지 마라(3번·5번). `studentBasicMissing`이 지금 필수로 보는 항목, 희망지역을 따로 검사하는 지금 규칙, 서버 저장(`basicRegisterApi`) 호출과 보내는 데이터, 저장 뒤 이동 경로를 바꾸지 마라.

## 3. 재검사 결과 (기준: `origin/main` `666393b6`, 파일 896줄)

실제 파일: `preview/auth-ui/src/screens/signup-basic.js` (896줄). 아래는 확인이 끝난 사실이다. 추측으로 넓히지 마라.

### 지금 학생 쪽 상태 (고칠 곳)

- 학생 '다음' 버튼 (L244 근처, `renderStudentBasic` 끝부분):
  ```html
  <button type="submit" class="btn btn--primary btn--block">다음</button>
  ```
  `disabled`가 없고, 입력이 바뀔 때 버튼 상태를 갱신하는 코드가 없다. 처음부터 눌러도 제출 처리가 돈다.
- 학생 칸에는 인라인 오류 자리(`data-field-error`)가 **없다**. 파일 전체에서 `data-field-error`는 과외쌤용 2곳(L313 `tutor_display_name`, L321 `main_subject`)뿐이다.
- 제출하면 `studentBasicMissing`(L92~108, 나머지 일곱 칸의 빈 항목 이름 목록)가 빈 항목을 모으고, 학생 분기 L679 근처에서 한꺼번에 띄운다:
  ```js
  alert(`기본정보를 모두 채워 주세요: ${missing.join(', ')}`);
  ```
- 학생 분기의 `alert`는 모두 9곳이다(희망 유형, 위 한꺼번에 표시, 희망지역 관련 등). 이 중 "사용자가 빠뜨린 칸"을 알리는 것들이 5번의 인라인 전환 대상이고, 시스템 오류성 알림은 5번에서 구분한다.

### 필수 항목의 기준 (바꾸지 마라 — 그대로 재사용)

- `STUDENT_BASIC_LABELS`(L79~89 근처)와 `studentBasicMissing`(L92~108)이 지금 정하는 항목이 기준이다: 표시명, 학교급·학년(미취학이면 학년 불필요), 희망 유형, 희망과목, 수업형태, 수업인원(단독과외면 자동으로 단독 처리되는 지금 규칙 포함), 예산(희망 유형에 따라 과외/공부방 예산 칸 중 보이는 쪽).
- 희망지역은 `studentBasicMissing` 밖에서 제출 전에 따로 검사하는 지금 구조를 유지한다(과외 희망이면 지역 선택, 공부방 희망이면 주소 검색 결과). 이 검사 자체·판정 조건은 바꾸지 말고, 표시 방식만 인라인으로 바꾼다(5번).
- 한 줄 요청문(`request_summary`)은 지금도 선택 칸이다. 절대 필수로 만들지 마라.

### 같은 파일 안 선례 (학생 분기에 맞게 참고하라고 있는 것 — 과외쌤 분기 자체는 고치지 마라)

- **인라인 오류 자리 + 제출 시 표시·focus**: 과외쌤 칸의 `<p class="form-note form-note--error" data-field-error="..." hidden></p>`(L313/321)와, 제출 처리에서 그 자리를 찾아 `hidden = false`·문구를 넣고 입력 칸에 `focus()`하는 방식(L754~774 근처). 학생 칸에도 같은 모양의 자리를 만들고 같은 방식으로 표시하되, 학생 칸 이름·문구에 맞게만 해라.
- **지역 슬롯 오류 표시**: `setTutorRegionSlotError`(L786 근처 호출, 정의는 공용 파일)처럼, 특정 칸 아래에 오류를 붙이고 지우는 전용 함수 방식. 단, 이 공용 함수·공용 파일을 학생용으로 억지로 바꾸지 마라. 학생 희망지역 표시는 학생 블록 안에서 해결하고, 공용 파일을 고쳐야 할 것 같으면 멈추고 보고해라(9번).
- 과외쌤 분기에서 이미 하는 "제출 전에 기존 오류를 한 번 지우고 다시 표시"하는 순서도 참고해라: 제출할 때마다 이전 인라인 안내를 먼저 지우고, 그때 빠진 칸만 다시 표시한다.

## 4. 손대도 되는 파일 (아래로 한정, 이 밖은 금지)

1. `preview/auth-ui/src/screens/signup-basic.js` — **중심 파일**. 학생 기본정보 렌더(`renderStudentBasic`)와 학생 제출 분기, 학생 전용 검사 연결만 고친다.

## 5. 작업 방법 (이 순서로)

1. 작업 시작 시점의 최신 `origin/main`을 받고, 거기서 브랜치 `cursor/253-student-signup-basic-20261018`을 만든다.
2. `signup-basic.js`에서 `renderStudentBasic`, `studentBasicMissing`, 학생 제출 분기를 직접 읽고 3번과 같은지 확인한다.
3. **인라인 안내 자리를 학생 필수 칸마다 만든다.** 과외쌤 선례와 같은 모양으로, 각 학생 `.student-basic__field` 안에 아래와 같은 자리를 칸 아래에 둔다(자리 이름은 학생 라벨 키와 맞춘다):
   ```html
   <p class="form-note form-note--error" data-field-error="public_display_name" hidden></p>
   ```
   - 대상 키: `public_display_name`(표시명), `grade_level`(학교급·학년 — 학교급/학년 칸을 함께 감싸는 그 칸), `preferred_lesson_type`(희망 유형), `preferred_region`(희망지역 — 과외 블록과 공부방 블록 각각에 두되, 보이는 쪽만 표시), `subject`(희망과목, 입력 id는 `subject_names`), `lesson_format`(수업형태), `preferred_student_count_group`(수업인원), `budget`(예산 — 과외 예산 칸과 공부방 예산 칸 각각에 두되, 보이는 쪽만 표시).
   - 안내는 `hidden`으로 시작한다. 자리만으로 레이아웃이 흔들리지 않게 기존 과외쌤 안내와 같은 클래스를 쓴다.
4. **빠진 칸을 키로 알 수 있게 한다.** 지금 `studentBasicMissing`은 이름(라벨) 목록을 돌려준다. 표시·focus에는 어느 칸인지(키)가 필요하다.
   - 검증 항목·판정 조건은 한 글자도 바꾸지 말고, 같은 판정을 키 목록으로도 얻을 수 있게만 정리해라(예: 키를 돌려주는 내부 함수를 두고 기존 함수는 그것을 라벨로 바꾸어 지금과 같은 결과를 내게 하기). 기존 호출 결과가 달라지면 안 된다.
   - 희망지역은 지금처럼 따로 검사하되, 빠졌다고 판정되면 `preferred_region` 자리에 표시할 수 있게 연결만 해라. 판정 조건(행정동/단지, 시·군 선택 등)과 문구의 뜻은 바꾸지 마라.
5. **'다음' 버튼 실시간 상태 갱신 함수를 만든다** (학생 폼 안에서만 동작):
   - 현재 폼 값으로 빠진 칸이 하나라도 있으면(희망지역 포함, 지금 판정 기준) '다음' 버튼에 `disabled`를 켜고, 전부 채워졌으면 끈다.
   - 처음 화면을 그릴 때(저장된 draft가 있으면 그 값 기준으로) 한 번 실행한다. 빈 상태로 시작하면 버튼은 처음부터 비활성이어야 한다.
   - 학생 폼의 모든 입력·선택·칩(라디오)에 `input`/`change`가 일어날 때마다 다시 실행한다. 희망 유형이 바뀌어 예산·지역 블록이 바뀌는 경우, 수업형태가 바뀌어 수업인원이 자동으로 단독이 되는 경우도 같은 갱신에서 반영해라(기존 `syncStudentHopeBlocks`·`syncLessonCountLock`와 충돌하지 않게 연결하고, 그 함수들의 기존 동작은 바꾸지 마라).
   - 버튼을 비활성으로 만들 때 폼 제출 자체를 막는 다른 장치(예: `required` 브라우저 검사)를 새로 붙여 동작이 이중으로 걸리게 하지 마라. 지금 제출 흐름을 유지하고, 버튼 상태는 위 함수가 책임진다.
6. **채우면 안내가 사라지게 한다.** 값이 바뀌어 다시 검사했을 때, 이제 채워진 칸의 인라인 안내는 숨기고 문구를 비운다. 아직 빈 칸의 안내는 그대로 둔다. 제출 전(아직 제출을 시도하지 않은 상태)에는, 버튼 비활성만으로 충분하고 빈 칸마다 안내를 미리 띄우지 마라 — 안내는 제출 시도 시점에 띄우는 것이 기본이다. 단, 한 번 제출을 시도해서 안내가 뜬 뒤에는, 고친 칸부터 바로 사라져야 한다.
7. **제출 시 학생 분기를 인라인으로 바꾼다.**
   - 제출이 들어오면 학생 필수 칸의 기존 인라인 안내를 먼저 모두 지운다(과외쌤 선례와 같은 순서).
   - 빠진 칸이 있으면: 각 빠진 칸 아래 인라인 안내를 표시하고(문구는 6번), **첫 번째 빠진 칸**(화면에 보이는 순서 기준)으로 `focus()`를 옮긴 뒤 `return`한다. `alert`로 한꺼번에 띄우지 마라.
     - focus 대상: 그 칸에서 실제로 입력하는 요소(표시명 input, 학교급 select, 희망 유형 첫 라디오, 희망지역의 첫 선택/검색 요소, 희망과목 select, 수업형태·수업인원 첫 라디오, 예산 input 중 보이는 쪽). 숨겨진 블록(희망 유형과 맞지 않는 지역·예산 블록)에는 표시도 focus도 하지 마라.
   - 학생 분기에서 "빠진 칸" 알림에 쓰던 `alert`들 — 희망 유형 선택, `studentBasicMissing` 한꺼번에 표시, 희망지역 선택 관련 — 은 위 인라인 표시로 대체한다. 예산 `invalid` 이벤트에서 띄우던 예산 `alert`(L625~630 근처)도, 같은 뜻이면 예산 칸 인라인 안내로 대체해라.
   - **그대로 두는 알림**: 계정 역할을 확인 중/확인 불가, 지역 목록 자체를 불러오지 못한 경우(`TUTOR_UNIT_LIST_ERROR` 같은 시스템 오류), 저장 API 실패 알림은 "빠진 칸"이 아니므로 지금 방식을 유지한다. 헷갈리면 임의로 바꾸지 말고 보고에 적어라.
   - 전부 채워진 정상 제출은 지금과 같은 데이터로 `basicRegisterApi`를 부르고, 같은 다음 화면으로 이동한다. 저장 중 버튼을 잠그고 풀던 기존 처리(`저장 중…` 등)도 그대로 둔다.
8. 고친 파일만 하나씩 이름으로 지정해서 add하고, 커밋 메시지 앞머리를 `253`으로 시작해서 커밋한다.
   - 예: `253 fix(signup): 학생 기본정보 다음 버튼·칸별 안내 개선`
9. 브랜치를 push하고 **멈춘다**. main에 합치지 않는다.

### 인라인 안내 문구 (새로 지어내지 말고 아래 뜻으로)

- 각 칸 안내는 그 칸이 비었다는 뜻이 한눈에 보이는 짧은 문장으로 한다. 기존 학생 제출 문구와 서버 라벨 뜻을 유지한다.
  - 예: 표시명 `표시명을 입력해 주세요.`, 희망과목 `희망과목을 선택해 주세요.`, 예산 `예산을 입력해 주세요.`
- 희망지역은 지금 제출 검사가 쓰는 문구의 뜻을 그대로 칸 아래에 옮긴다(예: `희망지역을 선택해 주세요.`, 시·군을 더 골라야 하는 경우는 그 뜻). 문구를 더 짧게 줄이거나 새 말을 만들지 마라.
- 한 칸에 안내가 여러 개 겹치지 않게, 한 칸에는 가장 먼저 걸린 안내 하나만 표시한다.

## 6. 금지 사항

- **다른 단계·공부방·과외쌤 변경 금지**: 약관·계정·완료 등 다른 단계, 공부방·과외쌤 렌더와 제출 분기는 바꾸지 마라.
- **검증 항목 변경 금지**: 무엇이 필수인지, 미취학이면 학년을 보지 않는 규칙, 단독과외면 수업인원이 자동으로 단독이 되는 규칙, 희망 유형에 따라 예산·지역 칸이 갈리는 규칙을 바꾸지 마라. 한 줄 요청문을 필수로 만들지 마라.
- **저장 방식 변경 금지**: 저장 API, 보내는 데이터의 이름·형태, 저장 뒤 이동 경로를 바꾸지 마라.
- **공용 파일 변경 금지**: `preview/shared/*`(지역 슬롯·희망지역·학교급 공용 파일 포함)를 학생용으로 바꾸지 마라. 필요하면 멈추고 보고해라(9번).
- **정상 흐름 변경 금지**: 다 채운 정상 입력에서 버튼·저장·이동이 지금과 달라지면 안 된다. draft로 미리 채워진 상태에서도 버튼이 올바르게 활성화되어야 한다.
- **일괄 치환 금지**: 파일 전체·저장소 전체 찾기·바꾸기로 `alert`를 한 번에 바꾸지 마라. 학생 분기인지 하나씩 확인하고 고쳐라.
- **main 병합 금지**: main에 합치지 마라. 브랜치에 커밋하고 push한 뒤 멈춘다.
- **force-push(강제 밀어넣기) 금지**
- **`git add -A` 금지**: 고친 파일만 하나씩 이름으로 지정해서 담아라.

## 7. 확인 방법

아래를 모두 확인하고 보고해라. 학생 기본정보 화면을 실제로 띄워서 확인하는 것을 기본으로 하고, 화면을 띄울 수 없으면 그 이유와 대신 한 확인을 그대로 적어라.

### 필수 확인 (하나라도 빠지면 완료가 아니다)

1. **빈 상태 버튼 비활성**: 학생 기본정보를 빈 상태(또는 필수 칸이 남은 상태)로 열면 '다음' 버튼이 처음부터 비활성인지 확인한다.
2. **하나씩 채우면 안내 사라짐 + 버튼 갱신**: 제출을 시도해 인라인 안내가 뜬 뒤(또는 안내가 떠 있는 상태에서), 칸을 하나씩 채울 때마다 그 칸 안내만 사라지고, 마지막 필수 칸을 채우는 순간 '다음' 버튼이 활성화되는지 확인한다. 희망 유형을 바꾸면 그에 맞는 지역·예산 칸 기준으로 다시 계산되는지도 확인한다.
3. **제출 시 인라인 + focus**: 빠진 칸이 있는 상태로 제출하면(버튼이 비활성이라 누를 수 없으면, 제출 시도 경로를 어떻게 재현했는지 적고), `alert`가 뜨지 않고 빠진 칸마다 아래에 안내가 표시되며, 첫 번째 빠진 칸으로 focus가 이동했는지 확인한다. 빠진 칸이 2개 이상일 때 첫 칸이 화면 순서상 첫 칸인지 확인한다.
4. **정상 입력 시 기존과 동일하게 저장·이동**: 필수 칸을 전부 채우면 버튼이 활성화되고, 제출하면 지금과 같은 저장 API 호출이 같은 데이터로 나가고 같은 다음 화면으로 이동하는지 확인한다. 저장 중 버튼 잠금·해제도 지금과 같은지 확인한다.

### 회귀 확인

5. **공부방·과외쌤 무변경**: `git diff`로 공부방·과외쌤 렌더/분기, 다른 단계 파일이 바뀌지 않았는지 확인한다.
6. **선택 칸 무영향**: 한 줄 요청문을 비워도 버튼·제출이 막히지 않는지 확인한다.
7. **미리 채워진 draft**: 저장된 값이 있어 처음부터 다 채워진 상태로 열리면 버튼이 활성화되어 있고 안내가 떠 있지 않은지 확인한다.

## 8. 완료 기준

- 빈 상태에서는 '다음' 버튼이 비활성이고, 입력할 때마다 상태가 바로 갱신된다.
- 제출 시 빠진 칸은 `alert` 한꺼번이 아니라 칸 아래 인라인으로 표시되고, 첫 빠진 칸으로 focus가 간다. 채운 칸의 안내는 바로 사라진다.
