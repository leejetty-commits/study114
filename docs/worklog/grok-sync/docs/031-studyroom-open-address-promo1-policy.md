## 0. 한 줄

공부방 **개설주소가 홍보지역1(대표)의 기본 정본**이다. 자동으로 채우되 **잠그지 않는다.** 수업 장소(개설)와 홍보 대표는 역할이 다르다.

---

## 1. 배경 · 피로도

가입 시 주소성 입력이 많다.

1. 본인주소  
2. 공부방 개설주소  
3. 홍보지역1(대표)  
4. 홍보지역2 (선택)  
5. 홍보지역3 (선택)

홍보 2·3은 이미 선택. 개설과 홍보1을 중복 입력하는 것이 특히 피곤하다.

---

## 2. 역할별 지역 축 (기존 잠금과 일치)

| 역할 | 지역 축 |
|------|---------|
| 과외쌤 | **시·군** |
| 공부방 | **행정동** + **아파트단지** (두 축). 개설주소는 상세 주소로 받고, 홍보·매칭 단위만 동/단지 선택 |

본 문서는 **공부방**만. 과외쌤 시·군(030)과 섞지 않는다.

---

## 3. 합의 규칙

### 3-1. 개설주소 = 수업 장소 정본

- 수업은 개설주소에서 이뤄져야 한다는 운영 전제(불법 회피).
- 개설주소는 **수업 장소 SSOT**. 홍보1을 바꿔도 개설주소는 바뀌지 않는다.

### 3-2. 홍보지역1 = 개설에서 자동 채움 (기본값)

- 개설주소를 입력·확정하면 홍보지역1(대표)에 **자동으로 채운다.**
- 행정동 vs 아파트단지는 **주소를 다시 받는 선택이 아니라**, 같은 개설주소를 **홍보·찾기에 어떤 단위로 쓸지** 고르는 선택이다.
  - 기본 후보: 행정동(주소에서 도출).
  - 단지 DB 매칭 가능 시: 아파트단지도 선택 가능.
- 결과 = 홍보1 + `region_basis`(dong | complex).

### 3-3. 홍보1은 수정 가능 (잠금 아님)

- 자동 채움은 편의. 대표 홍보만 다른 권역으로 쓰고 싶으면 **자의로 수정**한다.
- 예: 개설 = 개봉아파트 **1**단지, 홍보 대표 = 개봉아파트 **2**단지.
- 개설 ≠ 홍보1이면 안내 카피 예:  
  「수업은 개설주소에서만 진행됩니다. 지금 바꾼 건 홍보·찾기 대표 지역입니다.」

### 3-4. 본인주소 · 홍보2·3

- 본인주소: 운영자 거주지. **개설·홍보1과 별도.**
- 홍보2·3: 추가 권역. **선택 유지.**

### 3-5. 넣지 않은 것 (나중에 조여도 됨)

- 개설과 다른 홍보1을 **같은 행정동 안으로만** 제한할지: 미정. 1차 구현은 경고만, 강제 범위는 후속.
- 노션 본문 동기화: 사용자가 「노션에 남겨」라고 할 때만.

---

## 4. 입력 UX 목표 (구현 시)

이상적 흐름:

1. 본인주소 (필요 시)  
2. 개설주소 (상세 1회)  
3. 홍보 단위(동/단지) 선택 → **홍보1 자동 채움** · 필요 시 수정  
4. 홍보2·3 선택

개설과 홍보1을 **처음부터 두 번 고르게** 하지 않는다.
