### 작업 2. 배너 3칸 바탕에 사진 + 왼쪽 흰 막 적용

- 대상은 홈 상단 3칸(`.home-promo-trio__card`)뿐이다. 다른 배너(시네마형 `.home-mkt` 등)는 건드리지 마라.
- 목업(`mock-sharp.html`의 선명 A 행) 기준으로 아래를 맞춘다.
  1. **사진 배치:** 각 칸 바탕에 자기 칸 사진을 깐다. `background-size: cover`, `background-position: right center`(사진은 오른쪽 기준). 칸별 대응은 작업 1 표를 따른다.
  2. **왼쪽 흰 막:** 사진 위에 왼쪽이 진하고 오른쪽이 옅은 흰색 그라데이션을 덮는다. 목업 선명 A 값: `linear-gradient(90deg, rgba(255,255,255,.96) 0%, rgba(255,255,255,.88) 42%, rgba(255,255,255,.15) 100%)`. 왼쪽 글자 쪽은 진하게(96%→88%) 유지해 글자가 읽히게 하고, 오른쪽 끝은 15%로 옅게 해 사진이 보이게 한다. 이 값을 기준으로 하되, 실제 화면에서 글자가 안 읽히면 임의로 사진 자체를 바꾸지 말고 중단 보고해라(7장).
  3. **글자 가독성 유지:** 작은 제목·제목·설명의 색·크기·굵기는 지금 그대로 둔다. 글자가 흰 막·사진보다 위에 보여야 한다(목업처럼 글자 요소가 막보다 앞). 왼쪽 색 띠(4px)도 사진·막보다 앞에 지금처럼 보여야 한다.
  4. **사진을 못 불러와도 깨지지 않게:** 바탕색 `#f6f1e8`을 fallback으로 유지한다. 사진을 못 불러오면 지금 단색 모습으로 보여야 한다.
  5. **모서리:** 사진·막이 카드 모서리(12px) 밖으로 삐져나오지 않게 한다. 목업처럼 카드에서 넘침을 잘라야 하면 `.home-promo-trio__card` 범위 안에서만 처리해라.
  6. **hover(마우스 올림):** 지금 hover는 바탕색을 칸별 색으로 바꾼다. 사진을 깐 뒤에도 hover 때문에 사진이 단색으로 덮여 사라지면 안 된다. 테두리 색·제목 색이 바뀌는 기존 hover 취지는 유지하되, 바탕 처리는 사진·흰 막·글자 읽힘이 유지되는 범위에서만 조정해라.
  7. **불러오기:** 장식용 CSS 배경으로 넣는 것을 기본으로 한다. `fetchpriority=high`를 쓰지 마라. 사진을 `<img>`로 바꿔야 할 것 같으면 임의로 바꾸지 말고 중단 보고해라(7장).
- 구현 방식은 허용 파일(4장) 안에서 최소로 골라라. 칸별 클래스(`--study`에 해당하는 기본 카드·`--tutor`·`--parent`)만으로 CSS에서 사진을 나누어 깔 수 있으면 `home-marketing-banner.css`만 고치는 것을 우선한다. JS를 고쳐야 하면 `HOME_PROMO_TRIO`에 사진 경로를 더하는 최소 변경만 하고, 문구·링크 값은 한 글자도 바꾸지 마라.

1. **기존 배너 문구 변경 금지.** `HOME_PROMO_TRIO`의 세 칸 문구를 그대로 둔다.
   - 공부방: 작은 제목 `공부방 카탈로그` / 제목 `내가 찾는 공부방` / 설명 `가까운 곳부터 비교하고, 등록은 가볍게 시작하세요`

4. **왼쪽 색 띠·글자 색 변경 금지.** 띠 색(공부방 `#266bc4` / 과외쌤 `#0f766e` / 학생 `#c2410c`)과 글자 색을 바꾸지 마라.
5. **보이는 범위 변경 금지.** 3칸이 보이는 홈 종류(`guest`·`parent`·`study_room`·`tutor`)와 숨김 규칙을 바꾸지 마라. 자기 칸을 숨기는 등의 동작을 더하지 마라.

## 5. 작업 순서

1. 작업 시작 시점의 최신 `origin/main`을 받고, 거기서 브랜치 `cursor/258-catalog-banner-photo-20261019`를 만든다. 기준 코드와 줄·문장·클래스가 다르면 파일 안에서 같은 대상을 찾고, 내용이 크게 다르면 멈추고 보고해라.
2. 작업 1: 사진 3장을 3장 표의 경로에 바이트 그대로 복사하고, 크기·SHA-256을 대조한다. 라이선스 재확인 상태를 먼저 확인해라(2장 주의). 재확인이 안 됐으면 로컬 확인까지만 진행하고, 원격 push 전에 멈춰 보고해라.
3. 작업 2: 허용 파일 안에서 사진+흰 막을 적용한다. CSS만으로 되면 JS는 건드리지 마라.
4. 변경 금지 확인: `git diff`로 문구·링크·크기 관련 값이 바뀌지 않았는지 확인한다. 바뀌었으면 되돌려라.
5. 커밋은 **가능하면 성격별로 나눠라.** 한 브랜치 `cursor/258-catalog-banner-photo-20261019` 안에서 아래처럼 나누는 것을 기본으로 한다. 나누기 어렵면 합치되, 그 이유를 보고에 적어라. (사진 파일 커밋은 라이선스 재확인 + 종현 확인이 끝난 뒤에만 한다.)
   - 예: `258 feat(home): 홈 카탈로그 배너 3칸에 후보 A 선명 사진과 왼쪽 흰 막을 적용한다`
   - 예(사진을 따로 담을 때): `258 assets(home): 카탈로그 배너 사진 3장을 banners 자산에 더한다`
   - `git add`는 고친 파일만 하나씩 이름으로 지정해서 담아라. **`git add -A` 금지.**
6. 브랜치를 push하고 **멈춘다.** main에 합치지 않는다. (라이선스 미확인 상태에서는 사진 파일을 push에 포함하지 마라. 2장 주의 참고.)
7. 이후 순서는 고정이다: **브랜치 push 후 멈춤 → 검수 → 종현 승인 → main 병합.** 승인 전에 main에 병합하거나 배포하지 마라.

## 6. 확인 방법

아래를 모두 확인하고 보고해라. 하나라도 빠지면 완료가 아니다.

### 사진 파일 확인

1. 복사한 3장의 파일 크기·SHA-256이 2장 표와 같은지 확인한다(재인코딩했으면 완료가 아니다). 합계 55,420 bytes(약 54.1KB), 한 장이 80KB를 넘지 않는지도 함께 적어라.
2. 코드가 참조하는 경로(`/assets/banners/catalog-study.webp` 등)와 실제 파일 위치가 맞는지 확인한다. 참조 경로 오타로 사진이 안 뜨면 완료가 아니다.

### 화면 확인 — 사진·글자·크기

3. 홈 상단 3칸을 열고, 세 칸 모두에 각 칸 사진이 보이는지 확인한다: 공부방 칸=공부방 사진, 과외쌤 칸=과외쌤 사진, 학생 칸=학생 사진. 칸과 사진이 섞였으면 완료가 아니다.
4. 글자가 읽히는지 확인한다: 세 칸 모두 작은 제목·제목·설명이 사진 위에서도 지금처럼 읽혀야 한다. 왼쪽 흰 막이 왼쪽은 진하고 오른쪽으로 갈수록 옅어져 사진이 오른쪽에서 보이는지, 왼쪽 색 띠가 사진·막에 묻히지 않는지 함께 본다.
5. 문구·링크·크기가 그대로인지 확인한다: 세 칸 문구가 3장 변경 금지 1과 한 글자까지 같은지, 눌렀을 때 가는 곳이 전과 같은지(`/promo/study-room`·`/promo/tutor`·`/promo/parent`), 칸 크기·간격·모서리가 전과 같은지(높이를 고정하지 않았는지 포함) `git diff`와 화면으로 대조한다.
6. 마우스를 올렸을 때(hover) 사진이 단색으로 덮여 사라지지 않고, 테두리·제목 색 변화 등 기존 hover 취지가 유지되는지 확인한다.
7. 사진을 일부러 못 불러오게 한 상태(경로를 잠시 틀거나 네트워크에서 막는 등, 확인 후 원복)에서도 바탕색 `#f6f1e8` 단색 모습으로 깨지지 않게 보이는지 확인한다.

### 모바일 확인

8. 좁은 화면(폭 390px 기준, 720px 이하)에서 3칸이 1칸씩 세로로 쌓이고, 각 칸 사진·흰 막·글자가 깨지지 않는지 확인한다. 사진이 글자를 가리거나, 칸이 옆으로 넘치거나, 모서리 밖으로 사진이 삐져나오면 완료가 아니다. 목업 비교 기준은 `sharp-mobile-390.png`다.

### 공통 확인

9. `git diff --stat` 기준으로 고친 파일이 4장 허용 파일 안에만 있는지 확인한다. 허용 파일 밖 변경이 0이어야 한다. JS를 건드리지 않았으면 그 사실도 보고에 적어라.
10. 라이선스 재확인 결과를 보고에 적어라: 재확인을 어디서·어떻게 했는지, 사진 파일을 원격에 올려도 된다는 종현 확인을 받았는지. 아직이면 "미확인"으로 적고 사진 파일을 push에 넣지 않은 상태로 보고해라.

## 8. 금지 사항

- **허용 파일 밖 변경 금지** (4장). 특히 다른 배너·호출하는 쪽·라우팅·기존 자산은 건드리지 마라.

- **라이선스 미확인 상태로 사진 파일을 원격 push·배포하는 것 금지** (2장 주의). 확인 전까지 올릴지는 종현 확인을 받아라.

- **main 병합 금지.** 브랜치에 커밋하고 push한 뒤 멈춘다. 검수 → 종현 승인 → main 병합 순서를 지켜라 (5장 7번).
- **force-push(강제 밀어넣기) 금지**
- **`git add -A` 금지.** 고친 파일만 하나씩 이름으로 지정해서 담아라.
