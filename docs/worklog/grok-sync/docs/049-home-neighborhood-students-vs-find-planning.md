# 049 · 기획 — 홈 「우리동네 학생」≠ 메뉴 「학생찾기」

- 작성일: 2026-09-24 (KST)
- 목적: 페이지 구성·카피·알고리즘 차등 기획 (Cursor 구현 전 SSOT)
- 상태: **기획 확정** → Cursor 티켓 [050](050-home-neighborhood-students-find-ticket.md)
- 관련: 044 홍보1 전역 · 046 홈 상세검색 제거(공부방 찾기 쪽) · 학생찾기 필터는 기존 정본 유지
- 이번 **제외**: 스크린샷 속 데이터/카피 오류·더미 카드(대치동 등) — 별도 거론

## 0. 한 줄 결정

| 화면 | 역할 |
|------|------|
| **메뉴 · 학생찾기** | 기본은 홍보1 동네 목록 · **검색 클릭 시** 필터 결과로 재로드 (상세검색 SSOT) |
| **홈 · 우리동네 학생 탭** | 로그인 제공자의 **홍보지역1 동네 학생 수요 스냅샷** (구성·기본 알고리즘만 다름) |

공유: 학생 카드 UI · 쪽지준비 · 상세 · Search API(파라미터만 다름).

### 하단 학생 리스트 (2026-09-24 확정 방향)
- **같이**: 카드 컴포넌트·찜/쪽지준비/상세·정렬 UI(기본 최신순).
- **다르게**: 홈=홍보1+역할 자동 피드 결과 / 찾기=상세검색 파라미터 결과. 한 쿼리·한 결과셋을 두 화면에 공유하지 않음.
- 목록 헤더·빈상태 카피는 화면별로 분리(홈은 §3).
  
**같은 기본값·같은 상세검색 노출로 두면 안 됨.**

## 1-A. 학생찾기 — 기본 위치·목록 (2026-09-24 추가 잠금)

메뉴 **학생찾기**도 “빈 서울시”로 시작하지 않는다.

1. **로그인 제공자** 진입 시  
   - 희망지역/현재위치/탐색 지역 **기본값 = 홍보1** (홈과 동일 SSOT).  
   - 하단 리스트 = **검색 버튼 전**에도 그 동네 학생 자동 로드 (홈 스냅샷과 **같은 동네 기준**일 수 있음).  
2. **검색 클릭 후**  
   - 상세검색 필드(유형·과목·학년·예산·장소·인원·한 줄 요청문 등)로 **필터링된 결과만** 다시 로드.  
   - 지역을 사용자가 바꾸면 그 지역 기준으로 검색.  
3. **초기화**  
   - 필터는 비우되, 지역 기본은 다시 **홍보1**로 되돌리는 것을 권장(게스트는 기존 데모 지역).  
4. **게스트**  
   - 기존 데모(대치/서울시 등) 유지. 이번 잠금은 로그인 제공자.

### 홈 탭과의 차이 (갱신)

| | 홈 · 우리동네 학생 | 학생찾기 |
|--|--|--|
| 기본 지역 | 홍보1 | **홍보1** (동일) |
| 기본 목록 | 홍보1 동네 학생 | **홍보1 동네 학생** (동일 기준 가능) |
| 상세검색 | **없음** | **있음** |
| 목록이 바뀌는 시점 | 탭 진입·홍보1 변경 시 | 진입 시 자동 + **검색 클릭 시 필터 적용** |
| 지역 변경 | 불가(읽기전용) | 가능(주소찾기·희망지역) |

즉 차별점은 “첫 동네 결과”가 아니라 **필터로 넓히고 조일 수 있는지**다. 카드 UI는 공유, 쿼리는 찾기에서 검색 후에만 파라미터 확장.

## 2. 알고리즘 (홈 · 우리동네 학생만)

### 2-1. 잠금 규칙

1. **지역 SSOT = 홍보1** (`saved_regions` is_primary / promo1).  
   개설주소·hub `region_label`·게스트 대치동·MOCK 폴백 **금지** (044와 동일 함정).
2. **자동 실행**: 탭 진입 시 검색 버튼 없이 **즉시** 홍보1 기준 학생 목록 로드.
3. **역할 정합** (제공자 로그인):
   - 공부방 로그인 → 희망 유형 기본 = **공부방** (학생이 공부방을 희망한 건 우선; API 필드명 기존 student find 스키마 따름).
   - 과외쌤 로그인 → 희망 유형 기본 = **과외쌤**.
   - 사용자가 홈에서 유형을 바꾸게 하지 않음 (바꾸려면 학생찾기).
4. **필터**: 홈에서는 추가 필터 없음. (학년·과목·예산 등은 학생찾기 전용)
5. **「한 줄 요청문 있음」**: 홈 기본값 = **끄지 않음**(전체). 찾기의 체크는 찾기만.
6. **페이지네이션**: 기존 학생 목록과 동일. 홈 맵박스(046)와 숫자 동기 이슈 없음(학생 탭).
7. **프라임/픽/베이직 티어**: 홈 학생 탭에는 **유료 노출 티어 UI 없음** (학생 수요 목록만). 공부방 탭의 프라임구조와 섞지 말 것.
8. API: 기존 학생 검색 엔드포인트 재사용. 홈은 서버/클라에  
   `region = 홍보1`, `desired_type = 내 역할`, `mode = neighborhood_home` (또는 동등 플래그) 만 고정 전달.

### 2-2. 학생찾기와의 차이 (한 줄)

- 찾기 = 사용자 입력 파라미터의 결과.  
- 홈 = **파라미터를 시스템이 채운** 동네 피드.

## 3. 카피·구성 (홈 · 우리동네 학생)

### 3-1. 탭

- 좌: `우리동네 공부방` (기존)
- 우: `우리동네 학생` (기존 라벨 유지)

### 3-2. 섹션 헤더 (상세검색 자리 대체)

상세검색 박스 **삭제** 후, 그 자리에 짧은 요약 블록:

| 요소 | 카피 (잠금안) |
|------|----------------|
| eyebrow | `우리동네 학생 수요` |
| 제목 | `{홍보1짧은라벨} 학생` 예: `논현1동 학생` / `가능동 학생` (동 단위 우선; 시만 있으면 `부산 학생`) |
| 보조 문장 | `{홍보1표시}에서 지금 공개 중인 학생 요청입니다. 조건을 바꿔 넓게 보려면 학생찾기에서 검색하세요.` |
| 지역 칩(읽기전용) | `탐색 지역  {홍보1표시}` — 클릭·주소찾기 **없음** |
| 목록 상단 | `우동공과 학생` 유지 가능 · 우측 `현재위치  {홍보1표시}` |
| CTA 버튼 | `학생찾기에서 더 찾아보기` → `#/…학생찾기` 기존 라우트 (정확 해시 구현 시 확인) |

### 3-3. 빈 목록

- 제목: `이 동네에 아직 공개된 학생 요청이 없습니다`
- 본문: `홍보지역을 바꾸었거나, 아직 요청이 없을 수 있습니다. 학생찾기에서 다른 지역·조건으로 찾아보세요.`
- 버튼: `학생찾기로 이동`

### 3-4. 로딩

- `우리동네 학생 요청을 불러오는 중`

### 3-5. 쓰지 말 카피 (홈)

- `상세검색` / `검색` / `초기화` (홈 학생 탭)
- `희망 지역` 편집 유도
- 게스트용 `대치동` 데모 문장 (로그인 홈)
