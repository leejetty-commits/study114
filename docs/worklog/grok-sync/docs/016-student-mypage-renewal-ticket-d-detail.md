## 3. 필드 잠금 (노션 §3-2)

상세정보에서 **받고·저장하는** 값만 아래 9종이다.  
표시명(라벨)은 노션 표기를 쓰고, API 키는 기존 store/PHP 키를 쓴다.

| # | 화면 표시명 (잠금) | API / form name (잠금) | 비고 |
|---|-------------------|------------------------|------|
| 1 | 희망지역 추가값 | `preferred_region_note` | **추가 텍스트만.** 기본정보의 희망지역 본지역 select/단지 UI를 상세에 복제하지 말 것 |
| 2 | 희망 수업장소 | `lesson_places` | 기존 체크 그룹. 빈 배열 허용 |
| 3 | 주 횟수 | `lessons_per_week` | 숫자 |
| 4 | 1회 시간 | `minutes_per_lesson` | 숫자(분) |
| 5 | 희망 강의스타일 | `teaching_style_badges` | 기존 체크 그룹. 빈 배열 허용 |
| 6 | 희망 과외쌤 성별 | `preferred_tutor_gender` | `female` / `male` / `any` (기존 enum) |
| 7 | 학생 성별 | `gender` | `female` / `male` (기존 enum) |
| 8 | 출생연도 | `birth_year` | 숫자 연도 |
| 9 | 특이요청사항 | `special_request_note` | **상세 책임.** 카드 필수가 아님. 마이프로필 **상세 섹션**과 일치 |

### 3-1. 원칙 (어기면 거부)

1. 위 9종 **밖** 필드를 상세 폼에 끌어오지 말 것. (`request_summary`, `public_display_name`, `preferred_fee_*`, `subject_label`, `preferred_lesson_type`, `preferred_tutor_region_id` 등)
2. 같은 의미 값 **이중 저장** 금지 (노션 §3-3).
3. 「대표 희망*」「대표 *」라벨 금지 (노션 §6).
4. **필수** 마킹·HTML `required`로 공개 게이트처럼 막는 것 금지. 공란은 시각 구분만 (색/톤/옅은 배경).
5. 「아직 부족 n개」「공개 전 완료 필요」「자녀 정보 보완」 카피·체크리스트 **상세 화면에서 제거 또는 비표시.**
6. 이미 상세에 잘못 섞인 **기본정보 전용 UI**(예: `data-p19-hope-dual`로 본지역을 다시 받는 UI)가 있으면 **본지역 UI는 숨기거나 제거**하고, `preferred_region_note`만 남긴다. 기본정보 폼으로 코드를 “옮겨 담는” 대수술 금지. 애매하면 **중단·보고.**

### 3-2. 상단 안내 (노션 §5-2) — 문구 고정

상세정보 상단 lead는 **아래 한 줄만** 쓴다. 임의 의역·추가 문단 금지.

> 입력데이터가 맞을수록 더 적합한 과외쌤, 공부방을 만날 수 있습니다.

제목은 「상세정보」/학생 상세정보 계열 유지. 「자녀 상세」「공개 준비」 등으로 바꾸지 말 것.

## 4. 저장·API

1. **기존만:** `PATCH /api/registrations/students.php` + `action: update` (또는 이 프로젝트에서 이미 쓰는 동일 student update 경로).  
   **새** PHP 파일·새 action·새 URL **금지.**
2. payload에 §3 표의 키가 **실려야** 한다. 특히 `special_request_note`, `lesson_places`, `teaching_style_badges`.
3. PHP allowlist에 이미 있으면 **건드리지 말 것.** 거절(`InvalidArgument` 등)되면 **중단·보고** 후, 승인 하에 allowlist/검증만 최소 수정.  
   **임의로 다른 컬럼에 쑤셔 넣기 금지.** 스키마 ALTER 금지.
4. 권한: 본인 학생(id=1)만. 타인 id 쓰기·구멍 보이면 중단·보고.
5. 저장 성공 후:
   - 같은 detail 폼 재조회 값이 일치하거나
   - 마이프로필 리스트 **상세 섹션** (`profile-read` detail rows)의 특이요청·장소·횟수 등이 바뀐 값과 일치  
   → 보고에 **저장 전 / 저장 후** 표를 적을 것.
6. visibility 라디오(`special_request_visibility` 등)를 D에서 **새로 추가하지 말 것.** 기존에 폼에 박혀 공개 게이트처럼 보이면 **숨김/제거**하고 보고. (공개 게이트 폐기 정본)

## 6. 현재 코드 메모 (출발점 — Cursor가 “이미 있다”고 끝내지 말 것)

관찰 기준 로컬 트리 (C 직후):

- `renderDetailForm`에 §3 필드 골격은 **이미 있음.** D는 “필드 창작”이 아니라 **정본 잠금·카피·게이트 제거·저장·마이프로필 일치 검증**이다.
- `getStepDone(..., 'detail')`가 `dualHopeRegionsReady` + `preferred_tutor_gender`로 **완료 게이트**를 잡고 있으면, 상세 UI에서 그 문법이 보이면 **걷어낼 것.** (함수를 E까지 미루고 싶으면 **상세 화면에서만이라도** 스테퍼/부족 UI가 안 보이게)
- detail submit 경로에 `data-p19-hope-dual` 분기가 있으면, 상세에 본지역 dual UI가 **없어야** 한다. 있으면 제거·보고.
- PHP allowlist에 `special_request_note` 등 상세 키는 **이미 포함**된 상태일 수 있다. 있으면 PHP 미수정이 정상.
- `screens.js` 다른 구역(basic, hub, publish, not-found「자녀」)은 **D에서 건드리지 말 것** (회귀·범위 이탈). 단, detail 전용 공유 헬퍼를 고칠 때 basic이 깨지면 즉시 중단·보고.

## 7. 완료 전 필수 점검 (보고에 경로·요청·결과 적기)

### 7-1. 라우팅 (학생 세션, id=1)

1. `#/mypage` → 마이프로필 유지.
2. `#/mypage/registrations/students/1/detail` 진입·**새로고침 유지.**
3. 상단 탭: 마이프로필 / 기본정보 / 상세정보 / 쪽지설정 전환 정상.
4. 마이프로필 → 「상세정보 수정」 → detail.
5. 상세에 **한 줄 요청문** 입력칸 **없음.**
6. 기본정보(`…/basic`) 9종·요청문 **회귀 없음.**
7. A 리다이렉트(`#/mypage` → myprofile 등) **회귀 없음.**

### 7-2. API

1. detail 로드: 기존 조회 200, §3 9종이 폼에 채워짐 (있는 값만).
2. 저장: 네트워크 payload에 최소 `special_request_note` + (변경한) 장소/횟수 등 실림. 성공 코드.
3. **증거 표 (필수):**

| 시점 | API `special_request_note` (또는 대표 1~2필드) | 마이프로필 상세 섹션 표시 |
|------|-----------------------------------------------|---------------------------|
| 저장 전 | … | … |
| 저장 후 (검증 문구) | … | … |
| 원문 복구 후 | … | … |

4. 새 저장 엔드포인트 **없음.** PHP를 고쳤으면 파일·이유·스키마 미변경 자평.
5. 기본정보 저장·카드 한 줄 요청문 **깨지지 않음** (스모크 1회).

### 7-3. 카피·금지 문법 (상세 화면만)

상세 화면에 아래가 **보이면 실패:**

- 필수 / 아직 부족 / 공개 전 완료 / 대표 희망* / 자녀 추가·보완  
- 한 줄 요청문 입력  
- 기본정보 본지역 재입력 UI

상단 안내는 §3-2 고정 문장과 **일치.**

### 7-4. 예상외

중단·보고·승인 대기. 코드를 덧대어 막지 말 것.
