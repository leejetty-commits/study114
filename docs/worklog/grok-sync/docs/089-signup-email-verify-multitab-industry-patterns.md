# 089 · 조사 — 메일 확인·여러 탭, 다른 사이트는?

## 0. 한 줄

**메일 앱이 새 탭을 여는 것은 막지 못한다.**  
잘 만든 서비스는 “한 탭만 쓰게 강제”보다 **(A) 원래 탭이 확인을 감지해 이어가기** · **(B) 메일 안 짧은 인증번호** · **(C) 링크로 연 탭에서만 이어가기+안내**를 섞는다. **두 탭에서 둘 다 폼을 제출하게 두지는 않는다.**

---

## 1. 업계에서 자주 쓰는 패턴

| # | 패턴 | 요지 | 두 탭? | 비고 |
|---|------|------|--------|------|
| 1 | **원래 탭 폴링** | 대기 탭이 서버에 “확인됐나요?”를 짧게 물어보고, 되면 Basic으로 이동 | 새 탭은 열릴 수 있음 | Auth0 커뮤니티·검증 플로우 글에서 흔함. 포커스 있을 때만·간격 늘리기 |
| 2 | **탭 간 신호** | 확인 탭 → BroadcastChannel / localStorage → 대기 탭 이동 | 같음 | Chrome BroadcastChannel 문서. 같은 PC·같은 사이트만 |
| 3 | **메일 안 인증번호(OTP)** | 링크 대신(또는 함께) 코드를 원래 탭에 붙여 넣기 | **새 탭 없이도** 가능 | UX.SE 등. 링크는 “탭 닫았을 때”용 폴백 |
| 4 | **링크 탭에서만 이어가기** | 새 탭=본진, 대기 탭은 “닫아도 됨” 안내 | 두 탭 남음 | 지금 우동공과 073에 가까움 |
| 5 | **window.name으로 같은 탭** | 메일 링크 target을 이름으로 맞춤 | 이상적이나 | Gmail 등이 `target=_blank`로 바꿔 **거의 실패** |

공통: **한 번만 쓰이는 확인 토큰** · 확인 후 한쪽만 다음 단계 · 다른 쪽은 안내/잠금.

## 2. 우동공과에 맞는 후보 (결정 전)

1. **088안** — 대기 탭 잠금 + 신호/폴링으로 대기 탭만 Basic (메일 탭은 안내만)  
2. **OTP 병행** — 메일에 4~6자리 + 링크. 원래 탭에 코드 입력(이탈·두 탭 문제 가장 적음)  
3. **현상 유지** — 안내 카피만 (073)

추천 조사 결론: **2가 UX상 가장 흔하고 안전**하고, **1은 링크 습관을 유지한 채 보완**. 둘 다 가능하면 OTP+대기탭 감지가 이상적.
