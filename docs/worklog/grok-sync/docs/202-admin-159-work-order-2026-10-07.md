## 3. 보고서가 놓친 위험 (검수에서 추가 발견)

1. **잠긴 방식과 다른 제안(재그리기).** docs/190 t1478 절: 「저장 후 해당 칸만 재그리기」. 보고서 §2는 「저장 후 전체 `rerender()` + `a28Ui`로 열림 복원」을 기본으로 둠 → **잠긴 정책과 어긋남(보고서 제안 단계).** 허브 안에서는 해당 칸(펼침 영역/팝업 본문)만 다시 그리고 그 칸만 다시 바인딩해야 함.
2. **권한 게이트 우회.** `renderAdmin()`은 현재 경로(`/admin`)만 `canAccessAdminPath`로 검사(`admin/index.js:13-22`). 허브에 다른 화면을 끼워 넣으면 화면별 게이트를 안 거침 → 카드마다 `canAccessAdminPath(원래 경로)` 확인 필요(홈 팝업 = 부마스터 숨김).
3. **사이드바식 링크 바인딩.** `[data-a28-nav]` 클릭은 `bindAdminShellEvents`가 렌더 시점 root 전체에 한 번 붙임(`admin/shell.js:145-151`). 칸만 다시 그리면 새로 생긴 링크(회원 상세의 노출/결제 이동, 1354·1364·1400)는 **죽은 링크**가 됨 → 칸 재바인딩에 포함해야 함.
4. **해시 쓰기 3곳.** 노출 1513·1538·1543 (위 #8). 허브 모드에서는 셋 다 해시를 쓰면 안 됨.
5. **`bindA28ScreenEvents` 상단 공통 바인딩.** 함수 첫머리 `bindDetailDrawer(root)` 등 경로 무관 바인딩이 있음(517~). 칸마다 이 함수를 통째로 다시 부르면 공통 버튼에 **중복 바인딩** → 화면별 블록만 떼어 칸 root에 붙여야 함.
6. **패널 중첩·미리보기 안내.** 대상 화면들은 `renderPanel`로 감싸져 있음. 허브(`/admin`)에 끼우면 패널 안에 패널. `hub-notice-0` 검사(허브에 158 연습용 안내 없음)는 대상이 실도구라 유지되지만, 중첩 제목이 허브 제목 검사(`panelTitle(hubHtml) === '운영 홈'`, 첫 제목 기준)를 깨지 않는지 확인 필요.
7. **CSS 누수.** `home-admin.css`는 전역 로드(main.js:5)이고 사이트 쪽 클래스도 들어 있음(예: `.email-verify-overlay` 773-778, `.addon-*` 681-). → **기존 규칙 수정 금지, 끝에 새 규칙만 추가, 새 선택자는 `.admin-shell` 아래로 한정.**
8. **관리자 화면 「학부모」 누락 1곳.** 홍보 런치 데스크(미리보기 화면) `a28-screens.js:700`이 공용 `promo/catalog.js:22·40`의 audience 「학부모 · 원장」「학생 · 학부모(보조)」를 그대로 보여 줌. 사이트는 이 audience 값을 그리지 않음(promo/ 안 사용 0건). docs/200 §6 목록에도 빠져 있음.
