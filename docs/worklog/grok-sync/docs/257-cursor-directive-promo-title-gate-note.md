# 257 지시서 — 학생 소개 제목 교체 + 쪽지권 팝업 개발 메모 줄 삭제

- 작업 번호: 257
- 날짜: 2026-10-19
- 확정: 종현이 2026-10-19에 확정했다. 250에서 빼 뒀던 3곳을 추천안대로 모두 진행한다. (아래 2장)
- 브랜치 이름: `cursor/257-promo-title-gate-note-20261019`
- 기준 코드: `origin/main` `083afad91ac0cd8b9d87dbe527366fa85ef4742b` (2026-10-19 확인 시점, 256 병합·배포 완료 후). 작업 시작 시점의 최신 `origin/main`에서 브랜치를 만들어라. 아래 줄 번호가 밀렸으면 파일 안에서 같은 문장을 찾아 확인하고, 내용이 크게 다르면 멈추고 보고해라(7장).
- 이 글의 목적: 무엇을, 어느 파일만 건드려서, 어떻게 확인할지를 정하는 지시서다. 이 지시서에 없는 변경은 하지 마라. **코드 수정은 이 지시서를 받은 작업자만 한다. 지시서 작성 단계에서는 코드를 고치지 않았다.**

> 쉬운 말 안내: 학생 소개 페이지 제목 한 줄을 새 문장으로 바꾸고, 쪽지권 안내 팝업에 섞여 보이는 개발 메모 한 줄을 지우는 작업이다. 학부모 역할 카드는 일부러 그대로 둔다. 뜻·기능·화면 구조는 바꾸지 않는다.

## 1. 목적

1. 학생 소개 페이지(`/promo/parent`)의 안내 제목이 학생이 고르는 주체이고 학부모는 함께 확인한다는 확정 문구와 어긋난다. 제목 한 줄만 확정 문장으로 교체한다.
2. 쪽지권(쪽지 보내기 권한) 안내 팝업에 `학부모 화면 아님 · 15장 §7`이라는 개발 메모가 사용자 화면에 그대로 노출되고 있다. 이 한 줄만 삭제한다. 학부모 화면이 아닌데 '학부모'가 적힌 안내가, 주로 공부방·과외쌤에게 보이는 팝업에 뜨는 것이 문제다.
3. 학부모 역할 카드는 현재 문구가 확정 취지와 맞으므로 바꾸지 않는다. 검수에서 바이트 단위로 그대로인지 확인하는 것이 이번 작업의 일부다.

## 2. 확정 배경 (종현 확정, 2026-10-19)

- 이 3곳은 250(학생 화면 단독 '학부모' 문구 고치기)에서 고치지 않고 빼 뒀던 항목이다.
  - `parent-content.js` 69줄 제목과 76~80줄 학부모 역할 카드는 페르소나(누구를 위한 안내인지) 구분 의도가 있어, 250에서는 뜻이 바뀔 수 있어 남겼다 (250 지시서 2장 #2, 5장, 8장).
  - `overlays.js` 78줄은 사용자 문구가 아니라 개발 메모가 화면에 노출되는 형태라, 250에서는 일반 문구처럼 바꾸지 않고 별도 표시로 남겼다 (250 지시서 2장 #8).
- 종현이 2026-10-19에 이 3곳을 아래 추천안대로 모두 진행하기로 확정했다.
  1. 제목은 새 문장으로 변경한다 (3장 작업 1).
  2. 학부모 역할 카드는 그대로 둔다. 코드를 바꾸지 않는다 (3장 변경 금지 1).
  3. 팝업 메모 줄은 삭제만 한다. 코드 주석으로 옮기지 않는다 (3장 작업 2).

### 확인된 코드 근거 (기준: `origin/main` `083afad9`)

- 1·2번 항목은 학생 소개 페이지(`/promo/parent`)에서 `preview/home-ui/src/promo/screens.js` 138~151줄이 그린다. `personas.eyebrow`와 `personas.title`을 제목으로 표시하고, `personas.cards`를 역할·제목·본문 카드로 표시한다. 따라서 제목과 카드 문구의 원본은 `parent-content.js` 한 곳이다. `screens.js`는 건드리지 않는다.
- 3번 항목은 `preview/home-ui/src/messages/overlays.js`의 `showPaidGateOverlay`(52~94줄)가 항상 포함하는 한 줄이다. 이 팝업은 쪽지권이 없을 때 뜨는 안내로, 호출 위치상 주로 공부방·과외쌤이 쪽지권 안내를 볼 때 노출된다. 팝업 본문(제목·본문·남은 쪽지·답장 안내·힌트)은 `messages-copy.js`의 `buildMemoGateCopy()`가 만들며, 삭제 대상은 그 아래에 하드코딩된 메모 한 줄뿐이다.
- `.msg-gate__note` 스타일은 `preview/home-ui/src/styles/home-member-flows.css` 2347·2349줄에 있다. 메모 줄을 지워도 이 CSS가 남아 있는 것은 화면에 영향이 없다. CSS는 건드리지 않는다 (4장).

### 변경 금지 1. 학부모 역할 카드는 그대로 둔다 (`parent-content.js` 76~80줄)

- **코드를 바꾸지 마라.** 아래 현재 문구를 한 글자도 바꾸지 않는다.

  ```js
      {
        role: '학부모',
        title: '함께 보면 됩니다',
        body: '선택을 대신하기보다, 학생이 비교한 기준과 쪽지 내용을 같이 확인합니다.',
      },
  ```

- 지시서에 명시하는 이유: 이 카드는 학생이 고르고 학부모가 함께 확인한다는 역할 구분을 이미 담고 있어 확정 취지와 맞다. 작업 1의 제목 교체와 헷갈려 함께 고치는 것을 막기 위함이다.
- 검수(종현 확인) 단계에서 이 카드가 그대로인지 확인한다. 확인 방법은 6장을 따른다.

### 작업 2. 쪽지권 팝업 개발 메모 줄 삭제 (`overlays.js` 78줄)

- 파일: `preview/home-ui/src/messages/overlays.js`
- 위치: `showPaidGateOverlay` 안 78줄
- 삭제할 줄 (이 한 줄 전체를 지운다):

  ```html
          <p class="msg-gate__note">학부모 화면 아님 · 15장 §7</p>
  ```

- **그냥 삭제만 해라.** 개발 기록이 필요하다는 이유로 이 문구를 코드 주석(`<!-- -->`, `//` 등)으로 옮기지 마라. 주석으로 남기는 것도 변경이다.
- 이 줄 외에 팝업의 나머지 마크업·문구·동작은 바꾸지 마라. 특히 `copy.title`·`copy.body`·남은 쪽지 안내(`remainingLine`)·유효기간(`expiryLine`)·답장 안내(`replyNote`)·힌트(`hint`)·요금제 버튼·닫기 버튼은 그대로 둔다.

## 5. 작업 순서

1. 작업 시작 시점의 최신 `origin/main`을 받고, 거기서 브랜치 `cursor/257-promo-title-gate-note-20261019`를 만든다. 기준 코드와 줄·문장이 다르면 파일 안에서 같은 문장을 찾고, 내용이 크게 다르면 멈추고 보고해라.
2. 작업 1: `parent-content.js` 69줄 제목을 3장 작업 1의 문장으로 교체한다.
3. 작업 2: `overlays.js` 78줄 메모 한 줄을 삭제한다. 주석으로 옮기지 마라.
4. 변경 금지 1: `parent-content.js` 76~80줄 카드가 바뀌지 않았는지 `git diff`로 확인한다. diff에 이 카드가 나타나면 되돌려라.
5. 커밋은 **가능하면 작업별로 나눠라.** 한 브랜치 `cursor/257-promo-title-gate-note-20261019` 안에서 아래처럼 2개로 나누는 것을 기본으로 한다. 나누기 어렵면 한 커밋으로 합치되, 그 이유를 보고에 적어라.
   - 예: `257 fix(copy): 학생 소개 제목을 학생이 고르고 학부모가 함께 확인하는 문장으로 바꾼다`
   - 예: `257 fix(messages): 쪽지권 팝업에서 학부모 화면 아님 메모 줄을 지운다`
   - `git add`는 고친 파일만 하나씩 이름으로 지정해서 담아라. **`git add -A` 금지.**
6. 브랜치를 push하고 **멈춘다.** main에 합치지 않는다.
7. 이후 순서는 고정이다: **브랜치 push 후 멈춤 → 검수 → 종현 승인 → main 병합.** 승인 전에 main에 병합하거나 배포하지 마라.

## 6. 확인 방법

아래를 모두 확인하고 보고해라. 하나라도 빠지면 완료가 아니다.

### 작업 1 확인 — 소개 페이지 제목

1. 학생 소개 페이지(`/promo/parent`)를 열고, 안내 섹션 제목이 `학생이 중심에서 고르고, 학부모는 함께 확인합니다`로 보이는지 확인한다.
2. `git diff`로 `parent-content.js`에서 바뀐 줄이 69줄 제목 한 줄뿐인지 확인한다. 다른 섹션·문구가 함께 바뀌었으면 완료가 아니다.

### 변경 금지 1 확인 — 역할 카드 무변경 (바이트 단위)

3. `git diff`에 `parent-content.js` 76~80줄 학부모 역할 카드가 **나타나지 않는지** 확인한다.
4. 카드 문구가 바이트 단위로 같은지 원문과 대조한다: `role: '학부모'`, `title: '함께 보면 됩니다'`, `body: '선택을 대신하기보다, 학생이 비교한 기준과 쪽지 내용을 같이 확인합니다.'` — 공백·쉼표·마침표까지 같아야 한다. 검수에서도 같은 방식으로 확인하므로, 보고에 대조 결과를 적어라.

### 작업 2 확인 — 팝업 메모 줄 삭제, 나머지 안내 그대로

5. 쪽지권 안내 팝업(`showPaidGateOverlay`)을 띄워 `학부모 화면 아님 · 15장 §7` 줄이 화면에서 사라졌는지 확인한다. 코드에서도 `overlays.js`에 `msg-gate__note`와 해당 문구가 남아 있지 않은지 검색으로 확인하고, 검색 명령과 결과를 보고에 적어라. (CSS 파일에 `.msg-gate__note`가 남아 있는 것은 정상이다. JS·화면 기준 0이면 된다.)
6. 팝업의 나머지 안내가 그대로인지 확인한다: 제목(`copy.title`), 본문(`copy.body`), 남은 쪽지·유효기간 안내(있을 때), 답장 안내, 힌트, 요금제 버튼(있을 때), 닫기 버튼이 전과 같고, 닫기·요금제 이동 동작이 전과 같은지 확인한다.
7. 삭제한 줄이 코드 주석으로 옮겨지지 않았는지 `git diff`로 확인한다. 주석 형태(`<!-- 학부모 화면 아님`, `// 학부모 화면 아님` 등)로 남아 있으면 완료가 아니다.

### 공통 확인

8. `git diff --stat` 기준으로 고친 파일이 4장 허용 파일 2개 안에만 있는지 확인한다. 허용 파일 밖 변경이 0이어야 한다.

- **`git add -A` 금지.** 고친 파일만 하나씩 이름으로 지정해서 담아라.

- 학부모 역할 카드(76~80줄)가 바이트 단위로 그대로다.
- 쪽지권 팝업에서 `학부모 화면 아님 · 15장 §7` 줄이 사라지고, 나머지 안내(제목·본문·버튼)와 동작은 그대로다. 삭제한 줄이 주석으로 남아 있지 않다.
- 고친 파일이 허용 파일 2개 안에만 있다.

## 10. 보고 항목 (이대로 보고해라)

작업이 끝나면 아래를 빠짐없이 보고해라.

1. 브랜치 이름과 커밋 번호 (작업별로 나눴으면 커밋 2개 모두, 합쳤으면 그 이유)
2. 바꾼 파일 목록과 파일별 바꾼 줄 수 (`git diff --stat` 기준)
3. **문장 전후 대조**: 작업 1 제목의 전후 문장, 작업 2에서 삭제한 줄 전문
4. **제목 화면 확인 결과**: `/promo/parent`에서 새 제목이 보이는지
5. **역할 카드 무변경 확인 결과**: `git diff`에 카드가 없는지, 바이트 단위 대조 결과
6. **팝업 확인 결과**: 메모 줄이 화면·코드에서 사라졌는지(검색 명령과 결과 포함), 나머지 안내(제목·본문·버튼)와 닫기·이동 동작이 그대로인지, 삭제한 줄이 주석으로 남아 있지 않은지
7. 허용 파일 밖을 고친 것이 없는지. 만약 범위 밖이 필요해서 멈췄다면, 7장 양식대로 어느 파일·줄이 왜 필요한지 적어라.
