## 1. 관리자만 보기 (미리보기) vs 공개

### 1-1. 두 스위치 (개념)

| 이름(화면) | 의미 |
|------------|------|
| **미리보기(관리자만)** | 로그인 세션이 **관리자**일 때만 홈에서 이 팝업을 본다. 일반 손님·회원은 절대 안 봄. |
| **공개 표시** | 켜져 있고 기간 안이면, 아래 **대상**에 맞는 사람에게 홈에서 보인다. |

- 구현 초기는 **미리보기만** 켜고 공개는 끔.
- 공개를 켜도 대상이 비어 있으면 **누구에게도 안 띄움**(실수 방지). 「전체」를 고른 경우만 전원.
- 동시에 화면에 뜨는 팝업은 **최대 1개**. 후보가 여러 개면 우선순위 **공지 > 이벤트 > 광고**, 같으면 관리자가 정한 정렬·최신 쪽.

### 1-2. 「나만 본다」의 뜻

- **관리자 계정으로 로그인한 사람**만 미리보기 대상이다.
- 공부방·과외쌤·학생 **역할만**으로 미리보기 권한을 주지 않는다. (역할 ≠ 관리자)
- 계정 `jetty@naver.com`(네이버 소셜 · 공부방) — **2026-09-25 사용자 확인:** 상단 **관리자콘솔** → 실제 관리자 페이지 진입 OK. 미리보기 세션으로 사용.

### 1-3. 하지 말 것

- 미리보기 = 관리자 **설정 화면**에만 창을 그린다 → **금지**. 미리보기도 **실제 홈 위 모달**로 본다.
- 시안 HTML/ZIP을 관리자에 업로드 → **금지**.
- 게시판 글 = 팝업 → **1차 아님**(후순위 선택).

## 2. 대상 (복수 선택) — 잠금

관리자가 팝업을 올릴 때 **표시 대상**을 고른다. **복수 선택 가능.**

### 2-1. 선택지 (화면 문구 고정)

| 선택지 | 누구에게 뜨나 |
|--------|----------------|
| **전체** | 비회원(손님) + 로그인 모든 역할 |
| **비회원** | 로그인 안 한 손님 홈 |
| **공부방 회원** | 공부방 역할로 로그인한 사람 |
| **과외쌤 회원** | 과외쌤 역할로 로그인한 사람 |
| **학생 회원** | 학생·학부모 역할로 로그인한 사람 |

### 2-2. 복수 선택 규칙

1. **「전체」를 고르면** 다른 칸은 자동으로 비활성·해제한다. (전체 = 전원)
2. 「전체」가 아니면 **비회원 / 공부방 / 과외쌤 / 학생** 중 **1개 이상** 체크.
3. 예: 공부방+과외쌤만 → 학생·비회원에게는 안 뜸.
4. 예: 비회원만 → 로그인 회원에게는 안 뜸.
5. 한 사람이 여러 역할이면(드묾) → **현재 보고 있는 홈의 역할** 기준으로 맞으면 표시. (홈이 공부방 홈이면 공부방 대상만 해당)

### 2-3. 어디에 뜨나 (표면)

1차 기본:

| 표면 | 포함 |
|------|------|
| 손님 홈 | 대상에 **비회원** 또는 **전체**일 때 |
| 공부방 로그인 홈 | 대상에 **공부방** 또는 **전체** |
| 과외쌤 로그인 홈 | 대상에 **과외쌤** 또는 **전체** |
| 학생·학부모 로그인 홈 | 대상에 **학생** 또는 **전체** |

찾기·마이페이지·가입 화면에는 **1차 안 띄움**.

### 2-4. 「오늘 하루 보지 않기」

- 키는 **팝업 id + 대상 조합이 아니라 팝업 id만** (같은 창을 역할마다 다시 강요하지 않음).
- 자정(Asia/Seoul) 만료.
- 미리보기(관리자만) 모드에서는 「오늘 하루 보지 않기」를 **무시하거나**, 관리자용으로만 저장(구현 시 한쪽으로 통일 · 권장: **미리보기에서는 무시**해 매번 확인 가능).

### 3-2. set-a × set-b = **6종 전부 구현** (2026-09-25 잠금)

| 패밀리 | 차이 |
|--------|------|
| **set-a** | 로고 lockup만. 워터마크 없음. |
| **set-b** | lockup + 옅은 워드마크 워터마크. |

- 시안 6장(공지·이벤트·광고 × set-a·set-b)을 **모두** 홈 모달 템플릿으로 구현한다.
- 관리자(또는 더미 단계)에서 **패밀리(set-a/set-b) + 유형(공지/이벤트/광고)** 를 골라 쓴다. 「하나만 남기고 폐기」하지 않는다.
- Phase 0의 set-a/b 단일 확정 체크는 **폐기**(전부 구현으로 대체).

### 3-3. 공통 셸 (세 유형 모두)

1. **오버레이**: 반투명 어두운 막 (`rgba(28,25,23,0.40)` 근사). 홈 전체를 덮음.
2. **카드**: 모서리 약 12px · 그림자 `0 12px 36px` 약한 톤.
3. **닫기(X)**: 카드 우상단 · **밝은 흰 원형** 버튼 · 글자 × · **어두운(다크) 원 금지**.
4. **ESC**로 닫기 · 포커스 트랩(열리면 카드 안 포커스).
5. **「오늘 하루 보지 않기」**: 카드 하단 · 체크 + 문구. A는 footer 라벨, B·C도 동일 의미 위치.
6. 모바일: `max-width: min(100vw − 32px, 카드가로)` · `max-height: 80vh` · 내용 넘치면 **카드 안 스크롤**.
7. C 광고만: 화면 너비 ≤768px이면 **세로 스택**(왼쪽 민트가 위, 오른쪽 본문이 아래).

## 6. 관리자 계정 확인 (`jetty@naver.com`) — 2026-09-25 저장소 조회

- 사용자 진술: 네이버 소셜 · **공부방** 계정 · `jetty@naver.com`.
- 저장소에 **최고관리자 시드 이메일**로 들어 있음 (`AdminRoleService` bootstrap · `admin-permissions.js` · SQL 032/036 시드·백필 · dual-capability 문서). **「이메일만 있으면 무조건 관리자」는 아님.**
- 관리자 여부의 정본은 DB **`users.admin_level`** (`super_admin` / `sub_master`). 비어 있으면 콘솔 권한 없음.
- 시장 역할(공부방/과외/학생)과 관리자 등급은 **겹칠 수 있음**(공부방 primary 유지 + `admin_level`). 네이버 로그인도 같은 세션 규칙을 탐 — 소셜이 관리자를 **새로 만들어 주지는 않음**.
- 이메일 fallback으로 `jetty@naver.com` → `super_admin`이 되는 경우는 **이미 primary가 admin 역할인데 DB 등급이 비어 있을 때**뿐. 공부방 primary만 있고 `admin_level`이 NULL이면 **관리자 아님**.
- 팝업 미리보기 = **관리자 세션** (`isAdminUser` / `admin_level` 또는 admin 역할). 공부방 역할만으로는 불가.
- 기존 관리자 팝업 메뉴는 `settings`라 **최고관리자만** 메뉴 진입. 미리보기 게이트도 동일 계열 헬퍼 재사용.
- 운영 확인(추천): 해당 계정 로그인 후 `GET /api/auth/me.php` → `role_type`이 공부방(`study_room_owner`)이고 `admin_level`이 `super_admin`이면 OK. 또는 관리자 메뉴/`#/admin` 진입·`/api/admin/session.php` 200.
- DB 확인 SQL 요지: `users.email = jetty@naver.com`의 `admin_level`, primary `user_roles.role_type`, (있으면) secondary `admin`. 네이버 연결은 `user_oauth_accounts.provider = naver`.
- 기존 팝업 저장(`sessionStorage`)에는 **역할 대상 필드 없음** → 111 §2 대상(복수)은 신규 잠금.
