## 0. 한 줄 정의

| 방향 | 주체 | 성격 |
|------|------|------|
| **탈퇴** | 회원 자의 | 시장·내 정보는 걷되, **타인과 얽힌 히스토리는 남을 수 있음** |
| **삭제** | 관리자 임의 | 결제회원은 **프로필 soft→1년→하드** + **결제 원장 유지**; 무결제면 즉시 하드 |

지금은 관리자 UI의 「탈퇴」가 회원 soft 탈퇴와 같은 경로다. 앞으로는 **삭제**를 별도 관리자 액션으로 두고, 탈퇴와 섞지 않는다. 결제회원 삭제는 프로필 soft 1년 보관이 있다.

## 1. 탈퇴 (회원)

### 1-1. UX 원칙 · 회원 확인 카피 (**확정** · 2026-09-25)

탈퇴 진행 시 **확인 수순**이 필요하다.

**노출 원칙**
- **회원 화면**에는 보관연한·원장·법령 문구를 **쓰지 않는다.** (5년·1년·soft/하드 등은 **내부 문서·관리자 UI**만)
- 회원에게는 필요한 결과만 짧게 알리고, **편안한 인사**로 마무리한다.

**내부용 요지** (구현·검수용, 화면에 그대로 쓰지 않음)
- 내 계정으로 더 이상 로그인할 수 없다.
- 내가 올린 등록·나만의 정보는 사이트(찾기·홈·마이페이지)에서 빠진다.
- 쪽지처럼 상대가 있는 기록은 상대방 히스토리를 위해 남을 수 있다. 탈퇴 후 쪽지 표시명은 **성+○○** (예: 최○○).

**회원 확인 화면 카피 (확정)**

| 위치 | 문구 |
|------|------|
| 제목 | 정말 탈퇴하시겠어요? |
| 본문 | 탈퇴하면 이 계정으로는 다시 로그인할 수 없어요.<br>올려 두신 등록과 나만의 정보는 사이트에서 바로 사라져요.<br>쪽지처럼 상대가 있는 기록은 상대방에게 남을 수 있고, 그때 내 이름은 성만 보이게(예: 최○○) 바뀌어요. |
| 인사 | 그동안 우동공과를 이용해 주셔서 감사해요.<br>언제든 다시 찾아와 주세요. |
| 버튼 | 탈퇴하기 / 취소 |

**완료 화면 (확정)**

| 위치 | 문구 |
|------|------|
| 본문 | 탈퇴가 완료되었어요. |
| 인사 | 그동안 함께해 주셔서 감사해요.<br>좋은 인연으로 다시 만나길 바랄게요. |
| 버튼 | 홈으로 |

약관·개인정보 처리방침 등 **법적 고지 문서**의 보유기간은 별도 문서에서 다루고, **탈퇴 확인/완료 팝업·화면에는 넣지 않는다.**

### 1-2. 제거·숨김 대상 (**확정** · 2026-09-25 사용자 선택)

| 항목 | 처리 | 비고 |
|------|------|------|
| 로그인·계정 | soft 탈퇴 · 로그인 불가 | 재가입 위해 로그인 슬롯 해제(tombstone) 패턴 유지 |
| 이름·전화·이메일 등 개인정보 | **익명화** | 탈퇴 행에 실명 PII 잔존 금지 |
| 공부방·과외쌤·학생 **등록물** | 시장·찾기에서 **숨김** | 노션 미완 구간을 탈퇴 시 자동 숨김으로 닫음 |
| 역할(공부방/과외쌤/학생) | 비활성 | 로그인만 막고 역할이 active로 남는 상태 금지 (등록물 숨김과 함께) |
| 찜·최근열람·개인 설정 | **제거** | 나와만 관련된 데이터 |
| 구매내역 | **화면에서 즉시 제거** | 서버 결제·정산 원장은 **탈퇴일+5년** 후 하드 제거 (2026-09-25 잠금) |

선택지에서 **「내가 쓴 후기까지 삭제」는 고르지 않음** → 후기는 아래 보존.

### 1-3. 제외·보존 (**확정 / 잠금**)

| 항목 | 처리 | 이유 |
|------|------|------|
| **쪽지·대화** | **삭제 대상에서 제외** | 타인과 얽힌 히스토리. 상대방 쪽 기록 유지 |
| 쪽지 **표시명** | **성+○○** (예: 최○○) | 2026-09-25 확정. 「익명」= 성 한 글자 + ○○ 마스킹. 「탈퇴한 회원」 고정문구 아님 |
| **후기** (내가 쓴 것 포함) | **보존** | 사용자 선택에서 삭제 미포함. 상대·카드 히스토리 |
| 결제·구매·정산 **서버 기록** | **5년 보관 후 하드 제거** | 전자상거래법 시행령상 대금결제 기록 5년 관행에 맞춤. soft 탈퇴는 즉시 |

### 1-3-1. 쪽지 표시명 규칙 (확정)

- 형태: **성(첫 글자) + ○○** — 예: 최○○, 김○○
- 성이 없으면(또는 식별 불가): `○○○` 또는 동등한 마스킹 (구현 시 한 가지로 통일)
- 「탈퇴한 회원」「익명」 같은 **고정 문구는 쓰지 않는다**
- 상대 쪽지 목록·대화방 헤더·말풍선 발신 표시에 동일 적용

### 1-4. 잔여

- 회원 확인 카피 확정됨 (§1-1). Cursor 구현 티켓만 남음.

### 1-5. 하드 제거 일정 (**확정** · 2026-09-25)

| 시점 | 처리 |
|------|------|
| **탈퇴 즉시** | soft 탈퇴·로그인 불가, 등록물 숨김, 개인정보 익명화, 찜·최근열람·설정 제거, 구매 **화면** 제거, 쪽지 표시명 성+○○ |
| **탈퇴일로부터 5년 후** | 결제·계약·정산 **원장 하드 제거** |
| 참고 | 분쟁 기록 3년 분리는 이번 잠금에 넣지 않음. 결제 원장 5년에 묶음 |
| 관리자 삭제 · **결제 이력 있음** | 프로필 **soft 제거** → **1년 보관** → 하드 제거. 결제 원장은 **5년** (§2) |
| 관리자 삭제 · **결제 이력 없음** | 즉시 전부 하드 제거 |

## 2. 삭제 (관리자)

### 2-1. 잠금 (2026-09-25 사용자 · 관리자삭제 재잠금)

관리자 **삭제**는 결제 이력 유무로 나눈다. (**회원 탈퇴와 별개**)

#### A. 결제 이력이 **있는** 회원 (관리자 삭제)

| 대상 | 처리 |
|------|------|
| **프로필** (계정 식별·등록물·시장 노출에 쓰인 정보) | **소프트 제거** (로그인 불가·찾기/홈 미노출) → **1년 보관** → **하드 제거** |
| **결제·정산 원장** | **남김**. 화면 노출 없음. **결제일/작성일 기준 5년** 후 하드 제거 |
| 찜·최근열람·개인 설정 | 즉시 제거 |
| 쪽지·후기 등 | 관리자 삭제에서는 **즉시 하드 제거** (탈퇴 때처럼 남기지 않음) |

시장·게스트에게는 삭제 직후부터 안 보인다. 1년은 **운영·분쟁 대비 내부 보관**이다.

#### B. 결제 이력이 **없는** 회원 (테스트·더미 등)

- **즉시 전부 하드 제거** (남길 원장 없음).

### 2-2. 운영 주의 · 「회원 삭제」 확인 2단계 (**확정** · 2026-09-25)

- 무결제 즉시 하드는 **되돌리기 어렵다**. 결제회원은 1년 보관 구간이 있으나, **관리자** UI에 대상 요약·결제 유무·보관 기간 안내가 필요하다. (회원 화면에는 보관연한 금지)
- 회원 soft 탈퇴 버튼과 **라벨·권한·로그를 분리**한다. (삭제 ≠ 탈퇴)
- **「회원 삭제」는 확인을 두 번** 거친다. (사용자 잠금 2026-09-25)

| 단계 | 내용 |
|------|------|
| 1 · 요약 | 이메일 · 등록물 수 · 결제 유무 · 홈·찾기 미노출 안내 → **다음** |
| 2 · 재확인 | 대상 **이메일 재입력** 후에만 최종 **회원 삭제** 가능 |

- **탈퇴 처리**는 확인 1회로 둔다. 2단계 재확인은 삭제에만.

### 2-3. 구현 메모 (코딩 전)

- 하드 DELETE vs 전항목 soft 소거+검색 제외는 구현 때 정하되, **사용자·검색 결과에서는 흔적이 없어야** 한다.
- FK로 막히면 “등록물만 먼저 숨김/삭제 후 계정” 순서를 운영 절차로 둔다.

## 3. 지금 관리자 화면과의 갭

| 현재 | 목표 |
|------|------|
| 관리자 「탈퇴」≈ 회원 soft 탈퇴 (등록물 잔존 가능) | **탈퇴**: soft + 등록물 숨김 + PII 익명화 + 찜 등 제거 + 구매 화면 제거 + 쪽지·후기 보존 |
| 하드/일체 삭제 없음 | **삭제**: 결제회원=프로필 soft 1년→하드 + 원장 5년 / 무결제=즉시 하드 |

테스트 카드만 치울 때는 **삭제**를 쓰고, soft 탈퇴만으로 허수를 지우지 않는다. (152 P0와 동일)

## 정정 2026-09-30 (종현)
- 공부방·과외쌤(·학생)은 본인 카드 숨김·삭제 기능이 없다. 회원에게 「삭제」는 곧 탈퇴(소프트 제거)이고, 하드 삭제는 관리자 회원 삭제에서만 한다.
- 위 1-2의 「등록물 숨김」은 탈퇴 시 시스템이 자동 처리하는 것이지 회원이 고르는 기능이 아니다. 코드의 본인 hidden·delete 경로는 구알고리즘 잔재 → 최종검수에서 제거(final-review-carryover 참조).
- 관리자의 「홈·찾기에서 숨김/다시 보이기」는 156 §2-2 노출 보정 전용이며 본인 숨김과 무관하다.
