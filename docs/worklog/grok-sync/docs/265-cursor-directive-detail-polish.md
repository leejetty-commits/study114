4. `main`에서 직접 작업하지 마라. **push까지만 한다. `main` 병합·배포·force-push 금지.**
5. 운영 DB를 직접 고치지 마라. 마이그레이션·SQL 적용은 이 작업에 포함되지 않는다.


## 11. 완료 보고 양식

완료 보고에는 아래를 빠짐없이 적어라.

1. 브랜치 이름과 커밋 1·2·3의 해시. 시작 시점의 `origin/main` 해시와 기준 커밋 포함 확인 방법(1장 명령 결과).
2. 바꾼 파일 목록과 파일별 실제 diff 줄수 (허용 12개 안인지, 커밋별로 나눠서 명시). `handoff-bridge.css`를 빼거나 계정 버튼을 포함/제외했으면 그 판단 근거.
3. 항목별 전→후 대조: 사진 안내문, 버튼 제외 두 항목, 버튼 전용 규칙 수치, 찾기 12px 두 자리, 설명글 폭, 문구 축소 전 자리(5-2·5-3 표 순서대로. 바꾸지 않은 항목은 이유).
4. 10-1 검색 결과, 10-2 실측표 (a)~(i), 10-3 캡처 (j)~(k), 10-4 (l)~(m) 확인 결과.
5. 범위 확인 문장: "허용 파일 12개(실제 바꾼 파일 명시) 밖은 건드리지 않았습니다. 홍보 페이지 전부, 결제·제출 버튼 수치, 홈 히어로 12px, JS 로직, PHP, 사진 규격 수치는 바꾸지 않았습니다."라는 취지를 자기 말로 확인해 적어라.
6. 범위 밖으로 본 관찰이 있으면 「범위 밖 관찰」로 분리해 적되, 이번에 고쳤다고 쓰지 마라.
7. 멈춘 지점 보고: push까지 했는지, 병합·배포는 하지 않았다는 것을 적어라.
