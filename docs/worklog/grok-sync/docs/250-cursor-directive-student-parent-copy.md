## 1. 목적

- 학생(parent)·전체 공개 화면에 단독으로 적힌 '학부모' 문구(약 17줄)가 핵심 잔존이다. 학생 본인이 보는 화면인데 '학부모'만 적혀 있으면 보는 사람이 헷갈린다.
- 단독 '학부모'를 문맥에 맞게 '학생·학부모' 또는 해당 역할 화면에 맞는 표현으로 문장별로 자연스럽게 고친다.
- 공급자(과외쌤·공부방) 화면에서 상대방을 가리키는 '학부모' 문구는 정상 표기이므로 이번 범위에서 제외한다.

## 5. 작업 방법 (이 순서로)

1. 작업 시작 시점의 최신 `origin/main`을 받고, 거기서 브랜치 `cursor/250-student-parent-copy-20261018`을 만든다.
2. 2번 표의 파일·줄을 열어 문장을 직접 읽고, 학생·전체 공개 화면 문구인지, 공급자 상대방 지칭이 아닌지 문장마다 확인한다.
3. **문장별로 자연스럽게 고친다. 일괄 치환(찾기·바꾸기 한 번에 전부 교체)은 금지한다.**
   - 기본 방향: 단독 '학부모' → '학생·학부모'. 예: '학부모는 함께 보면 됩니다' → '학생·학부모가 함께 보면 됩니다'처럼 주어·조사·어미가 자연스럽게 이어지게 문장 전체를 다듬는다.
   - 역할 화면에 맞는 이동·귀속 문구는 그 역할로 고친다. 예: '학부모 홈으로 돌아가기' → '학생 홈으로 돌아가기'. 화면의 실제 이동 대상(학생 홈)이 맞는지를 확인한 뒤 고쳐라.
   - `parent-content.js` 69, 77줄(학생 중심·학부모 보조, 카드 role '학부모'): 페르소나 구분 의도일 수 있다. '학생·학부모'로 자연스럽게 재작성하되, 원래 뜻(누가 중심이고 누가 보조인지, 카드가 누구를 나타내는지)이 바뀌면 고치지 말고 중단·보고 항목에 전후 문장과 이유를 적어라.
   - `guide/copy.js`와 `guide/screens.js`에 중복되는 문구는 두 곳을 같은 표현으로 맞춘다. 한 곳만 고쳐서 문구가 어긋나게 하지 마라.
   - `messages/overlays.js` 78줄: 별도 표시. 개발 메모 노출이면 일반 문구처럼 바꾸지 말고 보고에 따로 적어라.
4. 문구만 바꾼다. 문구가 아닌 코드(변수명·키·조건·이동 대상 주소·함수 이름)는 바꾸지 마라. 표시 문구와 코드 식별자가 함께 있는 줄이면 표시 문구 부분만 고쳐라.
5. 고친 파일만 하나씩 이름으로 지정해서 add하고, 커밋 메시지 앞머리를 `250`으로 시작해서 커밋한다.
   - 예: `250 fix(copy): 학생 화면 단독 학부모 문구를 학생·학부모로 고친다`
6. 브랜치를 push하고 **멈춘다**. main에 합치지 않는다.

## 6. 금지 사항

- **공급자 상대방 지칭 문구 변경 금지**: 과외쌤·공부방 화면에서 상대방을 가리키는 '학부모'(약 19줄)는 고치지 마라.
- **문서·주석·관리자 화면 변경 금지**: 문서 파일, 코드 주석, 미사용 코드, 관리자 화면은 고치지 마라.
- **일괄 치환 금지**: '학부모' → '학생·학부모'를 파일 전체·저장소 전체에 한 번에 적용하지 마라. 문장마다 읽고 자연스럽게 고쳐라. 기계적으로 바꾸면 조사·어미가 깨지거나 뜻이 바뀐다.
- **뜻 변경 금지**: 요금·자격·대상·행동 주체 등 문장의 뜻이 바뀌는 수정은 하지 마라. 뜻이 바뀔 것 같으면 고치지 말고 보고해라.
- **기능·구조 변경 금지**: 화면 구성, 이동 대상, 버튼 동작, 데이터·API는 손대지 마라. 이번 작업은 표시 문구만이다.
- **main 병합 금지**: main에 합치지 마라. 브랜치에 커밋하고 push한 뒤 멈춘다.
- **force-push(강제 밀어넣기) 금지**
- **`git add -A` 금지**: 고친 파일만 하나씩 이름으로 지정해서 담아라.

## 7. 확인 방법

아래를 모두 확인하고 보고해라.

### 필수 확인 (하나라도 빠지면 완료가 아니다)

1. **학생 화면 단독 표기 0**: 허용 파일 기준으로, 학생(parent)·전체 공개 화면 문구에서 단독 '학부모' 잔존이 0인지 검색으로 확인한다. 검색 명령과 결과를 보고에 적어라.
   - 단, 5번에서 '뜻이 바뀌어 고치지 않음'으로 보고한 항목(69·77줄, overlays 78줄 등)이 남아 있으면, 그 항목을 잔존 목록에 따로 적고 이유를 밝힌다. 확인 없이 "0"이라고만 쓰지 마라.
2. **다른 역할 화면 무변경**: 과외쌤·공부방 화면과 공급자 상대방 지칭 문구가 바뀌지 않았는지 `git diff`로 확인한다. 허용 파일 밖 변경이 0이어야 한다.
3. **문장 자연스러움**: 고친 문장을 전부 전후 대조로 보고에 적고, 조사·어미가 깨진 문장이 없는지 직접 읽고 확인한다.
4. **중복 문구 일치**: `guide/copy.js`와 `guide/screens.js`의 중복 문구가 같은 표현으로 맞춰졌는지 확인한다.
5. **기능 무변경**: 고친 화면들(홈 배너·가이드·고객지원·내상점 복귀·학생 홍보 문구)이 전과 같이 열리고, 버튼·이동이 전과 같은지 확인한다.

### 회귀 확인

6. **고친 파일 확인**: `git diff --stat` 기준으로 고친 파일이 4번 허용 파일 안에만 있는지 확인한다.
