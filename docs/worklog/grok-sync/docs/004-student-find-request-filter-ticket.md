# 004 · 학생찾기 — 한 줄 요청문 필터·노출 티켓 (원본 잠금)

- 작성일: 2026-09-23 (KST)
- 목적: Cursor 작업 지시의 **범위·완료·금지**를 로컬 SSOT로 고정. 검토·보완지시문은 이 문서를 기준으로 한다.
- 상태: **원본 잠금** (구현 결과는 별도 문서/보완지시문으로 기록)

---

## 1. 작업 목적

학생찾기 화면에서 **한 줄 요청문 있음** 필터와 **한 줄 요청문 / 특이요청사항** 노출 경로를 닫는다.

핵심은 단순 UI 추가가 아니다.  
**학생찾기 진입 → 필터 상태 반영 → 목록 API 응답 → 리스트/베이직카드 노출**까지 실제 연결이 닫혀야 한다.

## 2. 포함 범위 (학생찾기 한정)

| 항목 | 잠금 |
|------|------|
| 기본필터 | **한 줄 요청문 있음** 추가. **상세필터 금지** (베이직카드에서 바로 읽히는 값) |
| 리스트/베이직카드 | **한 줄 요청문**, **특이요청사항** 반영 상태 확인 및 최소 보완 |
| 읽기 경로 전체 | 라우팅 · 필터 프론트 상태 · 목록 API · 리스트/베이직카드 매핑 |
| API | 필터/노출에 필요한 값이 없으면 **학생찾기 최소 응답 보강만** 허용. 학생 등록 구조 전면 수정으로 확장 금지 |

## 3. 제외 범위 (건드리면 티켓 위반)

- 학생 마이페이지
- 학생 기본정보 수정 화면
- 학생 상세정보 저장 구조 재설계
- 학생 등록 플로우 전반 리팩터링
- 학생찾기 외 다른 탐색/검색 화면
- 정렬 로직 개편 / 추천 로직 변경
- 정책 문구 전면 수정 / 무관한 CSS 정리
- DB 스키마 변경을 전제로 한 확장

이번 티켓 = **학생찾기 읽기/노출 보완**. 학생 도메인 전체 수정 티켓이 아님.

## 4. 구현 원칙

1. 가장 작은 범위로 닫는다. 필요한 곳만 수정.
2. 이미 저장되는 값을 학생찾기에서 읽을 수 있으면 **그 경로만** 닫는다.
3. UI만 맞추고 끝내지 않는다. 필터만 생기고 결과 불변 = 미완료. 카드 문구만 있고 API 값 없음 = 미완료.
4. 기본필터 우선. 상세필터로 밀어 넣지 않는다.
5. 노출은 학생찾기 리스트/카드 범위만. 상세페이지 수준 정보 재구성으로 확장하지 않는다.

## 5. 필수 확인 (수정 전후)

### 5-1. 라우팅 (반드시 문서에 이름을 찍어 잠근다)

- 학생찾기 진입 경로
- 필터 상태가 **라우트 파라미터 / 쿼리스트링 / 내부 상태** 중 무엇인지
- **한 줄 요청문 있음** 추가 시 기존 필터 구조와 충돌 여부

### 5-2. API

목록 API가 실제로 내리는지:

- 한 줄 요청문
- 특이요청사항
- 또는 한 줄 요청문 있음을 판단할 수 있는 원본 값

없으면 프론트만 고치지 말고, 학생찾기 최소 응답만 보강.

### 5-3. 리스트/베이직카드

- API → 카드 매핑 위치
- 노출 위치 / 빈값 처리 / 긴 텍스트 자르기 (기존 패턴 최소 수정)

### 5-4. 필터 동작

- 선택 시 목록 결과 변화
- 해제 시 원상복귀
- 다른 기본필터와 병용 시 깨지지 않음

## 6. 완료 기준 (전부 닫혀야 완료)

1. 기본필터에 **한 줄 요청문 있음** 추가됨
2. 해당 필터 선택 시 **목록 결과가 실제로 달라짐**
3. 학생찾기 API(또는 그 앞단)에서 한 줄 요청문 · 특이요청사항을 읽을 수 있음
4. 리스트/베이직카드에 정해진 방식으로 노출
5. 라우팅 / 상태 / API / 카드 연결이 모두 확인됨
6. 학생 마이페이지·등록 저장 구조까지 작업이 **번지지 않음**

## 7. 금지

- 학생 도메인 전체 구조 손보기
- 학생찾기 핑계로 마이페이지까지 같이 수정
- “나중에 필요할 것 같아서” 범용 리팩터링
- 필터 UI만 추가하고 API 미연결로 종료

## 8. 한 줄 해석

학생찾기에서 **한 줄 요청문 있음**을 기본필터로 추가하고, 한 줄 요청문 / 특이요청사항이 **라우팅·상태·API·리스트·베이직카드**까지 연결되는지만 **최소 범위**로 닫는 티켓.
