# 256-1 보완 지시서 — 커뮤니티·고객센터 세션 전 게이트 + 자기 분기 학생 찾기 저장 지역 재확인

- 작업 번호: 256-1 (256 보완, 한 묶음)
- 날짜: 2026-10-19
- 브랜치: `cursor/256-menu-flicker-20261018` (이미 push된 브랜치. 새로 만들지 마라)
- 이 지시서의 목적: 256 검수에서 조건부 합격으로 남은 두 건만 보완한다. 이 두 건 외의 변경은 하지 마라. **앱 코드 수정은 이 지시서를 받은 작업자만 한다. 이 지시서 작성 단계에서는 코드를 고치지 않았다.**
- 모델 지정 없음: 이 지시서는 종현이 Cursor에 직접 전달한다.

> 쉬운 말 안내: "세션 확정"은 내가 누구로 로그인했는지 서버 확인(`me.php`)이 끝난 상태를 말한다. "게이트"는 확인이 끝나기 전에 화면을 그리지 않고 막는 장치다. 이번 보완은 ①확인 전에 커뮤니티·고객센터 게스트 화면이 먼저 그려지는 길을 막고, ②느린 네트워크에서 학생 찾기 첫 화면에 저장 지역명이 끝까지 제대로 뜨는지 확인하는 것이다.

## 2. 보완 범위 — 이 두 건만

### 보완 1) 커뮤니티·고객센터 세션 전 게이트 수정 (필수 수정)

- **문제:** `preview/home-ui/src/main.js`에서 세션이 확정되기 전에 해시(`location.hash`)가 커뮤니티·고객센터로 바뀌면, 게스트(비회원) 화면이 먼저 그려진다. 로그인한 사용자에게 게스트 화면이 잠깐 보이는 깜빡임이 남는다.
- **고칠 곳:** `preview/home-ui/src/main.js` 한 파일.
- **검수에서 제시된 최소 수정안 (이 안에서 골라라):**
  - (가) `renderScreen()`의 커뮤니티 분기(기준 `:221-227`)·고객센터 분기(기준 `:207-213`) 앞에, 마이페이지 분기(기준 `:251-254`)에 이미 있는 것과 같은 `sessionChecked` 검사를 넣는다. 세션 확정 전이면 그리지 않고 돌아간다.
  - (나) 또는 `render()` 초입에서, 커뮤니티·고객센터 두 라우트인데 아직 세션 확정 전이면 그리지 않고 돌아간다.
  - 어느 쪽이든 **최소안 하나**만 택하고, 택한 방식과 이유를 보고에 적어라. 줄 번호는 브랜치 기준이므로 밀렸으면 파일 안에서 같은 분기를 찾아 확인하고, 내용이 크게 다르면 고치지 말고 멈춰서 보고해라 (6장 중단 보고).
- **기대 동작:** 세션 확정 전에는 커뮤니티·고객센터 게스트 화면을 그리지 않는다. 세션이 확정되면 기존 `render()`(기준 `:532`)가 실제 역할 화면을 그린다. 이 기존 재렌더 경로를 새로 만들거나 바꾸지 마라.
- **확인 필수:** 느린 네트워크에서 "홈 진입 직후, 세션 확정 전에 커뮤니티·고객센터 클릭"으로 재현(수정 전)과 수정 확인(수정 후)을 반드시 한다. 절차는 7장을 따라라. 빠른 네트워크에서만 확인하고 끝내지 마라.

### 보완 2) 자기 분기 학생 찾기 첫 화면 — 저장 지역명이 끝까지 뜨는지 확인 (재현될 때만 수정)

- **확인할 현상:** 느린 네트워크에서, 학생이 **자기 분기** 학생 찾기 첫 화면을 열었을 때, 저장해 둔 지역명이 끝까지 제대로 뜨는가. 안내 문구(예: 지역을 등록하라는 취지의 표시)가 남은 채로 끝나면 재현된 것이다.
- **왜 의심하는가 (코드 근거, 이미 확인됨):**
  - `preview/home-ui/src/auth-session.js:282`에서 `hydrateSessionDependencies`를 `void`로 부른다. 즉 세션 확정 뒤의 부가 로딩 완료를 기다리지 않고, 완료 후 다시 그리는 보장도 없다.
  - 학생 저장 지역은 `registrations-backend.js` 캐시가 차야 읽힌다.
  - 그런데 찾기 첫 화면은 세션 직후 바로 그려진다 (`preview/search-ui/src/main.js:86-87`). 그래서 부가 로딩이 늦으면, 첫 화면이 저장 지역을 못 읽은 상태로 그려진 뒤 다시 그려지지 않아 안내 문구가 남을 수 있다.
- **진행 순서 (반드시 이 순서):**
  1. 먼저 7장 절차대로 **재현 확인만** 한다. 코드를 먼저 고치지 마라.
  2. **재현되면:** `preview/home-ui/src/auth-session.js`의 `hydrateSessionDependencies` 완료 후 재렌더를 보장해라. 방식은 완료 이벤트를 알리고, `preview/home-ui/src/main.js`와 `preview/search-ui/src/main.js`가 그 완료를 받아 **한 번 다시 그리기**로 한다. 무한 재렌더나 반복 타이머(폴링)로 만들지 마라.
  3. **재현되지 않으면: 고치지 마라.** 측정 조건(네트워크 제한 방식·수치, 계정 분기, 저장 지역 상태)과 결과만 기록해서 보고해라. "예방 차원"으로 재렌더 코드를 넣지 마라.
- 보완 2의 수정 파일은 재현될 때만 허용된다: `preview/home-ui/src/auth-session.js`, `preview/home-ui/src/main.js`, `preview/search-ui/src/main.js`. 재현되지 않았는데 이 파일들을 보완 2 명목으로 고치면 범위 위반이다 (단, 보완 1로 `preview/home-ui/src/main.js`를 고치는 것은 별개다).

## 7. 확인 방법 (느린 네트워크 재현 절차 포함)

공통 준비:

- 개발자도구 네트워크 제한을 건다. 예: 브라우저 개발자도구 Network에서 "Slow 3G" 프리셋, 또는 Custom으로 지연(latency)을 크게 준 프로필. 보고에 **어떤 제한을 썼는지 수치까지** 적어라.
- 세션 확인(`me.php` 응답)이 늦어지는 조건이어야 한다. 제한을 걸어도 세션 확정이 즉시 끝나면 재현 조건이 아니므로, 네트워크 패널에서 `me.php` 응답이 늦게 오는 것을 눈으로 확인한 뒤 진행해라.
- 로그인 계정은 실제 역할 계정을 쓴다. 보완 1은 로그인한 역할(학생·공부방·과외쌤 중 최소 1개 이상, 가능하면 전 역할), 보완 2는 **저장 지역이 있는 자기 분기 학생** 계정으로 한다.

### 보완 1 확인

1. (수정 전 재현) 느린 네트워크에서 로그인 상태로 홈에 진입한 직후, 세션이 확정되기 전에 상단 메뉴의 **커뮤니티**를 누른다. 게스트(비회원) 헤더·본문이 잠깐이라도 보이는지 확인하고 기록한다.
2. 같은 방법으로 **고객센터**도 확인한다.
3. (수정 후) 같은 절차를 반복한다. 커뮤니티·고객센터 모두 세션 확정 전에 게스트 화면이 그려지지 않고, 세션 확정 후 실제 역할 화면이 바로 보이는지 확인한다.
4. 세션 확정 후 화면이 기존 `render()`로 그려져 최종 화면(헤더 메뉴 구성·본문)이 수정 전과 같은지 확인한다 (회귀 확인).
5. 진짜 비회원(로그아웃) 상태로 커뮤니티·고객센터를 열었을 때 화면이 수정 전과 같은지 확인한다.

### 보완 2 확인

6. 저장 지역이 있는 자기 분기 학생으로 로그인하고, 느린 네트워크에서 학생 찾기 첫 화면을 연다.
7. 첫 화면에 저장 지역명이 뜨는지, 안내 문구가 남은 채로 끝나지 않는지 **끝까지 기다려** 확인한다. 화면을 새로고침하거나 메뉴를 다시 눌러야만 지역명이 뜨는 경우는 "첫 화면에서 안 뜸 = 재현"으로 기록해라.
8. 재현 여부와 무관하게 측정 조건을 기록한다: 네트워크 제한 방식·수치, 계정 분기(공부방/과외 중 어느 쪽인지), 저장 지역이 실제로 저장되어 있었는지, 몇 번 반복했는지, 각 반복의 결과.
9. 재현되어 고쳤을 때만, 수정 후 같은 절차로 저장 지역명이 첫 화면에 끝까지 뜨는지를 다시 확인한다. 재현되지 않았으면 이 항목은 "수정 없음 + 측정 기록"으로 보고한다.

### 공통 확인

10. `git diff origin/main --stat`와 커밋별 파일 목록에 허용 파일만 있는지 확인한다. 금지 영역·253 파일이 diff에 있으면 그 자체를 보고에 적고 멈춰라.
11. 241 유지 확인: 세션 확인 전에 찾기 메뉴가 숨겨진 채로 남는지 본다.
12. 249 유지 확인: `#/messages` 동작이 수정 전과 같은지 본다.
13. 합격 부분 회귀 확인: 문구 3곳, 반대 분기 빈 현재위치, 찾기 전체 세션 게이트가 수정 전과 같은지 본다.
14. `#/guest` 첫 진입에서 게스트 선행 표시가 보이면 고치지 말고 보고에만 적는다 (5장 범위 밖).
