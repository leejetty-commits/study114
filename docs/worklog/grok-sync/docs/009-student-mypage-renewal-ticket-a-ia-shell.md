## 0. 한 줄 목적

학생(`navRole` = `parent` / `role_type` = `guardian_student`) 마이페이지의 **1차 메뉴·내 등록 상단 탭·기본 진입·구 경로 리다이렉트**만 노션 구조로 잠근다.  
검수·공개 게이트 UI를 **내비에서 치우고**, 폼·카드 디테일·저장 API 재설계는 **하지 않는다** (B~D).

## 1. 범위

### 포함

- `preview/home-ui/src/mypage/router.js` — 학생용 좌측 1차 메뉴·기본 진입
- `preview/home-ui/src/mypage/shell.js` / `screens.js` / `index.js` / `mypage-copy.js` — 메뉴 렌더·학생 첫 화면이 구 홈 대시보드로 안 가게
- `preview/home-ui/src/student-reg/router.js` (+ 라우팅에 직접 묶인 최소 화면 분기만) — 내 등록 탭·구 section 리다이렉트
- 학생 기본 진입이 `student-reg` 허브/목록/공개탭으로 새지 않게 하는 **리다이렉트·라벨**
- 라우팅·관련 **읽기 API가 깨지지 않는지 점검** (저장/스키마 변경 없음이 원칙)

### 제외 (한 줄이라도 건드리면 거부)

- 마이프로필 **실측 Basic 카드 UI·리스트 정보구역 본구현** (→ B)
- 기본정보/상세정보 **필드·저장·검증 로직 재설계** (→ C/D)
- 자녀/guardian 카피·스토어 전면 삭제 (→ E; A에서는 메뉴·진입만 안 보이게)
- 공부방·과외쌤 마이페이지, 유료/Pick·Prime, 학생찾기, 가입 온보딩 전면
- DB 스키마 변경, 무관 CSS 전역 정리, push / `build:dothome`

## 3. IA 잠금 (학생만)

### 3-1. 1차 메뉴 (순서 고정)

1. **내 등록**
2. **찜·비교**
3. **최근열람**
4. **쪽지**
5. **계정설정**

| 메뉴 | 경로 잠금 (권장) | 비고 |
|------|------------------|------|
| 내 등록 | 학생 단일 프로필의 **마이프로필** 경로 (아래 3-2) | 목록(`/…/students` 리스트)으로 열지 말 것 |
| 찜·비교 | 기존 찜 경로 재사용 가능 (`/mypage/wishlist` 등). 라벨만 **찜·비교** | 목록 UX 개편은 비범위 |
| 최근열람 | `/mypage/recent` | |
| 쪽지 | `/mypage/messages` (후기함 병합 라벨이 학생에 남아 있으면 **쪽지**로) | 쪽지 기능 개편 비범위 |
| 계정설정 | `/mypage/account` | |

학생 좌측에서 **제거·숨김** (진입 시 리다이렉트):

- `/mypage/home` 학생용 대시보드 (부족/공개 점검형 홈)
- 구매이력 `/mypage/plans*`
- 찜한학생 `/mypage/student-review`
- 제출서류·인증 등 공급자/기타 메뉴
- **내 문의 내역** — 이번 학생 1차 메뉴 5항에 없음. 메뉴에서 빼고, 직접 URL은 기존 동작 유지 또는 계정/고객센터로만 안내(새 페이지 만들지 말 것)

### 3-2. 내 등록 상단 탭

탭 (라벨 고정):

1. **마이프로필** (기본 진입)
2. **기본정보**
3. **상세정보**
4. **쪽지설정**

라우트 잠금 (기존 `student-reg` 트리 재사용 권장, **새 대메뉴 금지**):

| 탭 | section / path | 구 path 처리 |
|----|----------------|--------------|
| 마이프로필 | `…/students/{id}` 또는 `…/{id}/myprofile` 중 **하나로 통일**. 기본 진입 | 구 hub와 동일 자리면 hub를 마이프로필로 **개명·역할 변경** |
| 기본정보 | `…/{id}/basic` | 유지. **폼 내용 변경 금지** |
| 상세정보 | `…/{id}/detail` | 유지. **폼 내용 변경 금지** |
| 쪽지설정 | `…/{id}/settings`를 **쪽지설정 의미로 전환**하거나 `…/{id}/message-settings` 신설 후 settings→리다이렉트 | 구 「공개설정」 카피·공개 게이트 UI는 탭에서 제거. 쪽지 수신 on/off만 남기는 수준이면 A에서 **셸만**; 저장 로직 대수술이면 멈추고 보고 |
| (폐기) 미리보기·공개 | `…/{id}/publish` | **마이프로필로 301성 리다이렉트**. 탭에 두지 말 것 |

**1학생 1계정:**

- `/mypage/registrations/students` 목록(P19-01)·tab/draft|published|hidden 은 학생 로그인 시 **단일 학생 마이프로필로 리다이렉트**
- 학생 추가·자녀 목록 CTA를 1차·내 등록 진입에 두지 말 것
- student id 해석: 기존 스토어/API의 **현재 계정 학생 1명**. 없거나 여러 명이면 **중단 후 보고** (임의로 첫 id 골라 조용히 진행하며 데이터 지우지 말 것)

### 3-3. 기본 진입

- `getDefaultMypagePath('parent')` (및 마이페이지 루트 `#/mypage`) → **내 등록 · 마이프로필**
- 공부방·과외쌤 `getDefaultMypagePath` **변경 금지**

## 4. 구현 원칙

1. 과외쌤·공부방 **내 등록 탭 라우팅 패턴을 준용**. 학생만 새 내비 체계 창작 금지.
2. A에서 마이프로필 본문은 **플레이스홀더 허용**: 「B에서 Basic 카드·리스트 연결」 한 줄 + 기존 허브에서 **공개 체크리스트·부족 n개·공개하기 CTA**만 제거/숨김.
3. 기본정보·상세정보 화면은 **탭으로 들어가기만** 되면 성공. 필드·카피 리뉴얼은 C/D.
4. 디자인: 새 컴포넌트 만들지 말고 기존 mypage shell. 토큰 전면 패스는 F.
5. API: **읽기 경로가 404/500 나지 않게**. 새 쓰기 API·스키마 변경 없이 갈 것. 쓰기가 필수로 보이면 중단·보고.

## 5. 완료 전 필수 점검 (라우팅 + API)

보고에 **경로와 결과**를 적을 것. 빼먹으면 미완료.

### 5-1. 라우팅 (학생 세션)

1. 마이페이지 진입 → URL이 **마이프로필**이다.
2. 좌측 5메뉴만 보이고, 라벨이 잠금과 같다.
3. 내 등록 탭 4개 전환 시 URL·화면이 맞다. 새로고침 후에도 같은 탭.
4. `#/mypage/home`, `…/publish`, 학생 목록 URL → **마이프로필(또는 잠근 대체)** 로 리다이렉트.
5. 찜·비교 / 최근열람 / 쪽지 / 계정설정 클릭이 학생 문맥을 깨지 않는다.
6. 공부방·과외쌤으로 전환 시 기존 메뉴·진입이 **회귀하지 않는다** (스모크).

### 5-2. API

1. 마이프로필·기본정보·상세정보·쪽지설정 진입 시 기존 학생 프로필 **조회** 호출이 성공하거나, 의도적 empty 처리가 명확하다. (Network 근거)
2. A 범위에서 **새 저장 API를 만들지 않았다.** 실수로 저장을 건드렸으면 diff에 명시하고, 회귀 테스트.
3. 세션 없는/타역할 접근 시 기존과 동일한 가드(로그인 유도 등). 권한 구멍이 보이면 **중단·보고**.

### 5-3. 예상외 오류 시 (절대)

- 가정과 다른 데이터(학생 0명·N명), 라우트 충돌, API 500, 공급자 화면 깨짐, 티켓 밖 파일을 고쳐야만 진행 가능 → **즉시 중지**
- 임시 if·플래그·다른 모듈 덧대기 **금지**
- 보고: 재현 경로, 콘솔/네트워크, 시도한 최소 조치, **승인 대기**
- 승인 없이 다음 파일로 진행하지 말 것
