## 0. 한 줄 목적

공부방(및 동일 패턴이면 과외쌤) **상세정보1·2**에서  
(1) 비어 있어도 **저장이 서버 오류 없이** 되고,  
(2) 카피가 **「지금 다 안 채워도 됩니다. 다만 저장(다음)은 눌러 주세요」** 축으로 1·2가 맞게 한다.

---

## 1. 현상 (잠금)

- 상세1: 「필수정보는 입력해 꼭 해주세요」+ 다수 `*` · **비움 저장 안내 없음** · 저장/다음 버튼 있음  
- 상세2: 「비어 있어도 저장할 수 있습니다」있음 · 「저장 꼭」은 약함 · 일부 필드에 `*`와 배너 긴장  
- 저장 실패 예: `curriculum cannot be null` on `study_room_details` — UI/정책상 선택인데 **DB NOT NULL**  
- 031 개설→홍보1 자동채움은 **이 티켓에서 하지 말 것**

**첨부:** 사용자가 상세1·2·에러 스크린샷을 Cursor에 **직접** 첨부.

---

## 2. 포함

1. 빈 상세 저장 시 500/`cannot be null` 없게. 기존 컬럼에 **빈 문자열·스킵·nullable 처리** 중 기존 아키텍처에 맞는 **최소안**. 새 테이블·공개 게이트 재도입 금지. 스키마 ALTER가 필요하면 **중단·보고**(승인 전 임의 마이그레이션 금지 원칙이면 보고만).
2. 상세1·2 카피 통일 예(문장 고정 가능):  
   - 「지금 모두 입력하지 않아도 됩니다. 아래 **저장**(또는 다음)은 눌러 주세요.」  
   - 상세2 기존 배너와 충돌하면 한 톤으로 맞출 것.  
3. `*` / 「꼭 해주세요」: **Prime 자격 항목**에만 남기거나, 저장을 막지 않는 안내로 완화. 빈 저장을 프론트 `required`로 막지 말 것(정책상 선택 진행).
4. 대상 후보(조사 후 allowlist 확정):  
   - `preview/study-room-ui` 상세 화면·저장  
   - 관련 API/PHP insert (`study_room_details` curriculum 등)  
   - 과외쌤 상세가 동일 카피/NULL 문제면 **같은 최소 패턴만** (축·필드 세트 다르게 유지)

3. 카피: 1·2 모두 「비어도 됨 + 저장은 누름」 축.

5. 파일 allowlist + push 안 함.
