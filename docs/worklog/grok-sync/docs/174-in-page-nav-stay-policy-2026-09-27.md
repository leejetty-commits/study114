# 174 · 페이지 잔류 내비 (배지·블록 클릭)

- 작성: 2026-09-27 KST · 우동공과2
- 상태: **기획 잠금 · 점검·수정 대기** (PC/실사이트·Cursor는 요청 시)
- 원칙: **같은 페이지에 머무름이 기본**. 이탈은 “이 흐름에서 다음 화면이 자연스러울 때만”.

---

## 1. 사용자 잠금

- 본인이 **이미 있는 페이지**에서 배지·블록·칩·카드 일부를 눌렀을 때, 보통은 **그 페이지(또는 그 위의 팝업/패널) 안**에 있어야 한다.
- 다른 라우트로 보내면 **다시 돌아오는 비용**이 생겨 짜증 난다.
- **앞뒤 문맥·플로우를 면밀히 본 뒤에만** “잔류 / 이동 / 팝업”을 판정·수정한다. 기계적으로 전부 잔류·전부 이동 금지.

---

## 2. 판정 기준 (이상적 플로우)

| 판정 | 언제 |
|------|------|
| **잔류** (기본) | 필터·정렬·탭·접기/펼치기·같은 목록 내 상세 미리보기·설정 토글·배지로 상태만 바꾸는 경우 |
| **같은 화면 팝업/드로어** | 카드 요약·베이직카드·짧은 안내·확인 — 목록/홈 맥락 유지 |
| **이동 OK** | CTA가 명확히 “○○ 찾기/가입/작성으로 가기”, 또는 완료 후 다음 단계가 다른 모드 홈인 경우 |
| **이동 금지·수정 대상** | 로그인 상태인데 `#/guest`로 보냄, 소개·배너의 「홈으로」가 게스트 홈, 역할과 무관한 `#/plans`, 배지 클릭이 뜻밖의 앱/해시로 튕김 |

관련 기확인(163~167): 고객센터 「메인 홈으로」·검색 배너 「홈으로」가 로그인 중 `#/guest` — **잔류/역할홈**으로 고칠 후보(문맥 재확인 후 수정).

---

## 3. 점검 방법 (면밀 검토)

모드별(게스트·공부방·과외쌤·학생)로:

1. **시작 화면** URL·역할 기록  
2. 보이는 **배지·블록·칩·사이드 링크·「홈으로」**를 하나씩 클릭  
3. 기록: 출발 → 도착 → 브라우저 뒤로가기 시 복귀 여부 → **자연스러운가?**  
4. 판정: 잔류 / 팝업 / 이동OK / **이탈 버그**  
5. 이탈 버그만 티켓화 — 이상 플로우 한 줄 + 고칠 도착지(역할 홈·팝업·제자리)

제외: 이미 잠근 강제 없는 동네 인사(172), 사용자가 명시한 배포 전 코딩.

---

## 4. 수정 시 카피·도착지

- 「홈으로」→ 로그인 시 **그 역할 홈** (`#/study-room` · `#/tutor` · `#/parent`), 게스트만 `#/guest`  
- 목록 위 카드 → **팝업** 우선, 전체 상세는 「자세히」  
- 새 탭·외부는 사용자 의도 CTA만
