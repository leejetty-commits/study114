## 2. 253과의 겹침 방지 (먼저 읽어라)

- 253의 대상: 학생 가입 기본정보(`renderStudentBasic`, `data-form="basic-student"`), '다음' 버튼 비활성, 제출 시 칸별 인라인 안내·첫 칸 focus. 중심 파일은 `preview/auth-ui/src/screens/signup-basic.js`이다.
- 254의 금지:
  - `signup-basic.js`는 어떤 항목에서도 고치지 마라. S-R5에서 이 파일의 `alert`가 보여도 253 소관이므로 손대지 말고, 보고에 "253 겹침으로 제외"라고 적어라.

  - 253이 아직 merged되지 않았다면, 기본정보 단계는 254 범위 밖으로 그대로 둬라.
  - 같은 뜻의 인라인 안내 문구·방식을 기본정보 밖 단계에 새로 만들 때, 253과 문구 뜻이 어긋나지 않게만 하고, 253 파일을 참고로 읽는 것 이상은 하지 마라.

## 5. 작업 방법 (항목별로 이 순서로)

공통 시작:

1. 작업 시작 시점의 최신 `origin/main`을 받고, 거기서 브랜치 `cursor/254-student-remaining-bundle-20261018`을 만든다.
2. 항목마다 시작 전에 대상 코드를 직접 읽고 3번과 같은지 확인한다. 줄 번호가 밀린 것은 괜찮으나, 함수·상수 자체를 못 찾거나 내용이 크게 다르면 그 항목은 9번으로 중단 보고해라.

### S-R1 — CSS 간격 토큰 치환 (값이 같은 것만)

1. 두 대상 파일에서 간격 속성만 목록화한다: `margin`, `margin-*`, `padding`, `padding-*`, `gap`, `row-gap`, `column-gap`. 그 밖의 속성(너비·높이·글자 크기·테두리·위치 좌표 등)은 이번 항목 대상이 아니다.
2. 각 값을 3번 토큰 표와 대조한다. **계산값이 완전히 같은 경우에만** `var(--space-N)`으로 바꾼다. 예: `padding: 1rem` → `padding: var(--space-4)`, `gap: 8px` → `gap: var(--space-2)`.
3. 하지 마라:
   - 대응 토큰이 없는 값(예: 15px, 10px, 0.875rem, 백분율, `auto`)은 **그대로 두고** 보고 목록에 "대응 토큰 없음으로 유지"로 적어라. 가장 가까운 토큰으로 값을 바꾸는 것은 금지다.
   - 줄임(shorthand) 값은 구성 요소가 **전부** 정확히 대응할 때만 바꾼다. 하나라도 대응이 없으면 그 줄 전체를 그대로 둬라.
   - 단위 없는 `0`은 `0` 그대로 둔다(토큰으로 바꾸지 마라).
   - 치환 때문에 계산값이 달라지는 경우가 하나라도 생기면, 그 줄은 바꾸지 말고 중단 보고 대상(9번)으로 적어라. "보기 좋아지니까" 같은 이유로 보이는 간격을 바꾸지 마라.
4. 바꾼 줄마다 전/후를 보고에 적을 수 있도록 목록을 남겨라(7번 확인, 10번 보고 양식).
5. 두 파일이 이미 토큰 정의를 불러오는 체계 안에 있는지(토큰이 실제로 적용되는지)를 확인해라. 토큰이 정의되지 않은 채 `var(--space-*)`만 넣으면 간격이 깨진다. 정의 체계(`tokens.css` 로딩)까지 바꿔야 하면 그 항목은 9번 중단이다.

### S-R2 — `RECENT_NOTE` 삭제

1. 시작 시점에 저장소 전체에서 `RECENT_NOTE`를 다시 검색한다(정의·호출·문자열 참조 포함).
2. 부르는 곳이 정의뿐이면, `mypage-copy.js`에서 그 정의 줄만 삭제한다. 주변 상수·export 순서는 바꾸지 마라.
3. 부르는 곳이 하나라도 있으면 삭제하지 말고 그 항목을 9번 중단 보고해라(어디서 부르는지 적을 것).

### S-R3 — 내부 번호 안전장치

1. 학생 등록 범위(`student-reg/`와 그 호출부)에서 `screenId`, `P19-` 문자열이 화면에 표시되는 경로를 전수 검색한다: 제목, 화면 문구, 버튼·링크 글자, `document.title`, 접근성 라벨 등. 라우팅·분기·타입 주석 같은 내부 사용은 표시가 아니므로 대상이 아니다.

### S-R5 — 기본정보 밖 가입 단계 alert → 화면 안 안내

2. 각 alert를 아래로 분류하고, 분류대로만 처리한다.

   | 분류 | 기준 | 처리 |
   |---|---|---|
   | A. 사용자 입력 검증 | 빈 칸·형식 오류 등 사용자가 고칠 수 있는 입력 문제 | 화면 안 인라인 안내로 전환. 이미 인라인 표시가 함께 있으면 중복 `alert`만 제거하고 인라인을 유지 |
   | B. 시스템·저장 실패 | API 실패, 역할 확인 불가, 서버 오류 등 | 이번 항목에서 바꾸지 않는다. 현행 유지로 보고에 적어라 |
   | C. 완료·진행 확인 | 완료 안내 `alert`, 진행 여부 `confirm` | 흐름을 바꾸지 않는다. 현행 유지로 보고에 적어라 (검증이 아니므로 인라인으로 옮기지 마라) |

3. A 분류만 바꾸되, 아래 조건을 모두 만족할 때만 실행한다.
   - 그 단계 화면 안에 이미 인라인 안내 자리(오류 문구 요소 등)가 있거나, 허용 파일 안에서 그 단계 전용으로 최소 추가할 수 있을 것.
   - 학생 가입 경로에서 실행되는 코드로 확인될 것. 공부방·과외쌤과 공유되어 갈라낼 수 없으면, 그 alert는 바꾸지 말고 9번 중단 보고(공유 사유)를 적어라. 다른 역할의 가입 흐름까지 덩달아 바꾸는 것은 금지다.
   - 문구는 새 말을 지어내지 말고 기존 alert 문구의 뜻을 그대로 화면 안 문구로 옮긴다.
   - 입력값을 고치면 안내가 사라지는 기존 동작이 있으면 그 동작을 유지하고, 없으면 제출 시점 표시까지만 이번 범위로 한다(실시간 버튼 비활성 같은 새 동작을 만들지 마라. 그것은 253의 기본정보 범위에서만 확정된 방식이다).
4. `signup-form.js:205`처럼 "인라인 자리가 없을 때만 alert"인 fallback은, 인라인 자리가 실제로 만들어지는지 먼저 확인해라. 항상 인라인 자리가 생기는 구조이면 fallback alert를 어떻게 할지를 보고에 근거와 함께 적고, 구조가 불확실하면 바꾸지 말고 중단 보고해라.

## 7. 확인 방법

아래를 항목별로 모두 확인하고 보고해라. 화면을 실제로 띄워서 확인하는 것을 기본으로 하고, 화면을 띄울 수 없으면 그 이유와 대신 한 확인을 그대로 적어라.

### S-R1

1. **전/후 값 동일표**: 바꾼 줄마다 `파일:줄, 속성, 전 값, 토큰, 토큰 실제값, 동일 여부`를 표로 남긴다. 동일이 아닌 줄이 있으면 그 줄은 바꾼 것이 실패다.
2. **유지 목록**: 대응 토큰이 없어 그대로 둔 간격 값을 목록으로 남긴다.
3. **화면 동일 확인**: 학생 상세·학생 마이페이지 해당 화면을 전/후로 띄워 간격이 달라 보이지 않는지 확인한다(스크린샷 등 근거를 보고에 적어라). 띄울 수 없으면 값 동일표로 대신한 사유를 적어라.
4. **토큰 적용 확인**: 두 파일을 쓰는 화면에서 `var(--space-*)`가 실제로 토큰 값으로 계산되는지 확인한다(정의가 로딩되는 체계인지).

### S-R2

5. **사용처 0건 재검색**: 삭제 뒤 저장소 전체에서 `RECENT_NOTE`가 0건인지 확인한다.
6. **화면 무영향**: 마이페이지 해당 화면이 오류 없이 그려지는지 확인한다.

### S-R3

7. **표시 경로 전수표**: 검색한 표시 경로마다 `위치, ID를 그대로 낼 수 있었는지(전), 조치, 후 상태`를 적는다.
8. **모르는 ID 시험**: 존재하지 않는 화면 ID로 제목 변환을 확인했을 때 `P19-` 형태가 아닌 일반 문구가 나오는지 확인한다(확인 방법을 보고에 적어라).
9. **정상 제목 무변경**: 아는 ID들의 기존 한국어 제목이 전과 같은지 확인한다.

### S-R4

10. **조사 근거**: 호출 사슬·역할 분기 지점·영향 파일 목록이 파일:줄 근거와 함께 보고에 있는지 확인한다. 코드 변경이 0건인지 `git diff`로 확인한다.

### S-R5

11. **alert 전수표**: 기본정보 밖 가입 단계의 alert/confirm마다 `파일:줄, 문구 요지, 분류(A/B/C), 학생 경로 여부, 조치, 후 상태`를 적는다. `signup-basic.js`는 세지 말고 "253 겹침으로 제외"로만 적어라.
12. **A 분류 전환 확인**: 바꾼 곳마다 alert가 뜨지 않고 화면 안 안내가 표시되는지, 값을 고친 뒤의 동작이 기존과 어긋나지 않는지 확인한다.
13. **정상 흐름 확인**: 전부 채운 정상 가입 흐름에서 저장·다음 단계 이동이 전과 같은지 확인한다.
14. **다른 역할 무영향**: 공부방·과외쌤 가입 흐름이 바뀌지 않았는지 `git diff`와 공유 여부 표로 확인한다.

### 공통 회귀

15. **허용 파일 확인**: `git diff --stat` 기준으로 4번 허용 파일 밖 변경이 없는지, S-R4 관련 파일 변경이 0건인지 확인한다.

5. **S-R3 전/후**: 표시 경로 전수표(위치, 전 상태, 조치, 후 상태), 모르는 ID 시험 결과, 정상 제목 무변경 확인 결과. 고칠 곳이 없어 확인만으로 끝났으면 그렇게 적어라.
6. **S-R4 조사 보고 (변경 없음 명시)**: 호출 사슬(파일:줄·줄 수), 역할 분기 지점, 학생만 바꿀 경우 닿는 다른 역할·파일 목록, 분리 후보 지점(있다면), 위험과 다음 지시서 권고
7. **S-R5 전/후**: 기본정보 밖 alert 전수표(파일:줄, 분류 A/B/C, 학생 경로 여부, 조치, 후 상태), A 분류 전환 확인 결과, 정상 흐름 확인 결과, 다른 역할 무영향 확인 결과. `signup-basic.js` 제외(253 겹침)를 명시해라.
8. **253 겹침 확인**: 253 범위와 겹쳐서 제외·미실행한 것이 있으면 그 목록. 없으면 없다고 적어라.
9. 허용 파일 밖이 필요해서 멈춘 항목이 있다면, 9번 양식대로 어느 항목의 어느 파일·위치가 왜 필요한지 적어라. 멈춘 항목과 계속 진행한 항목을 구분해라.
