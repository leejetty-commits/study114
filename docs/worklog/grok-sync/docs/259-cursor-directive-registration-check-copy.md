## 1. 목표와 배경 (종현 확정 정책)

1. **기본등록 = 기본카드(무료) 자동 노출.** 기본등록 필수 8개(표시명·과외지역 1·대상(학교급)·주력과목·월 과외비·주 회수·1회 수업시간·슬로건)를 채우면 등록·노출된다. 이 규칙은 지금 코드와 같고, 이번에 바꾸지 않는다.
   - 근거(읽기만): `preview/shared/tutor-basic-fields.js` 기본 8개 목록, `src/Tutor/TutorBasicFields.php` 서버 판정, `preview/home-ui/src/tutor-reg/registration-check-model.js`의 「상세 항목은 노출 조건이 아니다」.
2. **상세 항목은 안 채워도 등록·노출된다.** 상세는 픽·프라임 자격 쪽 추가 입력이다. 그래서 상세 항목을 기본등록과 같은 「필수 · 부족」으로 겁주듯 표시하지 않고, **등급별 추가 입력**으로 표현한다: 「픽 노출시 몇개 추가입력, 프라임 노출시 몇개 추가입력」 방향, 문형은 「픽 노출까지 N개 더 입력」「프라임 노출까지 N개 더 입력」(종현 결정 2026-10-19).
3. **「베이직카드」는 사용자 말로 풀어쓰지 않고 정식 용어 「기본카드」로 통일한다**(종현 결정). 단, 이번 범위는 **등록점검 관련 문구로 한정**한다. 홈·찾기 등 다른 화면의 「베이직카드」는 이번 범위 밖이다(건드리면 중단 보고, 3·7장).
4. **새로 막는 장치(게이트)를 만들지 않는다.** 상세 항목이 비었다고 등록 완료·저장·노출을 새로 막는 검사를 추가하지 마라. 지금 통과되는 흐름은 그대로 통과돼야 한다.
5. 함께 정리하는 표시 오류:
   - 「부족 3개인데 이름 2개만 나열」되는 잘림: 전부 보이거나 「외 N개」로 나머지를 밝혀 개수와 나열이 모순되지 않게 한다.
   - 짧은 소개·상세 소개는 둘 중 하나면 되는데 각각 「필수」로 세는 표시: 각각 세지 말고 **한 묶음**으로 안내한다.

## 3. 금지 영역

1. **허용 3개 파일 밖의 모든 파일 수정 금지.** 범위 밖이 필요하다고 판단되면 작업을 멈추고 보고하라(t1844 규칙, 7장). 자기 판단으로 파일을 추가하지 마라.
2. **서버 판정 로직 변경 금지.** `src/Tutor/TutorBasicFields.php`, `src/Tutor/TutorDetailCompletionEvaluator.php`, `src/Tutor/TutorRegisterService.php` 등 PHP 전부, 그리고 `preview/shared/tutor-basic-fields.js`(기본 8개 목록)도 건드리지 마라.
3. **노출·자격 판정 기준 변경 금지.** 기본 8개 셈법, 픽 항목(`feature_1`, `student_target`), 프라임 항목(`intro_long`, `feature_2`, `feature_3`)의 **구성·개수 기준 자체**는 바꾸지 마라. 바꾸는 것은 그 결과를 보여 주는 **문구와 이름 나열 방식뿐**이다.
4. **새 게이트 신설 금지.** 상세 미입력을 이유로 등록 완료·저장·노출을 막는 검사, 경고 확인창, 필수 플래그의 판정 전용 신규 추가를 만들지 마라.
5. **CSS·레이아웃 변경 원칙 금지.** `preview/home-ui/src/styles/registration-check.css`를 포함해 스타일 파일은 건드리지 않는 것이 원칙이다. 예외는 단 하나: 문구가 길어져 기존 칸에서 글자가 넘쳐 깨지는 것이 캡처로 확인될 때만, 해당 클래스에 한해 글자가 보이게 하는 최소 조정(예: 줄바꿈 허용)만 허용한다. 색·간격·칸 크기·구조 변경은 금지하고, 예외를 썼으면 완료 보고에 이유와 캡처 지점을 적어라. 그 이상 필요하면 멈추고 보고하라.
6. **다른 화면 문구 변경 금지.** 홈·찾기·공부방·학생 화면, 유료상품·마이페이지 허브·홍보 화면 등의 「베이직카드」·「픽 추가」 표기는 이번 범위 밖이다. 등록점검 안에서만 통일한다.
7. **사진 관련 변경 금지.** `profile-photos.js`, 프로필 사진 행·업로드·대표 사진 문구는 건드리지 마라(사진 행은 이미 필수 아님).
8. 그 밖: `git add -A` 금지(허용 파일만 이름으로 `git add` 하라), **force-push 금지**, `main` 직접 작업 금지.

| 상세 행 비고 칸 `board.required` 표시 | 상세 행에도 기본등록과 같은 `필수` 표시 (`TRC_BOARD_DETAIL1/2_FIELDS`의 `required: true` — 산정방식·대학/대학원·짧은 소개·상세 소개) | 상세 행 비고 칸에 **`필수`를 표시하지 않는다.** 기본정보 8개의 필수 판정(`TRC_BASIC_FIELD_IDS`, shared 목록)에는 손대지 마라. 상태 칸의 `미입력됨` 표시는 그대로 둔다. | 확정 (A) |
| 짧은 소개·상세 소개 셈법 | 보드에서 각각 `필수`로 따로 셈. 둘 다 비면 부족이 2개로 잡힘 | **한 묶음으로 1개로 센다.** 둘 중 하나라도 채워지면 묶음은 채워진 것으로 본다. 둘 다 비었을 때의 안내는 각각이 아니라 묶음 하나로 보여 준다. `tutorFieldOkMap`의 기존 `introOk`(둘 중 하나) 판정을 재사용하고 새 판정을 만들지 마라. | 확정 (E. 셈법) |
| 짧은 소개·상세 소개 묶음 안내 문구 | (없음. 각 행에 `필수`만 있음) | 후보: 기존 문장 재사용 — `짧은 소개 또는 상세 소개 중 하나가 필요합니다` (`TRC_PROMO_MISSING_DEFS`의 `intro` 힌트에 이미 있는 문장). 비고 칸에 이대로 넣을지, 더 짧게 줄일지는 **문안 확인 필요**. 확인 전에는 두 행에 각각 새 문구를 임의로 만들지 마라. | **문안 확인 필요** (후보만 제시, 임의 확정 금지) |
| `board.allRequiredOk` | `모든 필수 항목 입력 완료` | 기본정보 구역에서만 쓰이는 범위면 유지. 상세 구역에서 이 문구가 뜨는 경로가 있으면 그 경로는 4-3의 상세 규칙(「부족」·「필수」 미표시)에 맞춰 정리하고, 새 문구가 필요해지면 임의로 만들지 말고 중단 보고하라. | 조건부 유지 |

### 4-4. 건드리지 않는 것 (확인용)

- `next.fill` (`${label} 입력하러 가기`), `promo.gotoField` (`입력하러 가기`), 상태 `O`/`미입력됨`, 접기/펼치기 문구는 이번 대상이 아니다.
- 픽·프라임 미입력 **목록 자체**(항목 이름·힌트·이동 링크)는 전부 보여 주는 지금 방식이 맞으므로 자르지 마라.

## 5. 작업 순서

1. `git fetch` 후 최신 `origin/main`에서 브랜치 `cursor/259-registration-check-copy-20261019`를 만든다.
2. 허용 파일(2장)만 수정한다. 작업 중 범위 밖 파일이 필요하다고 판단되면 **멈추고 보고**한다(7장).
3. 문구는 4장 표대로만 바꾼다. 표에 없는 새 문장을 만들지 마라. 「문안 확인 필요」 항목이 남아 있으면 착수하지 말고 보고한다.
4. 바꾼 뒤 확인한다(6장 검수 포인트의 세 상태를 화면으로 확인).
5. 커밋한다. `git add`는 허용 파일만 이름으로 지정한다(`git add -A` 금지). 커밋 메시지는 바꾼 내용이 드러나게 쓴다.
6. **push 후 멈춘다.** `main` 병합·배포는 종현 승인 후에만 한다. force-push 금지.

## 6. 완료 보고 양식

아래를 채워서 보고하라. 하나라도 빠지면 완료로 보지 않는다.

1. **바꾼 파일과 줄 수**: 파일별 추가/삭제 줄 수 (`git diff --stat` 결과 그대로).
2. **문구 전후 대조**: 4장 표의 항목별로 실제 바꾼 전→후를 적는다. 바꾸지 않은 항목은 「유지」라고 적는다.
3. **범위 확인 문장**: "허용 파일 3개(실제 바꾼 파일 명시) 밖은 건드리지 않았습니다. 서버 판정·노출/자격 기준·새 게이트·다른 화면 문구·사진은 바꾸지 않았습니다." 라는 취지를 자기 말로 확인해 적는다. 조건부 파일(`registration-check-render.js`, CSS 예외)을 썼으면 이유를 적는다.
4. **검수 포인트 (세 상태 캡처 지점)**: 아래 세 상태에서 등록점검 화면을 캡처해 붙인다.
   - (a) **기본만 채운 상태**: 기본 8개 완료, 상세 미입력 — 「기본카드 충족」, 상세 때문에 등록·노출이 막힌다는 뜻의 문구가 없는지, 「픽/프라임 노출까지 N개 더 입력」이 읽히는지.
   - (b) **픽까지 채운 상태**: 픽 항목 완료 — 픽 배지가 충족으로 바뀌고 프라임까지 남은 수만 남는지.
   - (c) **프라임까지 채운 상태**: 전부 완료 — 세 배지가 모두 충족인지.
   - 추가로, 부족 이름이 3개 이상인 상태에서 「외 N개」가 개수와 맞는지 한 장 더 붙인다.
5. **멈춘 지점 보고**: push까지 했는지, 병합·배포는 하지 않았다는 것을 적는다.

## 7. 중단 보고 규칙 (t1844)

- 허용 파일 밖을 고쳐야 하거나, 다른 화면(홈·찾기·공부방·학생)의 「베이직카드」까지 바꿔야 말이 맞는다고 판단되면, **고치지 말고 작업을 멈추고 보고**하라. 보고에는 무엇이 왜 범위 밖인지 한 줄로 적는다.
- 4장에서 「문안 확인 필요」로 표시된 문구가 확인되지 않은 채 남아 있으면, 그 문구를 임의로 만들지 말고 보고하라.
- 기준 코드(`origin/main`)가 이 지시서의 전(before) 문구와 크게 다르면, 비슷한 문구를 찾아 억지로 맞추지 말고 멈추고 보고하라.
- 예상 diff(2장)를 크게 넘길 것 같으면 진행하지 말고 먼저 보고하라.
