### 3-1. 문제 1 — T-E2 완료 화면 강의장소 코드 (A1)

- 문제: 등록 완료 화면 요약 「강의장소」에 `student_home_visit, public_place`처럼 영문 코드가 그대로 보인다.
- 무엇을 수정: `step-complete.js`에서 코드 배열을 그냥 `join`하지 말고, 같은 앱에 이미 있는 `TUTOR_PLACE_OPTIONS`(`preview/tutor-ui/src/state.js:83-87`, 학생자택방문·공공장소·강사자택)로 한글 label을 찾아 붙인다. **목록에 없는 값은 넣지 않는다**(빼는 방식으로만 처리하고, 새 label을 목록에 추가하지 마라). 구분자 `, `는 지금 그대로 둔다.
- 빈값 판단까지 포함(3-2): 지금의 `(s.lesson_places||[]).length ? …join… : '—'` 판단은 **원본 배열 길이**가 아니라 **label로 바뀐 뒤 남는 값** 기준으로 바꿔야 한다. 전부 모르는 값이면 길이가 있어도 `—`가 되어야 한다.
- 수정 후: 아는 값만 한글로 보인다. 전부 모르는 값이면 `—`. 아는 값만 있을 때 문장은 label 치환 외에는 전과 같다.

### 3-2. 문제 2 — T-M5 과외쌤·공유 변환의 모르는 값 원값 반환 (A2, B1~B8, C1~C2, D1~D2) ★ 하이픈 통일의 부작용 방지

- 문제: 이름표에 없는 값이 오면 상세상태·경력·학적·나이대·장소·학교급 등에서 영문 코드가 그대로 화면 문자열이 된다.
- 무엇을 수정: 허용 파일 안에서 **함수 하나씩** 읽고, 원값을 돌려주는 부분만 제거한다. 목록식 값(장소)은 아는 값만 남기고(filter), 단일값은 모르면 빈값으로 돌려준다. 라벨 목록 자체(`tutor-enums.js` 등)는 한 글자도 바꾸지 마라.
- **부작용 방지 — 확정 방식 (그냥 반환값만 `—`로 바꾸지 마라):**
  1. **원칙: 내부 판단 값과 최종 표시를 나눈다.** 함수가 `—`를 돌려주면 그 값을 받는 쪽이 「채워져 있다」고 오인할 수 있다(`r.value ? …`, `textStatus(...)`, `!String(value).trim()`, `.filter(Boolean)`, 합성 문장의 조각 넣기 등). 그래서 **화면 내부 모델·현황·점검 쪽에서는 모르는 값을 빈값(`''` 또는 남는 값 없음)으로 돌려 기존 빈값·채움 판정이 그대로 동작하게 하고, 마지막 표시 단계에서만 `—`를 찍는다.** 반대로 이미 빈 입력에 `—`를 돌려주는 것이 그 함수의 기존 계약인 경우(`exposure-format.js`의 여러 함수, `detailStatusLabel`)는 모르는 값도 `—`로 돌려 빈 입력과 같게 취급한다 — 이때도 아래 2·3을 확인한다.
  2. **허용 파일 안의 판단은 함께 고치는 것이 이번 범위에 포함된다.** 아래 판단 지점은 「반환값만 바꾸면 틀어지는 곳」이므로, 같은 파일 안에서 표시와 판단을 함께 맞추는 것까지가 허용 범위다. 새로 읽어 같은 종류의 판단이 또 나오면 같은 원칙으로 같은 파일 안에서만 맞춘다.
     - `step-basic.js`: 현황 행 조립 `overviewRowHtml`의 빈값 판단(`empty = !String(row.value ?? '').trim()`, `is-empty`/`is-filled` 갈래, `valueHtml || '—'`). `optionLabel`이 `—`를 돌려주면 채워진 행으로 오인되므로, 내부 값은 빈값으로 두고 행 표시에서 `—`가 되게 한다.
     - `step-complete.js`: 위 3-1의 길이 판단(남은 label 기준).
     - `exposure-format.js`: 합성 함수 `formatTutorTrustBadges`(B8)와 `formatGenderAgeLabel`(B5). `—` 조각이 문장 중간에 끼지 않게 라벨이 있을 때만 조각을 넣고, 남는 조각이 없을 때만 전체가 `—`가 되게 한다. 같은 파일의 다른 합성이 `!== '—'`로 빈값을 거르는 기존 방식도 깨지 마라.
     - `profile-read.js`: 행 렌더의 빈값 판단(`r.value ? '' : ' is-empty'`와 `r.value ? esc(r.value) : '미입력'`). **최종 표시는 `미입력` → `—`로 바꾸되**, 빈값·채움 갈래(`is-empty` 포함)는 빈 문자열 기준으로 지금처럼 동작하게 한다. 즉 변환 함수(C1·C2)는 모르는 값에 `—`를 직접 돌려줘 truthy로 만들지 말고 빈값으로 돌려, 렌더가 `—`를 찍게 한다. 강의스타일 행의 `styles && styles !== '—' ? styles : ''`처럼 `—`를 빈값으로 보는 기존 판단도 그대로 유지·확인한다. 이 파일 안에서 끝내라.
     - `registration-check-model.js`: `row(...)`·`textStatus(...)`·행 `status`와 기본 8개 채움 셈법이 값의 빈/채움을 가른다. D1·D2의 내부 값은 모르는 값이면 빈값으로 두어 **채움·부족 셈법과 상태가 전과 달라지지 않게** 한다. 최종 화면에서 빈 행이 `—`로 보이는 것은 259 병합 후 렌더의 기존 빈값 표시를 확인해 맡긴다 — 렌더를 고쳐야만 `—`가 되면 그 파일은 허용 밖이므로 중단 보고하라(8장).
  3. **허용 파일 밖 판단이 필요하면 중단 보고.** 고친 함수의 호출측이 허용 파일 밖에 있고(예: `exposure-render.js`의 `blankDash`처럼 `—`를 빈값으로 되돌리는 기존 처리, 합성·`filter(Boolean)`류), 그 호출측을 고쳐야만 표시·판정이 맞다고 판단되면 **고치지 말고 멈추고 보고**하라. 호출측이 이미 `—`를 빈 입력과 같게 다루고 있어 손댈 필요가 없으면, 그 확인 결과를 완료 보고에 적는다(수정한 것으로 치지 마라).
- 수정 후: 아는 값의 한글·구분자·순서·개수 규칙은 전과 글자 단위로 같고, 모르는 값은 영문으로 나오지 않는다. 전부 모르는 값이면 최종 화면 표시는 `—`다. 채움·부족·노출 같은 **판정 결과는 모르는 값을 넣기 전(빈값일 때)과 같아야** 하며, 모르는 값이 있다고 채워진 것으로 세면 실패다.

### 3-3. 문제 3 — T-E5 등록 API 500 예외 원문 노출 (E1, F1 프런트 방어 확정 포함)

- 문제: `register.php` 500 응답이 예외 원문을 담고 프런트 `alert`에 그대로 뜬다.
- 서버(E1): Throwable 처리 블록에서 사용자에게 돌려주는 `message`를 확정 문구 **`요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요`** 로 바꾼다. `error_log`의 서버 기록은 그대로 둔다. 422 검증 문구와 403 이메일 인증 문구는 바꾸지 마라.
- 프런트(F1, 확정 포함): `preview/tutor-ui/src/register-api.js`의 `postJson`에서 **500대 응답(`res.status >= 500`)이면 서버가 보낸 `data.message`를 그대로 던지지 말고** 확정 문구로 `Error`를 만든다. 서버가 앞으로 또 이상한 문구를 보내도 그 문구가 알림에 그대로 뜨면 실패다. 401·422 갈래의 기존 사용자 문구 처리는 그대로 둔다.
- **숫자 표기 경계 (초안 기준, T-R2와 겹치면 제외):** 지금 마지막 fallback인 `` `서버 오류 (${res.status})` ``처럼 **상태 숫자를 붙이는 표기를 없애는 일반 정리는 T-R2(묶음 13) 소관이라 이번 범위에서 제외한다.** 그 fallback 줄 자체는 이번에 건드리지 마라. 이번 프런트 수정은 500대에 확정 문구를 쓰는 **최소 분기 추가**로 끝낸다. 만약 500대 방어를 하려면 그 fallback 줄이나 숫자 표기 전반까지 바꿔야만 한다고 판단되면, 임의로 넓히지 말고 **T-R2 겹침으로 보고 멈추고 보고**하라(8장).
- 수정 후: DB·예외 원문이 응답과 `alert` 어디에도 나오지 않고, 사용자는 확정 문구만 본다. 정상 저장·422·403 안내 동작은 전과 같다.
