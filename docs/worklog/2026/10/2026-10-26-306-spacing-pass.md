## 항별 판단

### 1. 게스트 홈 hero-map↔첫 섹션 — **유지**
- 현재: `design-system.css` → `.hero-map { margin-bottom: var(--space-6); }` = 1.5rem
- 판단: 부모 모드와 동일 토큰 사용, 인접 섹션 리듬 적절. 변경 불필요.

### 2. 학부모 홈 my-box + provider-home-head — **유지**
- 현재: `.my-box { margin-bottom: var(--space-6); }` = 1.5rem
- 판단: 1.5rem은 카드와 제목 사이 충분한 숨 쉴 간격. 타이트하지 않음.

### 3. 과외쌤/공부방 홈 provider-tabs 위 여백 — **유지**
- 현재: `provider-tabs` 전용 CSS 선택자 부재. `parent-tabs` 규칙만 존재 (`margin-bottom: var(--space-3)`).
- 판단: 과외쌤/공부방 홈은 provider-tabs가 아닌 parent-tabs 패턴을 공유. 별도 여백 과다 원인 없음. 허용 파일 밖에서 JS 구조 확인 필요 시 후속.

### 4. 검색 결과 header↔목록 — **유지**
- 현재: `.search-header .auth-subheading { margin: 0 0 var(--space-4); }` = 1rem
- 판단: 1rem은 제목+설명과 결과 목록 사이 적정 간격. 검색 결과 카드 자체 padding이 과다로 보일 수 있으나 `.search-card` 수정은 허용 파일 밖.

### 5. 마이페이지 sidebar title↔nav gap — **수정**
- 파일: `preview/home-ui/src/styles/mypage-ops.css`
- 선택자: `.mypage-nav`
- 이전: `gap: 0.12rem` (≈2px, 비토큰 값, 너무 타이트)
- 이후: `gap: var(--space-1)` (= 0.25rem = 4px)
- 이유: 0.12rem은 스케일 밖 최소값. nav 링크 사이 시각적 분리가 거의 없었음. --space-1은 토큰 최소 단계이며 compact하면서도 읽히는 간격.

### 6. 유료상품 허브 cinema↔본문 warm bleeding — **유지**
- 현재: 7열 그리드 (`plans-hub-shell`) + warm 배경의 `margin-left: min(0px, calc(40rem - 50vw))` bleed 기법
- 판단: 복잡한 레이아웃 코드. 시각 확인 없이 최소 수정해도 회귀 위험. promo §3 이례에 해당. 시각 확인 후 후속 PR.

### 7. 모바일 ≤640 guest-gate 좌우 padding — **수정**
- 파일: `preview/home-ui/src/styles/design-system.css`
- 선택자: `.guest-gate` (640px 이하)
- 이전: `padding: var(--space-6) var(--space-6) var(--space-5)` (1.5rem/1.5rem/1.25rem) — 모바일에서 page-gutter(1rem)와 이중으로 좁아짐
- 이후: `padding: var(--space-4) var(--space-4) var(--space-3)` (1rem/1rem/0.75rem)
- 이유: 390px 화면에서 page-gutter 1rem + gate padding 1.5rem = 2.5rem per side → 콘텐츠 영역 230px. 변경 후 2rem per side → 310px. 데스크톱은 기존 유지.
