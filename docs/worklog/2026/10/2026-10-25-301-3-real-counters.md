## 배경

찜(`wish_count`)·비교(`compare_count`)·쪽지(`message_count`)는 DB 테이블(`user_favorites`, `user_compare_items`, `message_threads`)이 있지만, 검색 API 응답에 집계가 빠져 카드 숫자가 상시 0이었다. 추천(`recommend_count`)·후기(`review_count`)는 이미 실집계 경로가 있어 정상.

## 추적표

| 필드 | DB 출처 | 서버 집계 (수정 전) | 검색 API 출력 (수정 전) | 토글 API 출력 (수정 전) | 수정 후 |
|---|---|---|---|---|---|
| `recommend_count` | `study_rooms`/`tutors.recommend_count` 컬럼 | COALESCE 정상 | ✅ 실수 | ✅ toggle 응답 | 변경 없음 |
| `review_count` | COUNT `provider_reviews` 서브쿼리 | 정상 | ✅ 실수 | N/A | 변경 없음 |
| `wish_count` | COUNT `user_favorites` | ❌ 집계 없음 | ❌ 항상 0 | ❌ 없음 | ✅ 배치 COUNT + 토글 응답 |
| `compare_count` | COUNT `user_compare_items` | ❌ 집계 없음 | ❌ 항상 0 | ❌ 없음 | ✅ 배치 COUNT + 토글 응답 |
| `message_count` | COUNT `message_threads` | ❌ 집계 없음 | ❌ 항상 0 | N/A(쪽지는 토글 아님) | ✅ 배치 COUNT |

## 정적 근거

### 실집계 경로
`SearchService::search()` → `batchCount($pdo, 'user_favorites', 'target_type', 'target_id', $targetType, $ids)` — `tableExists`로 테이블 존재 확인 후 한 번의 `SELECT target_id, COUNT(*) … GROUP BY target_id`로 페이지 전체 ids 처리. 테이블 없으면 빈 배열(전부 0). N+1 아님.

### 토글 후 숫자 갱신
1단계(즉시): 핸들러에서 item 객체의 count를 ±1 후 rerender → 화면 즉시 반영.
2단계(서버): `queueToggleFavorite`/`queueToggleCompare`가 API 응답의 `wish_count`/`compare_count`로 DOM `.item-actions__count` 텍스트를 서버값으로 보정.

### recommend_count 회귀 방지
기존 `recommendCountExpr()` → `COALESCE(sr.recommend_count, 0)` 경로 및 `RecommendService::toggle()` → `adjustCount()` ±1 경로는 건드리지 않았다. 새 `batchCount`는 별도 후처리 블록.

## 보완2: lookup 동일성 — findItemInPools ≡ getExposureItem

**기준 tip:** `a6da9b7a` (같은 브랜치 이어 작업)  
**작업일:** 2026-10-25

### 문제

`handoff-backend.js`의 `findItemInPools`와 `user-actions-state.js`의 `getExposureItem`이 (1) 풀 순서, (2) nameKey 필터, (3) favorite card 폴백이 달라 다른 객체를 반환할 수 있었다. 토글 ±1(UI) 대상과 서버값 갱신/롤백 대상이 어긋남.

### 수정

#### `preview/home-ui/src/exposure-lookup.js` (신규)
- `lookupExposureItem(kind, id, opts)`: 풀 순서·nameKey가 기존 `getExposureItem` 정본과 동일. `opts.favoriteCardFn`으로 폴백 주입 가능.
- `lookupAllExposureItems(kind, id)`: kind+id에 맞는 **모든 풀의 item 참조**를 반환. `Set`으로 중복 방지.
- `exposurePools(kind)`: 정본 풀 순서: EXPOSURE_* → activeResultItems(parent→sr→tutor) → searchExposureItems(parent→sr→tutor) → homeBasicPool(kind).

#### `preview/home-ui/src/user-actions-state.js`
- `getExposureItem` 본체를 `lookupExposureItem(kind, id, { favoriteCardFn: getFavoriteCard })`로 대체.
- 기존 import (`EXPOSURE_*`, `previewState`, `getHomeBasicPool`) 제거.

#### `preview/home-ui/src/handoff-backend.js`
- `findItemInPools` 함수 제거. `lookupAllExposureItems` import.
- `queueToggleFavorite`/`queueToggleCompare`: `lookupAllExposureItems(kind, id)` → 모든 복사본에 서버 `wish_count`/`compare_count` 일괄 쓰기 + 실패 시 `prevCount`로 일괄 복원.
- 캐시 롤백: `prevInList` 플래그로 반전 대신 원래 상태 복원.

### 순환 import 없음
```
exposure-lookup.js → exposure-data, state, home-basic-live (리프)
user-actions-state.js → exposure-lookup, handoff-backend
handoff-backend.js → handoff-api, home-basic-live, exposure-lookup
```

### lookup 동일성 정적 근거
`lookupExposureItem`은 `exposurePools(kind)` 배열을 순회. 이 배열의 순서·구성은 기존 `getExposureItem`의 `pools` 배열과 **동일**:
1. `kind === 'tutor' ? EXPOSURE_TUTORS : EXPOSURE_STUDY_ROOMS`
2. `previewState.parentFind?.activeResultItems`
3. `previewState.studyRoomFind?.activeResultItems`
4. `previewState.tutorFind?.activeResultItems`
5. `previewState.parentFind?.searchExposureItems`
6. `previewState.studyRoomFind?.searchExposureItems`
7. `previewState.tutorFind?.searchExposureItems`
8. `getHomeBasicPool(kind)`

nameKey 필터(`kind === 'tutor' ? 'tutor_display_name' : 'study_room_name'`)도 동일. `user-actions-state.getExposureItem`은 `lookupExposureItem` + `favoriteCardFn` 폴백으로 동작. `handoff-backend`는 `lookupAllExposureItems`로 같은 풀·같은 필터를 사용하되 모든 hit를 반환해 전체 복사본 갱신.

## 보완3: prevInList를 토글 전 값으로 (캐시 롤백 정합)

**기준 tip:** `91533ba7` (같은 브랜치 이어 작업)  
**작업일:** 2026-10-25

### 버그

`optimisticToggleWishlist`/`optimisticToggleCompare`가 `list.splice`/`list.push` **후에** `queueToggleFavorite`/`queueToggleCompare`를 호출. queue 내부에서 `prevInList = userActionsCache.*.includes(id)` → 이미 토글 **후** 상태. catch에서 캐시 복원이 no-op.

### 수정 (`handoff-backend.js`)

1. `optimisticToggleWishlist`: splice/push **전에** `wasInList = idx >= 0` 캡처 → `queueToggleFavorite(kind, id, wasInList)` 인자로 전달.
2. `optimisticToggleCompare`: 동일 패턴 → `queueToggleCompare(kind, id, wasInList)`.
3. `queueToggleFavorite(kind, id, prevInList)`:
   - 시그니처에 `prevInList` 추가. 내부에서 `userActionsCache`를 읽지 않음.
   - `.then`: `data.in_favorite` 서버 정본으로 캐시 정합 + `classList.toggle('is-active', !!data.in_favorite)` 강제 + `data.wish_count` → item+DOM.
   - `.catch`: `prevInList`로 캐시 복원 + `classList.toggle('is-active', !!prevInList)` 강제 + `prevCount` → item+DOM.
4. `queueToggleCompare(kind, id, prevInList)`: 동일 패턴. `data.in_compare` + `data.compare_count`.
5. 두 queue 함수를 `export` → private `function`으로 변경 (같은 파일 내에서만 사용).
