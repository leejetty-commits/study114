# 301-4 — FS-T2-001 home-popups 방어

**브랜치:** `cursor/301-4-home-popups-20261025`  
**기준 tip:** `47fb4517` (origin/main)  
**작업일:** 2026-10-25

## 원인

`public/api/home-popups.php`의 GET 핸들러에서 `HomePopupService::listPublic()` → `HomePopupRepository::listPublishedInWindow()` 호출 시, `home_popups` 테이블이 없으면(069 미적용) PDO 예외 발생. 기존 catch는 `http_response_code(500)` + `{ok:false, error:'server_error'}` 반환 → 홈 로드마다 Network 탭 500.

## 수정

`public/api/home-popups.php` catch 블록: `http_response_code(500)` + 별도 에러 JSON 대신 `$popups = []` 할당 → catch 밖 공통 `echo json_encode(['ok' => true, 'popups' => $popups])`. 결과: **항상 HTTP 200** + 빈 목록 or 정상 목록.

- `error_log` 유지 — 서버 로그로 예외 추적 가능
- 스택·SQL 본문 사용자 노출 없음
- admin API (`public/api/admin/home-popups.php`) 미수정 — 기존 오류 동작 유지

## FE 확인

`preview/home-ui/src/home-popup/gate.js` `loadPublicCatalog()`:
- `res.ok ? res.json() : null` → non-ok 시 null → 빈 배열
- `.catch(() => { publicCatalog = []; })` → 네트워크 오류 시 빈 배열
- **수정 불필요** — 이미 방어 완료. PHP 200 반환으로 Network 빨간색 노이즈도 제거.

## 배포 재현

```
GET https://study114.net/api/home-popups.php → HTTP 200, {"ok":true,"popups":[]}
```

현재 운영에서는 이미 200 반환 (테이블 존재 or 기존 코드). 코드 방어는 테이블 미존재 시나리오 대비.
