# 홈 첫 화면 로딩 속도 — 화면 분할

- 날짜: 2026-11-16
- 브랜치: `work/home-speed-split-2026-11-16`
- 기준: `origin/main` `cde20e8c`
- 지시: `origin/docs/home-speed-split-2026-11-16` 의 `docs/worklog/grok-sync/docs/home-speed-split-2026-11-16.md`
- 상태: PR만 연다. 머지하지 않음. 이 세션은 자기 작업을 승인하지 않는다.

## 지시서 요지

게스트 홈(`#/guest`)의 첫 글자까지 시간을 줄인다. 로그인 후 화면은 그 주소에 들어갈 때 `import()`로 받고, 옛 조각이 없으면 한 번만 새로고침한다. 세션 확인 전에 게스트 홈 셸을 먼저 그린다. 홈 상단 「관리자 콘솔」은 빼고 마이페이지 배지만 남긴다. CSS 분할·배포 방식·인증·결제·라우트 주소는 바꾸지 않는다.

## 한 일

1. `main.js`에서 유료상품·마이페이지·학생/공부방/과외쌤 홈·공개 마이샵을 주소 진입 시 받게 했다. 쪽지·등록 화면·찾기 표면·후기함·제출함·탈퇴 사유는 그 화면 모듈 안에 있어 엔트리에서 같이 빠진다. 공개 마이샵 본문(약 14 kB)은 첫 화면에 필요 없어 분리하고, 게스트가 쓰는 마이샵 복귀 위치는 엔트리에 남겼다. `plans/router.js` 리다이렉트 표는 엔트리에 둔다.
2. `Failed to fetch dynamically imported module` 과 `vite:preloadError` 는 같은 주소에서 한 번만 `location.reload()` 한다. 조각 로드가 성공하면 플래그를 지워 다음 배포도 한 번 회복할 수 있다.
3. 비로그인 판정 전에 게스트 홈 셸을 그린다. 세션 전이거나 이미 로그인된 사용자는 로그인·회원가입·찾기·등록 입구·빈 카드 클릭으로 손님 전용 이동을 하지 못한다.
4. 홈·검색·가입·등록 상단의 「관리자 콘솔」 버튼을 뺐다. 마이페이지 배지는 그대로다. 개발 툴바의 「관리자」는 Vite 개발 서버에서만 있다. `admin-backend.js` 는 관리자이고 콘솔이 열린 뒤에만 받는다. 주소 판별은 `admin/route-match.js` 로 떼어 `a28-copy.js` 가 엔트리에 붙지 않게 했다. 손님용 공개 설정은 `site-settings-public.js` 다. `admin-fetch.js` 2차 비밀번호 게이트 동작은 그대로다.

## 수락 기준

### 1. 엔트리 크기

로컬 `preview/home-ui` `vite build`. CSS는 파일 하나(668.09 kB)로 유지.

| | 원본 | gzip |
|---|---:|---:|
| 이전 (`cde20e8c`) | 1,318.80 kB | 368.83 kB |
| 이후 (`index-BaRP_xoX.js`) | 651,826 bytes (651.83 kB) | 189,788 bytes (189.79 kB) |

감소: 원본 약 50.6% (목표 40% 이상).

### 2. 첫 글자 시간

Fast 4G 네트워크 제한은 이 환경에서 브라우저 네트워크 에뮬레이션이 막혀 측정하지 못했다. CPU 4배만 켠 로컬 프리뷰 1회: 첫 페인트·첫 내용 페인트 488 ms, DOMContentLoaded 376 ms, load 662 ms. 시크릿 3회 평균은 없다. 이전 시간과의 같은 조건 비교도 없다.

### 3. 회귀

Docker API(`127.0.0.1:8080`)가 꺼져 있어 로그인·역할 홈·관리자 2차 비밀번호·실데이터 목록은 보지 못했다. 로컬 프리뷰 `http://127.0.0.1:4174` 에서 확인한 것:

- `#/guest` 히어로 「우리동네 대치동」과 목록 칸이 그려진다. 첫 스크립트는 엔트리 하나다.
- `#/plans` 는 추가 조각을 받은 뒤 「유료상품은 로그인 후 이용할 수 있습니다」를 그린다.
- `#/mypage` 는 `#/mypage/registrations/students` 로 바뀌고 로그인 안내를 그린다.
- `#/parent` 는 비로그인이라 `#/guest` 로 돌아간다.
- 상단 유틸에 「관리자 콘솔」이 없다.
- 목록·공지·동네 인사는 API 연결 실패 문구가 난다. 콘솔의 연결 거부 외 스크립트 예외는 이 경로에서 보지 못했다.

### 4. 옛 조각

`vite:preloadError` 를 한 번 내면 `sessionStorage` 키 `study114-chunk-reload` 에 현재 주소가 저장되고 새로고침을 호출한다. 같은 주소로 바로 다시 내면 플래그가 같아 두 번째는 새로고침하지 않는다. 조각 파일 이름을 실제로 바꿔 복구되는 것까지는, 프리뷰 서버의 파일을 지우는 실험을 하지 않았다.

### 6. 로컬 Docker 추가 확인

범위를 두 흐름으로 줄여 빌드 결과(`http://127.0.0.1:4180`)와 로컬 Docker API에서 다시 보았다. 페이지에 심은 오류 기록은 두 흐름 모두 0건이다.

- 공부방 계정 로그인 후 `#/study-room`이 열리고 상단에 김운영이 보인다. `#/mypage`는 공부방 목록으로 열린다. 역할 홈 화면의 소식 칸은 「소식을 불러오는 중」, 지도 칸은 「아직 등록지역이 검색되지 않습니다」로 남아 있었다. 스크립트 예외는 없었다.
- 관리자 계정은 마이페이지의 「관리자 콘솔」(`#/admin`)로 2차 비밀번호 잠금 화면에 들어가고, 잠금을 풀면 운영 홈이 열린다. 상단 유틸에는 「관리자 콘솔」이 없다. 배지가 보인 뒤 주소가 잠금 화면으로 넘어가 배지만 따로 찍힌 화면은 없다.

## 남은 위험

- 관리자 허용 주소 목록이 `a28-copy.js` 메뉴와 `admin/route-match.js` 두 곳에 있다. 메뉴에 주소를 추가하면 `route-match.js` 도 같이 고쳐야 한다.
- 역할 홈 주소로 들어간 공부방·관리자 화면에서는 손님용 「로그인/회원가입」 줄이 기록되지 않았다. 게스트 주소로 들어온 로그인 사용자의 잠깐 노출은 이번 확인에 없다.
- 엔트리가 여전히 약 652 kB다. 우측 레일·공개 설정·콘텐츠 설정이 게스트 화면에 붙어 있다.
- 배포는 기존 FTP 덮어쓰기다. assets 삭제 옵션은 넣지 않았다.
