# 365 — 088 rollback 평문 SQL

지시: PR #171(`work/365-identity-design`, tip `04cfd7ed`)의 088 rollback을 닷홈 phpMyAdmin용 평문 SQL로 고친다. `information_schema`·`PREPARE` 없이, 백업표 기준 UPDATE로 `inquiry_status` 복구 → 기본값 MODIFY 원복(`study_rooms`·`tutors`) → UNIQUE 2개 DROP → 5칸 DROP → 백업표 DROP. 로컬 Docker 새 DB에서 088 적용 후 rollback 1회. 일반 push만. 머지·force push·`reset --hard` 없음.

## 수정

- `sql/schema/088_provider_identity_verification_rollback.sql`
- 기본값 원복 문안은 088 직전 정본(067 공부방 `open`, 079 과외쌤 `open`)이다.
- 복구 UPDATE는 백업된 행 중 아직 `paused`인 것만 `inquiry_status_was`로 되돌린다.

## 검증

로컬 `study114-mysql-dev`에 새 DB `study114_088rb`를 만들고 088을 적용한 뒤 rollback을 1회 실행했다. 검증 후 그 DB는 삭제했다.

- 미인증 `open` 공부방·과외쌤은 `paused`로 바뀐 뒤 rollback에서 `open`으로 복구
- 원래 `paused`·`not_accepting`은 유지
- 088 이후 `capacity_full`로 바꾼 행은 rollback이 덮지 않음
- UNIQUE 2개·identity 5칸·백업표 2개가 없어짐
- `inquiry_status` 기본값이 공부방·과외쌤 모두 `open`과 067·079 주석으로 돌아감
