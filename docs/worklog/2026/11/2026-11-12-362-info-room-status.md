## 4. 운영 반영 경로(확인한 사실)

- 원고는 DB에 들어가지 않은 상태다(docs/content/info-room/INDEX.md:4 「DB 미반영」).
- 배포 워크플로는 docs/**와 **/*.md 변경만으로는 실행되지 않는다(.github/workflows/deploy.yml:6-14). 실행돼도 FTP로 코드만 올리고 SQL은 실행하지 않는다(deploy.yml:71·86 안내문).
- 정보게시판 글은 DB `board_posts`에 저장되고, 쓰기는 관리자 또는 유료 공급자만 할 수 있다(src/Board/InfoBoardService.php:13-22).
- 공부방 정보게시판 카테고리 허용값은 `know-how`, `recruit`, `admin-tax`, `edu-news`뿐이다(InfoBoardService.php:28). 원고의 `category_suggest: startup`은 허용값이 아니다. 그대로 넣으려면 코드에 카테고리를 추가해야 하고, 코드 변경 없이 올리려면 기존 카테고리(예: `admin-tax` 「시설·행정·세무」, preview/home-ui/src/library/library-copy.js:31)로 정해 관리자 글쓰기로 올린다.
- 따라서 「머지 = 게시」가 아니다. 머지는 원고 보관이고, 게시는 운영 DB 쓰기(관리자 화면 글쓰기)다.

## 5. 오늘 크레딧 낭비 원인과 앞으로의 방식

- 원인: 글자 수(2,300/2,700/2,000자)와 trigram 교차 유사도 같은 기계 지표를 합격 기준으로 줬다. Cursor는 지표를 맞추려고 같은 글을 반복 생성했고, 검수는 지표 우회를 잡는 검사기 보강으로 번졌다(4차~9차). 그 사이 사실 오류(게시·제시 의무 혼동, 주거지 1명 신고 규정 누락 등)는 고쳐지지 않았다.
- 앞으로:
  1. 합격 기준은 사람이 읽는 품질과 사실 정확성. 기계 검사는 CJK·우동공과 문구·frontmatter만.
  2. 전체 재생성 금지. 검수자가 「파일:줄 — 현재 문장 → 대체 문장」 목록을 주고 그대로 한 번 적용한다.
  3. 4편씩 끊어 진행하고, 바뀐 줄만 다시 읽는다.
  4. 법령·세무·보호처럼 사실이 중심인 글(07·13·20·21)은 우동공과3가 원문 확인 후 초안을 쓰고 Cursor는 붙여 넣기만 한다.
